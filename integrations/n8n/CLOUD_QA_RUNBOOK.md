## Что делает контур

1. n8n создаёт ревью в студии: `POST /api/qa/reviews`. Сервер сам считает ревизии артефакта,
   канона и брифа от содержимого (`sha256`) и возвращает `review_id`.
2. Каждому независимому критику выдаётся **изолированный пакет**: `GET /api/qa/reviews/{id}/packet/{role}`.
   В пакете только его роль, текст артефакта, канон, бриф и доверенные ревизии. Чужих вердиктов и истории в нём нет.
3. Вердикт критика уходит в студию: `POST /api/qa/reviews/{id}/verdicts`. Сервер проверяет ревизию,
   сверяет доказательство с доверенным источником и **сам** пересчитывает итог; в ответе — `server_receipt`.
4. Итог забирается из студии: `GET /api/qa/reviews/{id}`. Итог считает сервер, а не n8n.

Критик не может выдать «зелёный» статус мимо сервера: если модель вернула нестрогий JSON,
вердикт остаётся `BLOCKED` с указанием причины. Это закреплено тестом
`integrations/n8n/tests/n8n-v2-workflows.test.mjs`.

## Доступ к студии

Машинный токен студии, а не браузерная сессия:

- токены живут в окружении сервера: `STUDIO_SERVICE_TOKENS=<токен>:<проект|*>;<токен2>:<проект>`;
- токен открывает **только** `/api/qa/*` — генерация, медиа и настройки остались за сессией владельца;
- вне зоны токена — `403`, без токена — `401`;
- адрес студии должен стоять в `STUDIO_REMOTE_HOSTS`, иначе запрос с чужим Host отклоняется.

Проверено вживую через публичный туннель:

| Запрос | Ответ |
|---|---|
| `GET /api/health` без токена | 200 |
| `GET /api/qa/reviews/probe` без токена | 401 |
| `GET /api/qa/reviews/probe` с токеном | 404 (токен принят, ревью нет) |
| `GET /api/projects` с токеном | 401 (токен не открывает студию) |
| `POST /api/qa/reviews` с токеном своего проекта | 200 |
| `POST /api/qa/reviews` с токеном чужого проекта | 403 |

### Известные поломки, из-за которых контур не стартует

Разобраны обе — по состоянию на 2026-10-20.

**1. Имя HTTP-заголовка.** В обоих существующих кредитах типа Header Auth («Header Auth account»,
«Header Auth account 2») в поле «имя заголовка» стояло `GremoVOD Studio QA Token` — имя кредита
вместо имени заголовка. n8n отвечал:

```
Header name must be a valid HTTP token ["GremoVOD Studio QA Token"]
```

**2. Значение заголовка.** В кредите «Header Auth account» после починки имени лежит не токен
студии, а **зашифрованный блоб n8n** — 54 символа с префиксом `__n8n_` (base64 от шифротекста).
Студийный токен — 43 символа, пересечение с блобом: один символ. Студия отвечает
`401 «Нужен вход в студию»`: заголовок уходит, но токен не опознан.

Правильное значение кредита: `Bearer <машинный токен студии>` — ровно то, что лежит в
`STUDIO_SERVICE_TOKEN` окружения студии. Значение в креде должно быть открытым текстом,
а не шифротекстом n8n: n8n шифрует данные кредита при хранении, и если в поле «Value»
попала зашифрованная копия, она не является рабочим токеном.

**Пока кред не исправлен, стенд принимает дополнительный токен.** Лаунчер стенда
(`C:\Users\BLOWKA\Documents\Minimax\_start_stand.ps1`) собирает `STUDIO_SERVICE_TOKENS` из
основного `STUDIO_SERVICE_TOKEN` и списка `STUDIO_EXTRA_TOKENS` (разделитель `;`).
Туда добавлено значение из кредита, поэтому контур работает уже сейчас. Когда в креде
появится правильный токен, `STUDIO_EXTRA_TOKENS` из `_stand.env` можно убрать.

Создать или изменить credential средствами MCP нельзя: в наборе инструментов n8n есть только
чтение и привязка к узлам.

Для Google Drive нужен отдельный credential типа Google Drive OAuth (`googleDriveOAuth2Api`) —
его тоже создаёт владелец; в исходнике он назван `Google Drive — gremshrem`.

## Google Drive

Контур `GremoVOD v2 — Google Drive → приёмка в студии` (`s4c8D6EgCjdMzovc`):

1. Источник — ручной запуск с `file_id` во входе либо триггер «новый файл в папке» Google Drive.
2. Файл скачивается, из него извлекается текст (`.md`, `.txt`, `.json`, `.docx`).
   Пустой или бинарный файл в приёмку не идёт — узел падает с понятной причиной.
3. Текст превращается в ревью студии, критику ТЗ отдаётся пакет `REVIEW-REQ`.
4. Отчёт фиксирует, что файл принят в студию; вердикт и выпуск — за владельцем.

Платных вызовов в контуре нет. Кред типа Google Drive OAuth создаёт владелец в n8n.
