# Расходный шлюз для n8n-агентов

Обязательный порядок для любого платного шага агента в n8n:

```
Триггер → Резерв расхода → [платный узел агента] → Отчёт о расходе
```

Резерв — это жёсткая остановка. Если студия отказала (400), платный узел не должен
запускаться: деньги кончились или у роли нет потолка. Продолжать «на свой страх и
риск» нельзя — тогда расход n8n снова выйдет из-под бюджета студии.

## Что значит «нет потолка — нельзя платить»

Потолок роли задаёт владелец в студии (панель «Лимиты платных генераций»). Агент
присылает, какая роль работает, и получает разрешение. Сумму он не присылает: свой
бюджет агент придумать не может, а потолок берётся из студии.

Роль без потолка → 400 → шаг не запускается. Это осознанный отказ, а не ошибка
конфигурации: у n8n-агентов A0–A5 собственных лимитов вообще нет (`budgetGuardrails:
null` в `agent-manifest.json`), а у A6/A7/A8 есть только оценки n8n — `$0.04`, `$0.15`,
`$0.30` за сессию. По документации n8n это «консервативные предварительные лимиты, НЕ
доказанный hard billing stop на Kie». Настоящий стоп теперь на стороне студии.

Потолок n8n (`sessionCostCapUsd`) и потолок роли в студии — две разные линии, и приоритет
у студии: если потолок роли меньше, останавливает студия; если больше, останавливает n8n.

## Адреса и авторизация

| Что | Адрес | Кто зовёт |
|---|---|---|
| Резерв | `POST /api/n8n/spend/reserve` | n8n, машинный токен |
| Отчёт | `POST /api/n8n/spend/settle` | n8n, машинный токен |
| Статус | `GET /api/n8n/spend/{permit_id}` | n8n, машинный токен |
| Потолки ролей | `GET/PUT /api/n8n/allowances` | владелец, браузерная сессия |

Машинный токен — `Authorization: Bearer <token>` из `STUDIO_SERVICE_TOKENS`; в зоне
токена должен быть проект, иначе 403. Потолки ролей машинный токен не достаёт: их
задаёт владелец.

Резерв:

```json
{"project_id": "…", "request_id": "…", "role": "A1", "stage": "idea", "model": "anthropic/claude-sonnet-5-5"}
```

Ответ: `permit_id`, `reserved_usd` (потолок роли), `status: "reserved"`.

Отчёт:

```json
{"permit_id": "…", "status": "done", "usd": 0.0042}
```

`status`: `done` — подтверждённый факт (обязательна сумма), `failed` — провайдер
ничего не списал, `unknown` — агент не отчитался, резерв остаётся занятым.

## Что делать при отказе

| Код | Значит | Что делает агент |
|---|---|---|
| 400 | нет потолка роли или он не влезает в бюджет | остановить шаг, сообщить владельцу |
| 401 | нет машинного токена | остановить шаг, спросить токен |
| 403 | токен не видит проект | остановить шаг, спросить зону токена |
| 409 | этот `request_id` уже закрыт | не открывать новый резерв под тот же шаг |

## Идемпотентность

`request_id` — один шаг, одна попытка. Повтор того же `request_id` возвращает тот же
`permit_id` и **не бронирует деньги дважды**. Закрытый резерв повторно не открывается
(409): двойного списания быть не должно.

## Файл-фрагмент

`workflows/n8n-spend-gate.fragment.json` — готовые узлы для вставки в workflow:
`Резерв расхода` (`onError: stopWorkflow`) и `Отчёт о расходе`. Это справочный фрагмент,
не развёрнутый workflow: публикация n8n-агентов и workflow — отдельное решение
владельца.

Полный контракт и решения, которые остаются за владельцем, — в
[docs/N8N_SPEND_ACCOUNTING.md](../../docs/N8N_SPEND_ACCOUNTING.md).
