# Model Studio

Локальная панель для Codex: общий промпт, PNG/JPEG/WebP референсы через выбор, drag-and-drop или Ctrl+V; Seedream 5.0 Pro и Qwen Image 2.1 через KIE; подготовка задания для встроенного imagegen.

Запуск из PowerShell под тем Windows-пользователем, который сохранил ключ KIE:

```powershell
cd C:\Users\BLOWKA\Documents\ChatGPT\AMOCRM\model-studio
node server.mjs
```

Открыть http://127.0.0.1:4317 в браузере или панели Codex. Node 20+, внешних npm-зависимостей нет. Сервер доступен только через loopback. Для остановки Ctrl+C.

Ключ берётся из существующего `kie-access/request.ps1`, расшифровывается DPAPI только внутри PowerShell. Браузер ключ не получает. Для настройки ключа используется `kie-access/connect.ps1`; ключ в чат передавать не нужно.

Три независимые кнопки: imagegen → боковой чат, Запустить Seedream, Запустить Qwen. Кнопки Seedream / Qwen сразу запускают платную задачу. Каждый запуск загружает референсы в KIE. Сервер опрашивает API каждые 5 секунд даже при закрытой вкладке, получает готовые PNG/JPEG/WebP и сохраняет их в `data/<id>/`. При сетевой ошибке повторяет чтение/скачивание через 30 секунд; платный POST генерации автоматически не повторяется. После перезапуска сервер продолжает задачи с сохранённым KIE taskId. Файлы отображаются рядом, есть ссылки на скачивание. История и черновик сохраняются локально в исключённой из Git папке `data/`.

Кнопка «Запустить imagegen» при заполненном промпте и добавленной картинке создаёт задачу `native_queued`. Активный чат-исполнитель запускает `node C:/AI_Workflow_Studio/model-studio/worker-client.mjs`: клиент определяет слот по `CODEX_THREAD_ID` и таблице `workers` из `/api/config`, затем ждёт `/api/worker/wait`. Явный аргумент (`imagegen-1`, `imagegen-2`, `qwen`, `seedream`) по-прежнему поддерживается. Для другого адреса сервера задайте `STUDIO_URL`. Два слота imagegen получают новые задания сразу после сохранения референсов и `task.txt`; Qwen и Seedream получают только уведомления `mode: observe`, без повторной отправки генерации в KIE. Ожидание длится до 50 секунд и возвращает `{idle:true}`, если задач нет. Для следующего задания или после idle активный чат снова запускает клиент. Сам клиент не вызывает генерацию. Этот путь работает при активном ожидающем чате и локальном сервере; он не будит закрытый чат. Минутный heartbeat относится к прежнему способу проверки очереди.

Исполнитель забирает только новые `native_queued`, эксклюзивно создаёт `data/<id>/worker.lock`, пишет реальные этапы в `progress.json` и вызывает встроенный imagegen. Панель показывает очередь, подготовку, генерацию, результат или ошибку. Процент выполнения и промежуточные изображения встроенный инструмент не предоставляет. Готовый PNG сохраняется в `data/<id>/result.png`; сервер обнаруживает его и отображает рядом с API-результатами. Если локальный файл не возвращён, исполнитель сообщает ошибку без фиктивного результата. Автоматического повторного запуска генерации после ошибки нет. Старые `waiting_native` не запускаются; их сообщения доступны в истории. Полный отдельный чат не встроен внутрь HTML: панель прикреплена справа к самому чату-исполнителю, а текущая беседа остаётся свободной.

«Подготовить промпты» использует отдельный шаблон для каждой модели: задача, пронумерованные роли референсов, ограничения и формат результата. Это локальная структуризация без платного LLM-переписывания и без анализа содержимого фото. Роли выбирает пользователь. Промпты можно редактировать в карточках; отредактированный текст имеет приоритет. Изменение исходного задания сбрасывает подготовленные промпты. Qwen получает `enhance_prompt: false`, чтобы провайдер не добавлял собственное переписывание. Seedream получает `quality: basic/high`, Qwen — `resolution: 1K/2K`, оба — отдельное `aspect_ratio` по проверенным схемам KIE. Лимит итогового API-промпта — 5000 символов.

«Проверить KIE» читает баланс без генерации. Исправлен поиск системных модулей Windows PowerShell при запуске из Node. Ошибки прежних попыток остаются в истории, автоматического перезапуска этих генераций нет.

Проверки: `node --test` проверяет поля запросов по сохранённым OpenAPI-схемам, сохранение пользовательского промпта и порядка референсов, локальный цикл imagegen → получение файла → скачивание. Тесты не вызывают платную генерацию. Для изолированных тестов используются `STUDIO_PORT` и `STUDIO_DATA_DIR`.

Контракты и цены проверены по каталогу KIE 15.10.2026. Локальные копии `catalog.json`, `seedream-schema.json`, `qwen-schema.json` содержат использованные схемы. Настройка не выполняет платных запросов; доступ конкретной модели при генерации и качество её результата ещё не проверены.

Официальные источники: https://docs.kie.ai/ и https://kie.ai/qwen-image-2.1 .

## Тесты и переменные окружения

`node --test` запускает все тесты; платных запросов они не делают (KIE подменяется модулем `support/mock-kie.mjs`).

| Переменная | Назначение | По умолчанию |
| --- | --- | --- |
| `STUDIO_PORT` | порт сервера | 4317 |
| `STUDIO_DATA_DIR` | папка данных | `data/` |
| `STUDIO_POLL_MS` | период опроса задач | 5000 |
| `STUDIO_RETRY_MS` | пауза после сетевой ошибки опроса | 30000 |
| `STUDIO_STALE_MS` | через сколько без признаков жизни задача imagegen считается зависшей и уходит в ошибку | 600000 (10 мин) |
| `STUDIO_KIE_MOCK` | путь к модулю-подмене KIE (только для тестов) | не задан |

Черновик хранится в двух файлах: `data/draft.json` (текст и параметры) и `data/draft-images.json` (картинки). Старый формат переносится автоматически при запуске.
