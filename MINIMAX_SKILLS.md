# System Coding Skills & Rules (MiniMax + Aider)

## 1. Skill: Prefix-Cache Preserver (Экономия контекста и кэша)
- Никогда не дублируй неизмененный код целиком.
- Для поиска сигнатур классов, методов и зависимостей сначала всегда используй `Repo Map`.
- Если для выполнения задачи не хватает внутренней логики файла, которого нет в активном чате — НЕ галлюцинируй реализацию. Остановись и напиши одну строку: `ДЕЙСТВИЕ: выполни /add <путь_к_файлу> или /read-only <путь_к_файлу>`.

## 2. Skill: Pre-Flight Impact Check (Анализ перед кодом)
Перед выдачей первого блока `SEARCH/REPLACE` напиши предельно сжатый блок `[IMPACT]` (максимум 3–4 строки):
- Какие функции/методы меняются и меняются ли их сигнатуры.
- Затронет ли это вызовы в других файлах (согласно Repo Map).
- Какой командой проверить результат (линтер/тест).
Сразу после блока `[IMPACT]` переходи к патчам без вводных слов.

## 3. Skill: Atomic Diff Generator (Безошибочные патчи)
- ЗАПРЕЩЕНО использовать комментарии-заглушки (`// ... existing code`, `# ... остальной код`, `...`) внутри блоков `REPLACE`.
- Если нужно изменить большой участок (более 40–50 строк) — разбивай его на несколько мелких независимых блоков `SEARCH/REPLACE`.
- В каждом блоке `SEARCH` захватывай ровно 3–4 неизменяемые строки сверху и снизу с идеальным соблюдением оригинальных отступов (пробелов/табов).

## 4. Skill: Reviewer-Ready Diffs (Чистота под Git и внешнее ревью)
- Меняй только те строки, которые напрямую относятся к текущей задаче.
- Запрещено попутно переформатировать соседние функции, менять стиль кавычек, переименовывать несвязанные переменные или пересортировывать импорты — `git diff` должен быть минимальным и чистым для проверки внешним ревьюером.

## 5. Skill: Financial Gatekeeper (Защита денежного контура GremoVOD)
- Любой новый или изменяемый платный вызов (LLM, генерация картинок, видео, аудио) ОБЯЗАН проходить через единый расчёт бюджета и резервирование (`llm_guard.py` / `security.py`).
- ЗАПРЕЩЕНО делать прямые вызовы SDK провайдеров (OpenAI, MiniMax, Anthropic, PiAPI) из HTTP-роутов `main.py` в обход шлюза резервирования.
- При работе с расходами всегда разделяй три сущности: `estimate` (оценка), `reserved` (активный резерв) и `actual` (фактический расход без обрезания через `min()`).
- При любом сетевом таймауте после отправки запроса провайдеру переводи задачу в статус `submission_unknown` с сохранением резерва.

## 6. Skill: Idempotent Task Contract (Контракт заданий FastAPI ↔ n8n)
- FastAPI — единственный владелец состояния, канона, ревизий и бюджетов.
- Любой эндпоинт, который вызывается из n8n или UI для запуска агента, должен принимать `task_id` и `revision_id` (или ключ идемпотентности).
- Повторный вызов с тем же `task_id` не должен запускать новую генерацию — он обязан вернуть текущий статус или сохранённый результат.
- При смене входных данных или ревизии старые вердикты критиков (`PASS`/`BLOCKED`) должны автоматически инвалидироваться.

## 7. Skill: Surgical Refactoring (Безопасный разбор монолитов `main.py` и `App.tsx`)
- При добавлении новой логики не раздувай HTTP-обработчики в `backend/main.py` и главный компонент `frontend/src/App.tsx`.
- Выноси новую бизнес-логику в отдельные сервисные функции/модули с чистыми типизированными входами и выходами (Pydantic-схемы на бэкенде, отдельные типизированные props на фронтенде), сохраняя внешнее поведение API неизменным.
