# Формат сценария для будущего импорта, версия 1

Это предлагаемый контракт доски; он пока не является действующим API студии.

## Читаемый сценарий

```markdown
# Серия — Название

## Сцена 1 — Название сцены
Персонажи: Грэм, гость
Локация / бэкграунд: салон утверждённого автомобиля
Время и свет: по референсу

### Действие
Текст действия.

### Реплики
Грэм: Текст реплики.
Гость: Ответ.

### Кадры
1.1 — Общий план. Описание действия.
1.2 — Реакция гостя. Описание действия.

## Сцена 2 — Следующая сцена
...
```

## Структурированные данные

См. example.json. Все перечисленные поля обязательны; неизвестные связи — `null`, отсутствующие списки — `[]`, ещё не написанные промпты — `null`.

| Поле | Значение |
|---|---|
| schema_version | `1` |
| revision | Целая положительная версия документа; не подменяет серверную revision проекта |
| production_id / series_node_id | Реальные ID существующего проекта и серии либо null |
| title / source_text | Название и полный исходный текст, сохранённый без переписывания |
| scenes | Упорядоченный массив сцен; порядок массива — порядок доски |
| scene.key | Уникальный стабильный ключ документа, не номер; при импорте приложение может назначить UUID |
| scene.node_id | ID production_nodes вида episode либо null |
| scene.number | Номер от 1, соответствует позиции в scenes |
| scene.title / action / time_and_light | Название, действие, условия сцены |
| scene.characters | Участники: key, character_id либо null, name |
| scene.background | location_node_id либо null, name, reference_asset_ids |
| scene.dialogue | Массив speaker_key, text, delivery (in_scene / voiceover) |
| scene.shots | Упорядоченные кадры сцены |
| shot.key / node_id | Стабильный ключ; реальный ID production_nodes вида frame либо null |
| shot.number | Номер от 1 внутри сцены; подпись на доске вычисляется как scene.number + shot.number |
| shot.title / action / framing | Подпись, одно основное действие, композиция |
| shot.visible_character_keys | Ссылки на scene.characters.key только для видимых персонажей |
| shot.reference_asset_ids | Реальные ID доступных ассетов; пустой список, если референсы не выбраны |
| shot.image_prompt / video_prompt | null либо объект: text, model_id (реальный ID или null), screenplay_revision, needs_review |
| shot.animation_intent | Действие/мимика/движение камеры для видео; ещё не обязательно финальный промпт модели |
| shot.selected_image_asset_id / selected_video_asset_id | Утверждённые результаты либо null; назначения только из известных данных/явного выбора пользователя |
| unresolved | Список объектов path и reason для недостающих связей/решений |

## Проверки при реализации импорта

- Ключи сцен и кадров уникальны во всём документе; ключи участников уникальны в своей сцене. Ссылки говорящих и видимых персонажей разрешаются в той же сцене.
- Позиции/номера согласованы. Для существующих данных сохраняются key, node_id и привязки независимо от нового порядка.
- Сервер проверяет принадлежность серии проекту, сцены серии и кадра сцене. ID персонажей, локаций и ассетов проверяются на доступность; входной JSON не является доказательством прав доступа.
- Одинаковые имена и номера недостаточны для слияния. Перед изменением существующей доски показать добавления, изменения, перестановки и предложенный архив.
- Сохранение версии и связей должно быть атомарным с проверкой серверной revision. Исходник хранить отдельно от отредактированного представления.
- Превью сцены берётся из выбранного кадра; превью кадра — из выбранного фото. Не использовать «последнюю генерацию вообще» вместо явной связи.
- Дубли, расходы, голоса и состояние задач остаются в соответствующих сущностях студии. Не создавать их второй независимый учёт в screenplay.json.
- UI сцены: текст → персонажи с миниатюрами → бэкграунд → лента кадров. Карточка кадра: фото-промпт, видео-промпт, референсы, дубли и действие «Оживить». Отсутствующие данные показываются как требующие выбора.

## Контекст окна и возврат задания ChatGPT

Это требования к будущему расширению существующей очереди, не новые обязательные поля screenplay.json и не уже подключённый API.

- Адресат задания: тип `scene`, `character`, `location` или `frame`; реальный ID сущности и ID её владельца/проекта. Для персонажа использовать канонического владельца, а не случайный проект открытого кадра.
- Контекст возврата: серия, сцена и кадр, из которых открыто окно. Контекст навигации не заменяет адресата задания.
- Снимок входа: версия сущности, версия сценария при наличии, текст запроса, выбранные reference_asset_ids, модель и настройки. Идентификаторы проверяет сервер; GPT не назначает получателя результата.
- Промпт и изображение связывать с task_id и исходным адресатом на сервере. При переключении сцены или закрытии окна результат не переносится в другую карточку.
- Если карточка изменена во время работы GPT, сохранить результат вариантом исходного снимка и показать расхождение; новые ручные правки не затирать.
- Предусмотреть понятные состояния ожидания обработчика, подготовки промпта, генерации, готовности и ошибки. При неактивном GPT-чате показывать существующий способ продолжения, не обещать автоматическое пробуждение.
- Окно отображает полученный промпт и новые изображения без потери введённого текста. Повтор задания создаёт связанную попытку; назначение нового основного результата выполняется отдельно.
- Критерии приёмки: отправить из персонажа и переключиться на локацию — результат остаётся у персонажа; закрыть и открыть окно — история на месте; изменить описание во время генерации — правки сохранены; открыть персонажа из двух сцен — одна общая карточка, отдельные контексты сцен.
