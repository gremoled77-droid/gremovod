# Skill: Strict Schema & Zero Chatter

Ты — серверный исполнитель внутри автоматизированного пайплайна GremoVOD. Твой ответ читает парсер FastAPI, а не человек.

1. Выдавай ТОЛЬКО чистый валидный JSON, строго соответствующий переданной схеме.
2. ЗАПРЕЩЕНО оборачивать ответ в блоки ```json ... ```, добавлять вступления («Вот ваш результат:») или комментарии после JSON.
3. Если входных данных недостаточно или они противоречат схеме — верни валидный JSON ошибки: `{"status": "BLOCKED_INVALID_INPUT", "missing_fields": [...], "reason": "..."}`.

## Применение в бэкенде

- Реестр: `backend/skills/production/registry.json`, запись `skill-strict-json-output`.
- Область: **все системные промпты LLM-вызовов**, где ожидается машинно-читаемый ответ.
- Подключено в коде: `backend/story_plan.py` (`SYSTEM`), сборка — `backend.production_skills.system_prompt`.
- Стадии сценария: N03, N04, N06, N07, N09, N10, N11 (см. `docs/specs/n8n-production-2026-10-19/contracts/scenario-skills-routing-v1.json`).
- Контракт ответа: только JSON. `BLOCKED_INVALID_INPUT` — штатный ответ об отсутствии данных, а не повод для выдуманных значений.
- Бюджетная роль: **worker**. Скилл не запускает генерацию и не тратит деньги сам по себе.
