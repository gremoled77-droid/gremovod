# Reference-driven Shot Contract

Применять к плану с несколькими опорами, повторяющимся исполнением, раскрытием по реплике или продолжением A→B. Это практика **GREMOVOD**, предложенная на основе [разбора источника](../../../docs/research/AI_VIDEO_DIRECTING_MOHEBI_2026-10-24.md). Не считать её перечнем проверенных возможностей Seedance/Higgsfield или Blender.

Заполнять нужные пункты в заметках существующего кадра и монтажном листе. Ключи кадра, версии сущностей и действующие согласования сохраняются. Отдельная схема данных, новый сервис и новые обязательные поля не нужны.

## 1. Reference Role Map

Для каждой реально доступной опоры записать: существующий ID/путь и версию; статус утверждения; роль; что сохранять; что **не** переносить; каким поддерживаемым входом она передаётся. Отсутствующие файлы помечать как отсутствующие, а не выдавать условное имя за ID.

| Роль | Закрепляет | Не переносить автоматически |
| --- | --- | --- |
| Identity | Внешность утверждённого героя, одежду | Позу, мимику и голос фотографии |
| Geometry / object | Пропорции, двери, стойки, колёса канонического объекта | Случайные повреждения, чужой дизайн |
| Composition / camera | Крупность, точку камеры, раскрытую зрителю информацию | Внешность другого человека или геометрию чужой машины |
| Look / environment | Свет, цвет и пространство сцены | Реквизит и детали, не утверждённые в мире |
| Performance Anchor, опционально | Ритм, взгляд, жест, поведение в утверждённом образце | Голос, личность исполнителя, все события образца |
| Continuation | Выбранное конечное состояние A для начала B | Повтор действия A или весь его монтаж |

Роли могут совмещаться в одном файле, но конфликт обозначать явно. При конфликте идентичности или геометрии остановить подготовку до выбора утверждённой опоры; красивый style-reference не переопределяет канон. Фото разных сторон машины дополняют друг друга, а не задают несколько разных машин.

**Capability gate:** сверить конкретные модель, маршрут и режим: image/video/audio reference, число опор, first/last frame, длительность, формат, native audio и continuation. Различать «описано провайдером», «реализовано в маршруте», «проверено вживую». Неизвестное остаётся UNKNOWN. Документы PR #102/#103 — исследование, не разрешение включить модель.

Если video reference не поддержан или не проверен, не отправлять MP4 как выдуманный параметр. Подготовить разрешённые изображения/текст, отдельные клипы для монтажа либо остановиться до подтверждения маршрута. Наличие предыдущего клипа само по себе не подтверждает специальный режим video extension.

## 2. Performance Anchor и речь

Добавлять anchor только когда нужно повторить конкретный ритм или поведение. Указать утверждённый образец, используемый интервал, нужные свойства и допустимые изменения следующего исполнения. Без образца достаточно актёрской задачи и временных битов; не создавать обязательный дополнительный клип.

Для речи выбрать один путь: утверждённая внешняя дорожка **или** разрешённая native speech. Внешняя речь с native dialogue не должна давать два голоса. Если отключение native речи не подтверждено, пересмотреть маршрут; не полагаться только на фразу в промпте. Атмосферу и предметные звуки планировать отдельно. Без разрешённого голоса/прав на образец не клонировать голос: использовать утверждённый профиль или вариант без речи. Voice ID не придумывать.

## 3. Временные биты и точки склеек

Записать начало → изменение → читаемый результат. Для каждого бита: оценочный интервал, видимое действие, состояние камеры, что зритель уже знает и что скрыто. Не заполнять каждую секунду новым событием; длительность выбирать по действию и доступному режиму.

Для склейки по словам указать существующую утверждённую реплику/версию и cue: после каких слов или после конца фразы. До получения аудио это смысловая привязка без точного таймкода. После получения утверждённого файла измерить cue на монтажной шкале, зафиксировать исходный интервал и точку склейки с учётом частоты кадров проекта. Замена текста, темпа или дорожки требует повторной проверки cue.

Внутренние биты и команды hard cut в текстовом промпте — режиссёрское намерение. Они не гарантируют точного исполнения, multi-shot API или пригодного стыка. Если точность важна, готовить отдельные простые клипы с запасом входа/выхода и резать в CapCut.

## 4. Continuation Contract A→B

| Запись в заметках | Что зафиксировать |
| --- | --- |
| Наследуемое из A | Идентичность, геометрия, свет, одежда, реквизит, положение, взгляд, направление и фаза движения, контакт, звуковой фон |
| Точка передачи | Выбранный дубль A, реально просмотренный выходной интервал/кадр; планируемый вход B до появления результата помечен как план |
| Новое действие B | Только следующее событие, его повод и результат; без повторного разгона или повторения реплики из A |
| Разрешённые изменения | Новая крупность/точка камеры и намеренный перенос времени с понятной монтажной причиной |
| Запрещённый дрейф | Новые двери, другой герой, разворот оси, телепортация, мгновенная остановка, необъяснимый скачок света/звука |
| Проверка стыка | Конец A + начало B в последовательном просмотре со звуком; дефект, решение и пригодные интервалы |

Продолжение по референсу и физическое продолжение движения — разные вопросы. Даже при доступной передаче MP4 отдельно проверить состояния. Если A движется, а B неподвижен, нужна видимая остановка или согласованное сокращение времени; слово continuation этого не исправляет.

## 5. Physics checks

- Колёса вращаются сообразно перемещению, шины касаются дороги; кузов не скользит и не проходит сквозь предметы. При остановке скорость меняется постепенно, если монтаж не объясняет пропуск времени.
- Тормозной суппорт закреплён относительно подвески/кулака и не вращается вместе с диском. Проверять только если деталь различима; невидимое помечать NOT_OBSERVABLE.
- Дверь вращается на канонической петле; её размер, стойки, окна и доступный зазор сохраняются. Руки и предметы удерживают контакт, люди не проходят сквозь салон.
- Направление фона, параллакс и движение камеры согласованы. У закреплённой в машине камеры фон движется по логике движения машины.

Смотреть движение в нормальном темпе и проблемный интервал замедленно. Первый/средний/последний стоп-кадры помогают локализовать дрейф, но не подтверждают физику переходов.

## 6. Inspection: пять осей и решение

Для каждой оси записать файл/версию, просмотренный интервал, наблюдение, статус и действие. PASS относится только к проверенному свойству, FAIL — к наблюдаемому дефекту, NOT_RUN — проверка не выполнена, BLOCKED — отсутствует необходимый материал/поддержка. Невидимые свойства обозначать NOT_OBSERVABLE с причиной; общий PASS из них не выводить.

| Ось | Наблюдаемая проверка |
| --- | --- |
| 1. Identity | Лицо, одежда и узнаваемость в начале, середине, конце и во всём движении |
| 2. Geometry | Пропорции, двери, стойки, окна, колёса, реквизит; отсутствие раннего раскрытия длины |
| 3. Motion / physics | Контакты, инерция, вращение, направление, фаза действия и камера |
| 4. Speech / sound | Утверждённые слова и голос, разборчивость, паузы, отсутствие дубля речи, согласованность звучащих событий |
| 5. Delivery | Фактические длительность, размер, соотношение сторон, fps и доступный файл; пригодные монтажные интервалы |

Дополнительно проверить **стык A→B** и целую сцену в 16:9 и 9:16: cue, ось, состояние, смысл раскрытия и непрерывность звука. Метаданные и status=completed не доказывают художественную приёмку; просмотр без звука не закрывает ось 4. Запрошенные fps/разрешение не заменяют измеренные.

## 7. Fallback

При неподдерживаемой опоре, дрейфе или неточном раскрытии выбрать минимальное изменение, сохраняющее событие: упростить движение → закрепить камеру/действие → разделить на два независимых клипа → точная склейка в CapCut. Если ошибочна исходная геометрия, вернуться к «Кадрам»/утверждённым опорам; монтаж не исправляет канон. Не превращать fallback в автоматический платный повтор.

Записать триггер, выбранную замену, что сохраняется по смыслу, какие входы/выходы и монтажные заметки изменились и какие проверки повторить. При изменении промпта, опор, модели или версии материала прежнее согласование не переносить автоматически: действующие quote/hash/confirm gate применяются заново. При submit UNKNOWN остановиться, сохранить holds и сначала сверить исходный расход; повтор не является fallback.

## 8. Пример: «Таксист Грэм», длина скрыта → полный профиль

**Условие задания:** жёлтый удлинённый ВАЗ-2106 и утверждённая фраза диктора, после которой можно раскрыть длину. Это постановочный пример, не правка канона. В старом контексте ветки встречается цвет «баклажан»; пакет задачи и Draft PR #102 описывают жёлтый вариант. Перед производством нужен утверждённый снимок канона нужной версии. До его получения — CANON_REFERENCE_PENDING; при расхождении — BLOCKED, без перекраски или изменения профиля по собственной инициативе.

**Материалы:** выбранные утверждённые ракурсы машины спереди/сбоку/сзади (geometry), Грэм при его появлении (identity), композиции A и B, единый look. Реальные ID/пути и версии заполняются из проекта. Реплика: **требуется существующий утверждённый line_id/версия и аудиофайл**; здесь их нет, текст не придуман. Performance Anchor не обязателен. До получения этих материалов точный тайминг и художественная приёмка BLOCKED/NOT_RUN.

| Бит | Содержание | Знание зрителя / склейка |
| --- | --- | --- |
| A, вход и удержание | Утверждённый тесный фронтальный ракурс или деталь передка; машина с самого начала канонической длины. В простом варианте стоит, камера неподвижна | Читается жёлтый ВАЗ; боковина, отражения, тени и фон не выдают длину |
| A, фраза диктора | Удерживать скрывающую композицию до конца утверждённой фразы; оставить достаточный запас дубля | Не расширять кадр, не растягивать кузов и не раскрывать профиль внутри A |
| Cue → B | После измеренного конца фразы сделать обычную жёсткую склейку в CapCut на полный боковой профиль | Первое полное раскрытие длины; без морфинга и перехода, смешивающего обе геометрии |
| B, удержание | Полный канонический профиль читается достаточно долго; тот же объект, свет, место, состояние, звук | Зритель успевает понять длину; длительность утверждается по сборке |

**Канонический профиль:** сверять всю видимую сторону с утверждённой опорой, включая ширину/длину, двери, стойки, окна, петли и колёса. Пакет фиксирует классический передок/зад ВАЗ-2106 и особую левую заднюю дверь. Дополнительные детали из WIP [knowledge base #102](https://github.com/gremoled77-droid/gremovod/blob/9a84a0b89af4c2b3fc0b5929602fd12d73b99239/docs/blender/BLENDER_KNOWLEDGE_BASE.md): без BMW-дизайна, BBS mesh; слева стандартная передняя дверь → короткая фиксированная вставка с отдельным узким окном → длинная задняя suicide-дверь с петлями на задней стойке; справа длинная задняя дверь с наружными петлями и дополнительная стойка с узким центральным окном. Лево/право — физические борта машины. Эти сведения WIP не заменяют утверждённый визуальный эталон и не разрешают добавлять двери. Грэма, если он виден, сохранять по его утверждённому референсу.

**A→B:** в простом fallback оба клипа показывают стоящую машину. Если исходный сценарий требует движения, согласовать состояния и торможение отдельно; не заменить их неподвижностью молча. B меняет ракурс и объём раскрытой информации, сохраняя геометрию. Независимая подготовка двух клипов допустима без video reference; совпадение проверить по общим опорам и стыку.

**CapCut:** положить утверждённый звук на шкалу, измерить конец фразы `t_cue`, выбрать границу кадра `t_cut >= t_cue` с нужной паузой по смыслу. Урезать A/B по пригодным интервалам, сделать hard cut, сохранить одну речь и согласованную атмосферу. Просмотреть последний участок A, стык и начало B, затем всю сцену. Не выдавать эту инструкцию за созданный проект CapCut или готовый MP4.

**Два формата:** для 16:9 и 9:16 заранее подобрать отдельные композиции A/B: A нигде не выдаёт длину, B целиком показывает канонический профиль с читаемыми пропорциями. Если профиль не помещается в вертикаль, изменить композицию/дистанцию по утверждённой опоре; случайный crop горизонтального кадра не считается готовым вертикальным раскрытием.

## 9. Негативные сценарии для проверки решения

Это документальные ожидания, не выполненные live-тесты.

| Случай | Ожидаемое решение |
| --- | --- |
| S1: нет утверждённого identity/канона | BLOCKED подготовки соответствующего входа; запросить реальный материал, ID не выдумывать |
| S2: video reference не поддержан | Не отправлять его; разрешённые изображения/текст, отдельные клипы и повторный review |
| S3: нет разрешённого голоса/образца | Не клонировать; утверждённый профиль либо вариант без речи |
| S4: внешняя TTS + native dialogue | Выбрать один источник речи; проверить отсутствие второго голоса |
| S5: A едет → B внезапно стоит | FAIL физики/стыка; остановка или согласованный пропуск времени |
| S6: длина видна до cue | FAIL раскрытия; исправить композицию A, включая отражения и оба формата |
| S7: лишняя дверь/стойка | FAIL геометрии; исправить материал, канон не переписывать |
| S8: MP4 отсутствует | Inspection NOT_RUN; приёмка BLOCKED, completed не равен PASS |
| S9: промпт/опоры изменились | Обновить версию и quote/hash/согласование по действующим правилам |
| S10: submit UNKNOWN | STOP, сохранить holds, сверить расход; без повторного платного запроса |
| S11: прошлый клип назван extension | Проверить маршрут; иначе только план reference-driven continuation |
| S12: проверены три стоп-кадра | Движение и звук NOT_RUN до просмотра/прослушивания соответствующих интервалов |
