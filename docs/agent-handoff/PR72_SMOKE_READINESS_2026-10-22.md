## Authorization contract v2

The MCP tool still has no enable/cwd/command/permission/grant argument. Startup policy
selects an owner authority directory. Its grant file must be a direct child of that
directory. `approval_scope()` is a local, non-inference scope preview; no CLI is run.

Grant fields are generated by smoke.py: version, canonical authority, policy digest,
request ID/digest, PR tag, exact input SHA, capability, max_calls=1, subscription_only,
timeout, Bridge HEAD/fingerprint, CLI fingerprint, unique 32-hex grant_id and an aware
expires_at. An empty expiry template is invalid. Expired/mismatched/old-v1 grants fail.
The source package/dependency installation remains trusted host software; fingerprint
checks are not a complete supply-chain attestation.

Before any provider CLI or model exec, an OS authority lock is held and the unique
claim file is created with exclusive creation and fsync. It is never automatically
deleted. A preflight/process failure may consume the grant without any model call;
this is intentional. Do not reset budgets, remove claims or reuse a prior grant.
The same-user host owner can edit files/code; this is an operational consent gate,
not protection against arbitrary malicious host programs.
