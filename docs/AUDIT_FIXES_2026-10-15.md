# Исправления по аудиту Claude — 15 октября 2026

## Блок 1: доступ к локальному API и расходы

- Разрешены Host `127.0.0.1`, `localhost`, IPv6 loopback. Посторонний Origin и cross-site Fetch Metadata отклоняются до обработчиков, включая multipart.
- Случайная сессия на каждый запуск сервера: `/api/session`, HttpOnly SameSite=Strict cookie для изображений и заголовок для запросов интерфейса. Это защита от сторонних страниц, а не от программ, уже работающих под учётной записью владельца компьютера.
- Воркер чата сохраняет собственную проверку ключа; основной чат Codex работает. Непроверенные API-LLM маршруты `/api/chat`, `/api/llm/chat`, `/api/compose`, `/api/agents/run` временно возвращают 503 до сетевого вызова. Для восстановления нужны проверенные тарифы, ограничения токенов, расчёт верхней оценки и такой же серверный бюджет. Превью контекста и локальные черновики доступны.
- `/api/model-jobs/estimate` выдаёт HMAC-подпись проекта, фактического payload, цены и срока 10 минут. Подмена параметров, перенос между проектами, истечение или перезапуск сервера требуют новой оценки. Подпись не является доказательством человеческого согласия; остаются отдельное подтверждение и лимит запуска.
- SQLite `BEGIN IMMEDIATE` сериализует проверку бюджетов и резервирование до запроса провайдеру. Повтор существующего request_id не вызывает оплату. Начальные лимиты: $1 на каждый проект и $2 в сутки по Москве; редактируются в «Экономике» и сохраняются в БД.
- Бюджет консервативно учитывает документированные оценки всех отправок, включая failed/submission_unknown, а не подтверждённые списания. Автоматического освобождения резерва нет. Исторические generation_approvals также учтены. Реальное списание провайдера может отличаться от документированной оценки.
- Отключённые видеоадаптеры отклоняются до разбора duration: 400 вместо KeyError/500.
- Фронтенд использует единый транспорт. После потери сессии платные запросы автоматически не переотправляются.

## Блок 2: сохранения, восстановление и доставка результатов

- Перед миграцией сохранена согласованная копия БД: `runtime/before-project-revisions-20261015.sqlite3`.
- Версия проекта `revision` автоматически повышается SQLite-триггером при изменении state/title, включая воркер и замену персонажа. Старую БД мигрируем без удаления содержимого. Обновление проекта требует `base_revision`; устаревшее или отсутствующее значение даёт 409.
- Интерфейс выполняет трёхстороннее объединение независимых правок. Одновременная правка одного поля останавливает сохранение; локальный текст остаётся в форме, доступно скачивание JSON-черновика. Прежние клиенты/скрипты должны сначала GET проект и передавать его revision как base_revision.
- Ручная привязка Task ID для `submitting`/`submission_unknown`: сначала GET существующей задачи и просмотр данных, затем явное подтверждение. Модель, task_type и промпт обязаны совпасть; отличия референсов/параметров показаны для ручной сверки, поскольку PiAPI нормализует URL. Привязанный к другому заданию Task ID отклоняется. Повторной генерации и нового бюджетного резерва нет.
- Фоновый монитор каждые 30 секунд проверяет известные Task ID и сохраняет completed-результаты в библиотеку. Неопределённые отправки без ID не пересоздаёт. Скачивания идемпотентны и сериализуются по заданию/индексу. Ошибки скачивания записаны отдельно; максимум 5 автоматических попыток с задержкой, затем ручной повтор скачивания.
- Галерея получает состояния доставки; карточки библиотеки используют кешируемые WebP-миниатюры до 512 px. Оригиналы доступны отдельно.
- Локальные изображения можно отдельно загрузить в ephemeral storage PiAPI по явному подтверждению в библиотеке. Официальная схема: `https://app.piapi.ai/docs/tools/file-upload`, Creator/Pro, ресурс до 24 часов. Локально ссылка кешируется 23 часа и может использоваться в сцене и Video Lab. Лимит оригинала 7,5 МБ выбран с учётом расширения Base64. В реальный аккаунт файлы при проверке не отправлялись; доступность зависит от тарифа. Документация сохранена в `docs/official-prompts/piapi-file-upload.html`.

Проверено: 40 серверных тестов, 3 теста фронтенд-объединения, tsc/Vite build. В браузере на отдельном временном проекте проверены объединение локального задания с новым серверным промптом и отказ при конкурирующей правке задания. Временный проект после проверки удалён. Скриншот: `docs/audit-conflict-verified-2026-10-15.png`.

Не завершено: подтверждённые тарифы и повторное включение платного LLM-резерва; общая библиотека персонажей и структура сериала; автоматический запуск Codex-чата из сервера.


## Бесплатное временное облако — 15.10.2026

- По запросу пользователя добавлен TempFile.org как временное хранилище по умолчанию, PiAPI оставлен в выборе провайдера как резерв.
- Официальная схема: https://tempfile.org/api, multipart POST /api/upload/local, files + expiryHours=24. Прямая ссылка строится по документированному fileId/download, а не по странице просмотра. Ключи генерационных сервисов в TempFile не передаются и не читаются.
- Срок ссылки хранится с запасом: не дольше 23 часов или раньше, если сервис сообщил более раннее истечение. Провайдер хранения включён в кеш; смена провайдера требует отдельной загрузки. Существующая таблица мигрируется с provider=piapi для старых записей.
