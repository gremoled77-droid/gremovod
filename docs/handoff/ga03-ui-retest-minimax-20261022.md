## Найденные дефекты и что исправлено

### 1. Стенд smoke занимал порты рабочей студии

`tests/release_gate_browser_smoke.mjs` поднимал интерфейс на 5173 или 8000 — это порты рабочей
студии (AGENTS.md: её фронт на 5173, бэкенд на 8000). В момент прогона 5173 был занят её фронтом,
и стенд занял бы 8000 — фронт рабочей студии проксирует `/api` на 8000 и начал бы говорить со
стендом.

Исправлено: стенд берёт свои порты (по умолчанию 5174, 5175, 5176, 8081 — `UI_PORTS` в
окружении переопределяется), backend — 8001 со своим `STUDIO_DATA_DIR` во временной папке.
`backend/security.py` пропускает Origin только с 5173/8000, поэтому прокси vite снимает
заголовки `origin` и `sec-fetch-site` — ровно то, что предписывает AGENTS.md для стенда на
других портах. Порт 8000/5173 рабочей студии не занимаются, чужие процессы не останавливаются.

### 2. Требование аудио не влияло на утверждение

Экран отправлял `required_modalities: ['VIDEO']` всегда. Чекбокс «требовать аудиодорожку» влиял
только на манифест N34: мастер без звука, измеренный без требования, спокойно утверждался, хотя
владелец на экране видел включённое требование.

Исправлено (`frontend/src/releaseGate.ts`): `requiredModalities(requireAudio)` даёт
`['VIDEO','AUDIO']`, когда требование включено. Сервер сам проверяет покрытие N35 и отклоняет
утверждение с `MEDIA_NOT_CONFIRMED`. Допуск по-прежнему решает сервер — клиент только передаёт
требование владельца.

### 3. Экран не показывал, с каким требованием мерили N34

Манифест N34 сервер не хранит (в таблице `release_artifact_qc` его нет), а вердикт относится
именно к тому манифесту, которым мерили. Экран показывал просто «Пройдена».

Исправлено (`frontend/src/StageSummary.tsx`): измерение запоминает манифест, на экране видно
«(с требованием аудиодорожки)» / «(без требования аудиодорожки)», а если владелец поменял
требование после проверки — предупреждение, что вердикт получен с другим требованием.
Предупреждение, а не запрет: допуск считает сервер.

### 4. Причина от сервера терялась

Ответы release-gate кладут причину во вложенное поле `detail` объекта деталей (например,
`AUDIO: в мастере нет аудиодорожки`), а `errorText` читал только `detail.message`. Владелец видел
«Мастер не покрывает требуемые модальности» без объяснения.

Исправлено (`frontend/src/releaseGate.ts`): причина показывается вместе с сообщением сервера.
Сырой вывод FFmpeg при этом не выводится — он появляется только вместе с сообщением сервера
по-русски.

## Что осталось нерешённым

1. **Блок N35 на экране не показывает покрытие AUDIO.** `backend/release_gate.py:128` жёстко
   зашивает `['VIDEO']` в read-модели свидетельства N35, хотя при утверждении модальности
   берутся из тела запроса. Это правка бэкенда, она вне моего фронтового scope — решение владельца.
2. **Требование аудио живёт только на клиенте.** Сервер не сохраняет манифест N34, поэтому после
   перезагрузки страницы экран показывает вердикт сервера, но не показывает, с каким требованием
   он получен. Требует изменения схемы `release_artifact_qc`.
3. **Настоящий вход владельца не реализован** (`OWNER_AUTH_REQUIRED` в бэкенде): `owner_id` —
   атрибуция, а не аутентификация. Известная граница, на экране написано прямо.
4. **Реальный MP4 владельца не проверялся** — только синтетические файлы ffmpeg (320×240, 2 с).
   CapCut, мобильная версия и облако не проверялись.
5. **Файлы PR #86 не соответствовали стилю проекта** (`prettier --check` падал на всех четырёх).
   Привёл к `frontend/.prettierrc.json` — из-за этого диф в `tests/release_gate_browser_smoke.mjs`
   больше, чем содержательные правки.

## Зависимость от PR #87

PR #87 (`build/claude/ga-03-scope-ext`, коммит `c40f8bd`) расширяет область `ga-03` в
`tools/minimax_task_scopes.json` на `frontend/src/releaseGate.ts`, `frontend/src/design.css` и
`tests/release_gate_browser_smoke.mjs` — без него мои правки выходят за объявленную область.

Манифест в эту ветку **намеренно не включён**: guard в PR #87 относит
`tools/minimax_task_scopes.json` к control-файлам (`CONTROL_FILES`) и читает манифест из
базовой ревизии, чтобы ветка не могла расширить свою область тем же PR. Scope-ветка `minimax/*`,
меняющая сам манифест, получила бы `CROSS_OWNER_CHANGE`.

Все четыре изменённых файла попадают в расширенную область `ga-03` из PR #87:
`frontend/src/StageSummary.tsx`, `frontend/src/releaseGate.ts`,
`frontend/src/releaseGate.test.mjs`, `tests/release_gate_browser_smoke.mjs`.

Порядок для владельца: **PR #87 должен встать в базу до PR #86** (или до моего PR), иначе
scope-проверка моей ветки останется в режиме `NO_SCOPE_MANIFEST` / `LEGACY_BRANCH_NOT_ENFORCED`
и фактически ничего не проверяет — а вместе с PR #87 приезжает и offline-CI, который гоняет
`pytest` и `npm test`.


в своём каталоге, `C:\AI_Workflow_Studio\backend\studio.sqlite3` не тронута.

Примечание: в рабочей копии остался неотслеживаемый каталог `.stand-data/` — это данные пробного
запуска (собственная `studio.sqlite3` и пустые `media`/`character_library`). Он не попадает в
коммиты и его можно удалить обычным `Remove-Item`; в команде выше каталог данных вынесен за
пределы репозитория, чтобы такое больше не повторялось.
