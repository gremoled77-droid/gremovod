### 2. Устранить подтверждённое мобильное переполнение демо

Точки входа в текущей main `5474a70`:

- `frontend/src/StoryboardDemo.tsx` — разметка демо; `.sd-layout`, сцены, карточки и редактор сущности.
- `frontend/src/StoryboardDemo.css` — `.sd-layout`, `.sd-scene`, `.sd-links`, `.sd-mini`, `.sd-frames`, `.sd-frame`, `.sd-shell`, мобильный media query.

Проверить min-content у grid-детей и flex-элементов, фактическую ширину сцены и строки кадров. Существующий `.sd-frames` намеренно имеет `overflow-x:auto` и фиксированные карточки по 190px; сначала определить, где горизонтальная лента раздувает всю сцену. Минимальный путь — `min-width:0` у реально переполняющего grid/flex-ребёнка и ограничение ширины ленты. Если лента остаётся горизонтальной, она должна прокручиваться **внутри своей области**, а не тянуть весь экран. Перенос/мобильная сетка — если локальная прокрутка не решает доступность. Не скрывать проблему глобальным `overflow-x:hidden` или уменьшением масштаба страницы.

Приёмка: 390×844 и 360×800, общая рабочая область без горизонтального скролла, кнопки и участники не обрезаны; при 1440×900 нет регрессии. Проверить также одиночное длинное имя участника. Сохранить до/после в одной компоновке. Эта часть не требует изменения API или платного вызова.

### 3. Перестроить карточку вокруг выбранного изображения

В `StoryboardDemo.tsx` один редактор используется для разных типов сущностей. Изменение проверять для кадра, сцены, героя, локации и вложенного открытия; не переставлять общую форму вслепую.

Минимальная композиция для кадра:

1. Заголовок и выбранное изображение; если изображения нет — понятное пустое состояние.
2. Ввод «Что изменить» и относящееся к нему действие GPT.
3. Варианты и выбор основного; действие «Оживить выбранное» относится именно к основному изображению.
4. Дополнительные сведения: описание, участники, локация и референсы остаются доступны в раскрываемом блоке либо ниже рабочей группы.

Использовать существующие компоненты и состояние. Сохранить `selected`, `prompt`, обработчики загрузки, ограничения выполнения заданий и сброс устаревшего видео при выборе варианта. Не дублировать выбранное изображение через новое состояние и не запускать генерацию при раскрытии/переключении. Desktop: превью и текущий запрос видны вместе; mobile: превью находится до длинных метаданных. Закреплённый action bar добавлять только при необходимости, проверив перекрытие контента и экранной клавиатуры.

Production проверять отдельно: `frontend/src/ProductionStoryboard.tsx` использует `ProductionEntityEditor.tsx`, а не `StoryboardDemo.tsx`. У рабочего экрана кадров собственный `CreateScreen.tsx`. Если проблема подтверждена там, сделать отдельный небольшой пакет с сохранением реального маршрута референсов/цены/подтверждения; не копировать демо-обработчики в рабочие экраны.

### 4. Согласовать оформление и прикрепление

Источник токенов — актуальный `frontend/src/design.css`, не значения из старого AuthKit-отчёта. В `StoryboardDemo.css` есть собственные фон, шрифт, фиолетовые `.sd-active/.sd-primary`, hover/focus и рамки. Привести роли к общей системе минимально: primary, secondary, selected, focus, disabled. Не менять палитру и шрифты всего сайта.

У загрузки референсов сохранить доступный file input, label, accept, multiple, обработку ошибок и удаление из текущего запроса. Можно оформить одной зоной прикрепления и миниатюрами; не скрывать input способом, делающим его недоступным клавиатуре. Не приравнивать сущности сцены к фактически отправляемым референсам без проверки маршрута.

### 5. Улучшить сообщение о связи с сервером

В текущей main текст находится в `App.tsx`: catch начальной загрузки и блок с «Повторить открытие проекта». Предложение: «Нет связи с сервером» + понятное следующее действие + повтор; техническую команду оставить в подробностях. Использовать существующий `startupAttempt`, не добавлять второй polling/retry-механизм. Не писать время успешной проверки или обещание восстановления без соответствующего события. ## Как сдавать каждый пакет

- До/после: одинаковые данные, viewport и состояние; локальные скриншоты без выгрузки проектов третьим лицам.

- Для чистого CSS без новой логики не добавлять тесты на строки стилей. Для изменённой логики выбора/состояния — узкий содержательный тест в существующем наборе. Проверки frontend по правилам проекта: `npm test`, `npx tsc --noEmit`, `npm run build`, форматирование изменённых файлов. Backend-проверки — если он действительно меняется.
- Вручную: ширины 1440/390/360, клавиатура Tab/Shift+Tab/Esc, видимый focus, отсутствие перекрытия действиями и нижним меню. Проверка размеров контейнеров дополняет, а не заменяет скриншоты.
