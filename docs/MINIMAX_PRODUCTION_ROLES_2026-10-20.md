# Производственные роли MiniMax: пять навыков для дешёвого исполнителя

Дата: 20.10.2026. Контур 2, после контура 1 (агенты A0–A8 в n8n, `integrations/n8n/`).

## Задача

Дорогая модель (Sol, Sonnet, Opus) один раз придумывает идею и драматургию, дальше ролик штампует MiniMax. Слабые места быстрых моделей: вода вокруг JSON, выдуманные детали мимо канона, забытые технические ограничения генераторов. Пять навыков закрывают их по узлам: навык подключается точечно, там, где нужен, и не тащится во все промпты.

## Пять навыков

| Навык | Файл | Подключать | Что жёстко задаёт |
|---|---|---|---|
| `skill-strict-json-output` | [SKILL.md](../skills/skill-strict-json-output/SKILL.md) | на всех узлах MiniMax | только чистый валидный JSON по переданной схеме; без ```json-обёрток, вступлений и комментариев; при нехватке входа — `{"status": "BLOCKED_INVALID_INPUT", ...}` |
| `skill-canon-lock` | [SKILL.md](../skills/skill-canon-lock/SKILL.md) | «Мир», «Персонажи», «Раскадровка» | запрет менять внешность, одежду, возраст, палитру, физические приметы и локации из `[CANON]`; дублирование визуальных якорей в каждом шоте, потому что видеогенератор не помнит предыдущие кадры |
| `skill-video-prompt-crafter` | [SKILL.md](../skills/skill-video-prompt-crafter/SKILL.md) | «Кадры», «Видео» | сухой технический промпт: оптика → физическое действие → окружение и свет → движение камеры → текстура; абстрактная эмоция заменяется видимой физикой; при `prompt_style="found_footage"` — маркеры любительской съёмки |
| `skill-precheck-filter` | [SKILL.md](../skills/skill-precheck-filter/SKILL.md) | ворота перед критиками A6–A8 | чек-лист: все ли сцены и таймкоды на месте, укладывается ли хронометраж реплик в шот (не более 2.5 слов в секунду), совпадает ли `revision_id`; иначе `REJECTED_PRECHECK` с указанием строки дефекта |
| `skill-evidence-packager` | [SKILL.md](../skills/skill-evidence-packager/SKILL.md) | «Выпуск», Media Inspector и QA | сухой технический отчёт по артефакту: sha256, длительность, состав потоков, список кадров с таймкодами; без художественных оценок |

Тела первых четырёх навыков взяты из спецификации владельца дословно. Пятый (`skill-evidence-packager`) написан по реальным контрактам репозитория: `backend/media_qc.py` (`sha256_file`, `measure`, вердикты `PASS_TECHNICAL`/`FAIL`/`BLOCKED`) и `integrations/n8n/QA_EVIDENCE_POLICY.md` (`artifact_scope`, `checked_scope`, типы доказательств, запрет выдавать метаданные за просмотр).

## Реестр ролей

`backend/minimax_roles.py` — единственное место, где решено, какой набор идёт на какой узел.

- `BASE_SKILL` — `skill-strict-json-output`; подключается на всех узлах ровно один раз.
- `ROLES` — девять узлов студии по `frontend/src/StageNav.tsx`: `idea`, `world`, `chars`, `board`, `frames`, `video`, `sound`, `edit`, `release`.
- `GATE_SKILLS` — отдельный вызов-ворота перед дорогими критиками: `skill-precheck-filter`.
- `EVIDENCE_SKILLS` — пакет для Media Inspector и QA-контура: `skill-evidence-packager`.
- `ALIASES` — спецификация называет четвёртый навык `skill-cheap-gatekeeper`. Каноническое имя `skill-precheck-filter`, прежний идентификатор продолжает разрешаться.

Тексты читаются из `skills/<id>/SKILL.md`: YAML-заголовок отбрасывается, в модель уходит тело навыка. Версия — хеш содержимого, поэтому правка текста видна в журнале задания. Навык без файла пропускается и попадает в `missing_skills`, а не роняет набор.

## Как забрать набор

```
GET /api/llm/roles                 # весь реестр
GET /api/llm/roles?stage=frames    # набор одного узла
```

Ответ набора — готовые `{"id", "instructions"}` для `TextTask.skills` шлюза `backend/llm_guard.py`. Там же задаются `stage.id`, `stage.revision` и `response_format: "json"`, то есть узел, ревизия и требование строгого JSON идут на уровне задания, а не в тексте промпта.

Порядок вызова в контуре: дорогой продюсер задаёт канон → MiniMax на нужном узле получает набор из реестра → `skill-precheck-filter` отсекает брак до вызова A6–A8 → `skill-evidence-packager` собирает технический отчёт для приёмки.

## Что не сделано

- **Навыки не заведены в n8n.** `integrations/n8n/agent-manifest.json` — read-only снимок реальных ресурсов n8n; добавление туда неустановленных скиллов сделало бы снимок недостоверным. Синхронизация GitHub ↔ n8n остаётся отдельной задачей (Skill Sync).
- **Ни одного платного вызова.** Проверка шла только по файлам репозитория, без обращения к провайдеру.
- **Расхождение по found-footage.** `skill-video-prompt-crafter` требует маркеры любительской съёмки, а уже реализованный в коде профиль `backend/prompt_rules.py::FOUND_FOOTAGE_RULES` требует блоки WORLD LOCK / TIMECODED BEATS / MANDATORY / NEGATIVE. Это два независимых источника требований; свести их — следующий шаг.
- **`skill-evidence-packager` сам не измеряет.** Он получает уже измеренные факты: измерение остаётся за `backend/media_qc.py`, вердикт — за серверным QC.
- **`skill-strict-json-output` не заменяет серверную проверку.** `llm_guard.validate_task_result` по-прежнему отклоняет невалидный JSON; навык снижает число таких ответов, но не отменяет проверку.
