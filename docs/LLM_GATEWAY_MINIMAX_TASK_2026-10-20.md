# GremoVOD — MiniMax: Multi-provider LLM Gateway (20.10.2026)

**Задача:** расширить существующую AI Workflow Studio общим LLM Gateway для недорогих и бесплатных текстовых моделей, без создания второй платформы и без нарушения действующих защит от расходов.

**Ключевое решение владельца:** сначала на карточке каждого вызова показ тарифной стоимости Kie.ai / PiAPI (даже для бесплатного API); в «Бюджет / Экономика» суммируется **только фактическое списание**. Полное обязательное правило и контрольные примеры: [LLM_GATEWAY_COST_DISPLAY_POLICY_2026-10-20.md](LLM_GATEWAY_COST_DISPLAY_POLICY_2026-10-20.md). При разночтениях оно приоритетнее общего задания.

- Проверить git status, список worktrees и историю. При несовместимых незакоммиченных правках остановить затрагивающее их изменение, не применять reset --hard / force-push.
- Сначала составить карту того, что уже реализовано. Ключевые модули: backend/main.py (эндпоинты /api/llm/estimate и /api/llm/chat), backend/llm_guard.py (PRICES, quote, reserve, llm_calls), backend/connections.py (PIAPI/KIE и ключи), backend/kie.py (существует для image/video, это не универсальный текстовый адаптер), backend/economics.py, backend/series_economics.py, backend/security.py, backend/model_catalog.py и соответствующий frontend. Не переписывать image/video.

## 1. Провайдеры и роли

Список ниже — ориентировочные снапшоты тарифа на 20.10.2026, не разрешение на платный запуск, не подтверждение live-доступности.

| Провайдер | Модель | Роль | Input / output $ за миллион токенов |
| --- | --- | --- | --- |
| Kie.ai | GPT-6 Luna | дешёвые простые задачи | $0.03 / $0.15 |
| Kie.ai | Claude Haiku 5.5 | независимые проверки, редактура | $0.06 / $0.30 |
| PiAPI | GPT-5.6 Luna | запасной дешёвый маршрут | $0.02 / $0.12 (акция) |
| MiniMax direct | MiniMax M3.1 Flash | код и сложные агентные задачи | $0.15 / $0.60 |
| DeepSeek direct | DeepSeek Flash | резерв и анализ | тариф зависит от временных условий: сверить официальную страницу |
| OpenRouter | MiniMax M3.1 Flash Free | опциональные бесплатные тесты | $0 / $0 при доступной квоте |

Для интеграции: Kie GPT-6 Luna использует специализированный Responses-эндпоинт; Kie Haiku — Claude Messages; PiAPI — существующий chat/completions. MiniMax, DeepSeek, OpenRouter подключать отдельными адаптерами, а не заменой host при несовместимых протоколах. Проверить точные upstream model IDs, версии, capabilities, rate limits, цену кеша, токены размышления и особенности responses/tool calls по документации до включения.

**Не смешивать тарифы моделей в расчётах реальных денег.** Цена GPT Luna может использоваться как честно помеченный ценовой ориентир для другой модели, но фактический платёж всегда рассчитывать по тарифу того поставщика, который выполнил запрос.

## 2. Обязательные функции

1. Единый server-side model registry с датой/URL источника цены, проверкой поддерживаемых функций, enable/verified-флагами; никакие произвольные upstream URL/модели не приходят от пользователя.
2. Действующие API и signed quote сохранить обратно совместимыми; подпись связывает проект, provider, model, версию цены, hash сообщений/настроек/tools, max_tokens, выбор fallback и допустимый максимум платежа.
3. До любых платных вызовов — оценка *реальной* стоимости, атомарная резервация бюджета, проверка лимитов проекта/дня/серии, подтверждение владельца. Бесплатный маршрут тоже журналировать; запрещено резервировать ориентир как реальную оплату.
4. Защитить идемпотентность по request_id, race condition, timeout с возможным списанием, Cloudflare 1010/401/403, 429/5xx; нельзя бесконечно пробовать fallback и списывать по нескольку раз.
5. Route modes manual/auto. По умолчанию без параллельных вызовов нескольких LLM. Выбор по задаче: simple=Kie Luna; editorial=Kie Haiku; coding=MiniMax (Free только opt-in); резерв=DeepSeek; PiAPI как дополнительный маршрут. Автопереключение только если соответствует разрешенному ограниченному бюджету, функциям и политикам владельца.
6. Usage, cache tokens, unknown-cost status, сохраняемые price snapshots. Никакой фиктивной точности при отсутствующем usage; ноль только при подтверждённо бесплатном маршруте.
7. В UI: карточка LLM-вызова с главным ценовым ориентиром Kie/PiAPI, исполняющей моделью и статусом; в подтверждении реальный ожидаемый платёж, в Экономике — только actual, отдельно pending/unknown/reference. Это требуется и для узлов/n8n.
8. Продолжать применять существующую политику API-ключей: KIE_API_KEY, PIAPI_API_KEY; для новых провайдеров MINIMAX_API_KEY, DEEPSEEK_API_KEY, OPENROUTER_API_KEY. Секреты только серверные, не печатать, не коммитить.

## 3. Этапы

- **A. Аудит:** сопоставить существующий код, схемы БД, маршруты и зависимости. Отчет о блокерах и о том, что можно переиспользовать.
- **B. MVP:** Kie Luna, Kie Haiku, PiAPI backward compatibility; эталон Kie/PiAPI + реальный ledger; MockTransport тесты.
- **C. Остальные:** MiniMax direct, DeepSeek direct, OpenRouter free + предсказуемые fallback и ограничение бюджета; mock-схемы.
- **D. UI и n8n:** минимальные изменения существующих экранов; одинаковые правила учёта в UI, API и агентах; dry-run инструкции n8n.
- **E. Реальные проверки:** только после отдельного одобрения владельца для конкретных расходов. Не включать запуск новой модели без подтвержденных схемы, тарифа и разрешения.

Не подключать LangChain, Redis, Celery, Kafka, новую БД, облачные сервисы только ради MVP. Основа уже есть: FastAPI, SQLite, httpx, React + TypeScript.

## 4. Обязательные проверки

- Бесплатный OpenRouter отдает корректный тарифный ориентир Kie/PiAPI, бюджет +$0.
- Платный direct API показывает ориентир и отдельно истинную сумму к оплате до подтверждения; бюджет учитывает только фактическую стоимость.
- Fallback после Free корректно добавляет только платежи реально платного поставщика; неизвестные начисления не становятся нулём.
- Нет утечки ключей, неправильно подписанных quote, двойных платежей, изменения старых image/video вызовов или потери исторических llm_calls.
- Моки Kie Responses и Haiku Messages, OpenRouter, MiniMax, DeepSeek; 403/1010/429, timeout, error-body 200, нет usage, cache, микросуммы, злонамеренный provider/URL.
- Команды для полной проверки: python -X utf8 -m unittest discover -s backend -p "test_*.py"; python -m pytest backend (если доступно); в frontend npm test и npm run build. Указать фактические PASS/FAIL/SKIP; не утверждать, что тесты запущены, если нет.
