# ГремоВОД v2 — логика экранов

Дата: 24.10.2026. Ветка `claude/gremovod-v2`. Статус: ТЗ на согласование владельцем. По нему уже сделана только серверная часть мира (коммит `f4e5110`).

ГремоВОД v2 — новая оболочка в одном окне поверх прежнего сервера и базы. Делаем **мультфильм**: простой объёмный мульт-стиль, архитектура Минска по реальным фото — место должно узнаваться, суперреалистичная чёткость не нужна. Чем меньше сложных элементов, тем проще генерация.

**Масштаб серии (ориентир владельца, не жёсткое правило):** серия ≈ 4 мин = 240 с ≈ 20 сцен по ~12 с; сцена = 2–3 кадра (одна видеогенерация на кадр, 4–6 с); у кадра несколько дублей, в сборку идёт один. Итого 40–60 кадров на серию. Короткие версии (Shorts) пока не делаем. Уровни: **Проект → Серия → Сцена → Кадр**; сбоку — **Мир** (общие герои, локации, стиль). Цель — полная серия: изображения → видео → звук → комплект для CapCut. Сначала делаем десктоп, телефон — позже, как пульт.

## 1. Общие правила оболочки

| Зона | Правило |
| --- | --- |
| Шапка | ◆ ГремоВОД и путь с реальными названиями («ГремоВОД › Пилот › Сцена 06 › Кадр 03»); каждое звено ведёт на свой уровень. Справа — сумма с масштабом («Сцена 06 · $3.10») и счётчик очереди; оба открывают шторку. |
| Левая панель | Одна на всех уровнях: **Мир** (Герои, Локации, Стиль), **Серии** (текущая раскрыта до сцен), **Библиотека** (Без привязки). Внизу свёрнуты «Инструменты» и «Настройки». |
| Центр | Основную площадь занимает рабочий материал. Вкладки — только этапы текущего уровня. |
| Шторка справа | Открывается по кнопке, постоянно не висит: «Что уйдёт в запрос», свойства, расходы, очередь (`Dock.tsx`). |
| Дорожка внизу | Только у сцены и кадра (кадры сцены с длительностями) и в «Сборке» серии. Сворачивается. |
| Текст | Ни одно название не повторяется на экране дважды. Пояснения — за «И». На экране одно главное действие; редкие — в «⋯». |
| Адрес | У каждого места свой адрес; кнопка «Назад» в браузере поднимает на уровень выше. |
| Деньги | Навигация, восстановление и просмотр ничего не запускают. Любой платный запуск идёт через оценку и подтверждение (`GenerationReview`). |

**Студия не привязана к ГремоВОДу.** Уровни, состояния, отбор референсов, формула кадра и расходы — общие для любого проекта. Всё, что делает ГремоВОД ГремоВОДом (стиль, мир, «Запрещено», слои), лежит в **паспорте проекта** и меняется без кода. Следующим проектом может быть другой мультфильм или реалистичное кино: создаём проект, выбираем режим, заполняем паспорт.

Слова интерфейса: проект, серия, сцена, кадр, место, вариант, герой, образ, дубль. Слов «эпизод» и «ролик» в интерфейсе нет; в коде сцена остаётся `episode`.

## 2. Состояния — одинаковые на всех экранах

Готовность считается только по данным, никогда — по посещённым экранам.

| Объект | Состояния | Откуда берётся |
| --- | --- | --- |
| Фото кадра | нет → есть варианты → **утверждено** | файлы кадра, `selected_image_file_id` |
| Видео кадра | нет → идёт → есть дубли → **дубль выбран** → **принят** | файлы кадра, `selected_video_file_id`; «принят» — новая отметка владельца после просмотра со звуком |
| Звук кадра | реплик нет / реплики без файла / **озвучено** | `frame_sound_cues` |
| Кадр | **готов** = фото утверждено + дубль принят + реплики озвучены | вычисляется |
| Сцена | **готова** = все кадры готовы, назначены место и герои | вычисляется |
| Серия | **к выгрузке** = все сцены готовы; **проверена в CapCut** — отметка владельца после импорта | вычисляется + отметка |
| Материал мира | загружен → **утверждён** (основной) → в архиве (бывший основной) | `selected_image_file_id` узла, у героя — `working_asset_id` |
| Герой | **готов** = утверждён пакет из 8 ракурсов и назначен голос | слоты пакета героя |
| Место | **готово** = утверждён основной фон; ракурсы пакета — по мере надобности | слоты пакета места |
| Оценка сцены | 7 фильтров по 0–2 (см. §6), сцена смотрится на фоне всей концепции | отметка владельца |

Пока отметки «принят» нет, интерфейс пишет «дубль выбран», а не «готово».

## 3. Проект — главная

**Зачем:** понять, где остановился, и вернуться туда одним нажатием.

**Видно:**
- большая кнопка **«Продолжить работу»** с точкой и временем («Пилот › Сцена 06 › Кадр 03 · Видео · вчера») и меткой «есть черновик», если он есть;
- серии: номер, название, число сцен, хронометраж по плану и по факту, «дубль выбран N из M», сколько потрачено; кнопка «+ серия»;
- одна строка пропусков по миру («у Грэма нет голоса · 3 сцены без места»).

**Не показываем:** общую ленту материалов, конвейер этапов, круги бюджета.

**Главное действие:** «Продолжить работу».

**Как работает «Продолжить работу»:**
- Точка хранится на сервере (таблица `workspace_cursor`): серия, сцена, кадр, этап, просматриваемый вариант. Записывается только при переходах внутри серий, сцен и кадров; Мир, Библиотека, Расходы и Настройки её не меняют.
- Восстановление не меняет выбранные фото и дубли: просматриваемый вариант хранится отдельно от выбранного.
- Если кадр в архиве или удалён, открывается ближайший доступный уровень выше с объяснением («Кадр 03 в архиве — открыта сцена 06»). Соседний кадр не подставляется, черновик не удаляется.
- Черновики текстов хранятся в браузере, как сейчас, с меткой «не сохранено»; при уходе студия спрашивает «сохранить или отбросить».

## 4. Мир

**Зачем:** один источник героев, мест и стиля для всех серий. Отсюда в запрос уходит только утверждённое.

**Слева — дерево:**
```
Герои
  Грэм
    Зима            (образ)
Локации
  Минск
    Немига
      Двор на Немиге
        Ночь        (вариант)
        Зима        (вариант)
Стиль
Без привязки  26
```

**В центре — папка выбранного узла:**
- заголовок с типом («Ночь · вариант места „Двор на Немиге“»);
- три фильтра: **С натуры** (реальные фото), **Референсы**, **Все изображения**; утверждённое помечено ✓ и стоит первым;
- под галереей одна строка: что узел берёт у родителя («Геометрия: фон двора ✓» или «Лицо: основной образ Грэма ✓») и «Где используется: Пилот › Сцена 06, 07».

**Действия:**
- «Загрузить» — с компьютера или перетаскиванием файлов, в том числе из `!GREM TAXI`;
- у картинки — «Сделать утверждённым», в «⋯» — «В корзину» и «Перенести»;
- в дереве — «+ место», «+ вариант» (только у места), «+ образ» (только у героя).

**Паспорт проекта** (бывший «Стиль») — общая основа каждого промпта. Принадлежит проекту (у каждого проекта свой), читается при каждом запросе, в кадр не копируется.

- **Режим** — заготовка, с которой начинается паспорт: «3D-мульт», «реалистичное кино» и др. Режим заполняет уровень стилизации, блок стиля и базовый список «Запрещено»; дальше всё правится вручную. Библиотека режимов общая для всех проектов.
- **Эталон стиля** — одна утверждённая картинка, задающая отрисовку. У ГремоВОДа пока не выбран: владелец делает пробные картинки, выбирает лучшую — «Сделать эталоном стиля». До выбора паспорт помечен «стиль не утверждён».
- **Поля:** место и время; главная идея мира; уровень стилизации; архитектура (для ГремоВОДа — реальный Минск по фото, узнаваемо, без лишних деталей); материалы и фактуры (как упрощаются поверхности); палитра; логика света («свет с причиной»); настроение; камера; **Запрещено** (единый список проекта; в запрос уходит утверждениями, а не «no …»).
- **Палитра и время суток в паспорте не фиксируются.** Прежние значения «баклажан, янтарь, ночной Минск» отменены владельцем.
- **Надписи разрешены:** точный короткий текст пишется в промпте в кавычках; сложные и «красивые» надписи — в монтаже.
- **Слои времени** — описываются в паспорте, включаются у сцены. Для ГремоВОДа: «Воспоминание 2014» — более старый, менее яркий, ближе к ч/б, с шумом. Детали эпохи (машины, телефоны, вывески 2014) идут в промпт; сам вид «старой записи» лучше накладывать фильтром в монтаже, а не просить у генератора: дешевле, одинаково на всех кадрах, отменяется.

**Кнопки сцены** (по умолчанию для всех её кадров, кадр может переопределить): **время суток** — день / сумерки / ночь; **погода** — ясно / пасмурно / дождь / снег; **слой** — основной / воспоминание. Свет кадра по умолчанию следует из времени суток и источников места.

**Карточка героя:** описание внешности, голос (сервис, голос, пример), образы и **обязательный пакет из 8 ракурсов**: лицо анфас, 3/4 слева, 3/4 справа, профиль; полный рост спереди, сзади, слева, справа. Пока пакет не утверждён, герой не «готов» и сцена показывает это как пропуск. Пакет лежит в папке героя; генерация пакета — существующий `SheetPanel`/`sheetShots.ts` (сейчас там другой набор: эмоции вместо видов сзади и сбоку — привести к 8 видам).

**Машина — отдельный герой.** «Шестёрка» — вымышленная машина по мотивам ВАЗ-2106; владелец моделирует её в Blender, чтобы она была одинаковой во всех кадрах. Своя карточка в дереве Мира (группа «Транспорт»), свой **пакет ракурсов**: спереди, сзади, слева, справа, две 3/4, салон с места водителя, салон с места пассажира. Рендеры из Blender загружаются как референсы «С натуры» и утверждаются как пакет. Проверка по ракурсам машины — та же, что у героя.

**Главные герои и массовка.** Сначала утверждаются пакеты топ-5 главных героев. Затем — **массовка**: отдельная группа в «Героях», простые люди в той же стилистике, без особой детализации, с настроениями (грустные, весёлые и т.д.). Массовка уходит в запрос с ролью «люди на фоне» и никогда не подменяет главного героя.

**Пакет места** (по желанию, слоты): общий, средний, деталь, обратная точка, с героем внутри. Ночная или зимняя версия — не ракурс, а **вариант** места.

**Без привязки:** старые файлы, которым нет места в дереве. У каждого видно, откуда он: дата, промпт, модель. Действие — «Перенести в…» с выбором узла. Автоматически ничего не раскладывается.

**Правила:**
- место задаёт геометрию, вариант — тот же план с другим светом или сезоном; вариант внутри варианта создать нельзя;
- герой — одна карточка; образ берёт лицо у героя; герой и его образ не могут стоять в одной сцене одновременно;
- если у варианта нет утверждённого фона, сцена показывает «варианта Ночь ещё нет» и не подменяет его похожим;
- генерация кадра сама в мир не попадает; «В мир» — отдельное действие.

**Готово:** у каждого используемого героя есть утверждённый образ и голос, у каждого используемого места или варианта — утверждённый фон.

**Уже есть в коде:** дерево, варианты, образы и отбор утверждённого (`production_folders.py`, `production_entities.py`, `test_world_tree.py`); загрузка в папку узла; галереи героев (`CharactersScreen`, `CharacterReferences`) и локаций (`LocationsTab`). **Нужно сделать:** экран дерева, раздел «Без привязки», строку «Где используется».

## 5. Серия

**Зачем:** история серии и сборка всей серии из выбранных результатов.

**Три режима центра:**

1. **История** — сюжетная доска.
   - Исходный сценарий сохраняется как есть.
   - Карточки сцен: название, кратко, герои, место, что меняется; порядок.
   - ИИ предлагает разбиение по кнопке с оценкой цены; карточки принимаете вы.
   - «Применить к сценам» — отдельное действие после просмотра изменений.
   - Уже есть: `StoryPlanBoard.tsx`, `story_plan.py`.
2. **Сцены** — сетка сцен по порядку: номер, название, место, герои, миниатюры кадров, состояние («кадры 3/5 · дубли 2/5»), план и факт по времени. Нажатие открывает сцену. Уже есть: `ProductionStoryboard.tsx`, `storyboard.py`.
3. **Сборка** — дорожка серии.
   - Выбранные дубли по порядку сцен и кадров, реальные длительности, реплики; сквозная музыка и атмосфера отдельными дорожками.
   - Список «чего не хватает».
   - Кнопка «Собрать комплект для CapCut», после импорта — отметка «проверено в CapCut».
   - Уже есть: `edit_list.py`, `EditListPanel.tsx`, `MotionPanel.tsx`. Нужно сделать: интервалы клипов и отметку проверки.

**Главное действие** зависит от режима: «Применить к сценам», вход в сцену или «Собрать комплект».

**Следующий шаг:**
- нет сцен → «Разбить сценарий на сцены»;
- у сцены нет места или героев → указать;
- есть невыбранные дубли → к первому такому кадру.

**Хронометраж:** план — из карточек сцен, факт — сумма выбранных дублей (позже — выбранных интервалов). Число сцен и их длина не фиксированы.

**Готово:** все сцены готовы, комплект собран, импорт в CapCut проверен владельцем.

## 6. Сцена

**Зачем:** поставить сцену и довести её кадры до готовности.

**Видно:**
- сверху — название, место (с вариантом) и герои сцены с кнопкой «Изменить»; коротко — замысел сцены из карточки истории;
- в центре — кадры сцены крупными миниатюрами (утверждённое фото, если есть); под каждой состояние «фото ✓ / дубль ✓ / звук ✓» и кнопка «+ кадр»;
- дорожка внизу — кадры по порядку с длительностями и реплики под ними.

**Главное действие:** открыть кадр, которому нужен следующий шаг (кнопка «Дальше: кадр 03 — выбрать дубль»).

**Следующий шаг:**
- нет места → выбрать место;
- у места нет утверждённого фона → перейти в Мир к этому месту;
- нет кадров → «Добавить кадры»;
- дальше — первый незаконченный кадр.

**Правила:**
- кадры наследуют место и героев сцены; кадр может заменить ракурс места, но не само место без явного действия;
- порядок кадров в сцене — монтажный; очередь производства может быть другой и этот порядок не меняет.

**Оценка сцены — 7 фильтров** (по 0–2, итог 0–14: 0–6 переделать, 7–10 рабочая, 11–14 сильная). Смотрим сцену на месте, насколько она выбивается из общей концепции:
1. Смысл сцены в одном предложении. 2. Взгляд сразу на главном. 3. Ритм: события на акцентах. 4. Крупности чередуются осознанно. 5. Пластика: движения естественные, без «плывущих» тел. 6. Консистентность: герой, место и стиль стабильны. 7. Детали второго плана, которые хочется пересмотреть.
Слабый пункт ведёт к нужному кадру.

**Уже есть:** состав и место сцены (`SceneCast.tsx`), карточка сцены (`ProductionEntityEditor.tsx`), состояния кадров (`frameStatus.ts`).

## 7. Кадр

**Зачем:** получить для кадра утверждённое фото, принятый дубль и озвученные реплики.

**Сверху** — **смысл кадра одним предложением** (если не формулируется — кадр переделать). Под ним свёрнутая «заполнялка»: доминанта, символический предмет, статус героя, объектив, свет с причиной. Отметка **«говорит в кадре»**: тогда фото и видео строятся под липсинк (голова почти неподвижна, рот виден, мягкий свет). **Вкладки:** Фото · Видео · Звук. **Дорожка внизу** — соседние кадры сцены, чтобы сверять внешность, свет и направление взгляда.

**Фото:**
- В центре крупно просматриваемый вариант, под ним лента вариантов только этого кадра.
- Внизу — поле промпта, модель и кнопка «Сгенерировать · $0.04».
- Шторка «Что уйдёт в запрос»: миниатюры утверждённых материалов (лицо героя, образ, фон места, ракурс), отдельно — список «не хватает» (из `missing_approved`). Строка «Сохранится в: Пилот › Сцена 06 › Кадр 03».
- У варианта действие «Утвердить для кадра»; утверждённое фото становится опорой для видео.
- Уже есть: `CreateScreen.tsx`, `GenerationReview.tsx`, `context()`; проект кадра открывается через `open-project`.

**Видео:**
- Опора — утверждённое фото. Без него вкладка подсказывает: «сначала утверди фото».
- Поле движения (действие, игра, камера), модель, длительность, цена на кнопке.

## 7б. Формула кадра (сборка промпта)

Владелец заполняет 0–1, при желании выбирает 3–5; остальное студия собирает сама и пишет связным текстом, а не склейкой ярлыков (`prompt_rules.py`). Порядок совпадает с официальными профилями GPT Image и Nano Banana (`prompt_profiles.json`).

| № | Блок | Откуда |
| --- | --- | --- |
| 0 | Смысл кадра одним предложением | карточка кадра |
| 1 | Герой и действие: одна строка-якорь («Грэм с Image 1, та же кепка») + что делает и чувствует; внешность словами не расписываем | карточка кадра + пакет героя |
| 2 | Место: что изменилось в сцене (время, погода, люди, предметы) и что видно в этом плане; архитектуру словами заново не описываем | сцена + утверждённый фон |
| 3 | План и композиция: крупность через содержимое («лицо на весь кадр»), ракурс, где герой; в машине — всегда где камера | меню `cameraFrameCatalog` |
| 4 | Свет с причиной | из кнопок сцены; меню — ручная замена |
| 5 | Оптика — только проверенные фразы, описывающие видимый эффект (`LENS_PROMPT_TESTS_2026-10-17.md`); марки камер и «film grain» не пишем | меню, по желанию |
| 6 | Стиль — неизменный блок | паспорт проекта + эталон стиля |
| 7 | Роли референсов (Image 1 — лицо, Image 3 — место) | шторка «Что уйдёт в запрос» |
| 8 | Ограничения утверждениями («сохрани лицо и кепку как на Image 1») | паспорт: «Запрещено» |

Формат и разрешение — настройки запуска, не текст. Отдельного «Negative prompt» для GPT Image и Nano Banana нет: такой текст модель читает как обычные слова.

## 7в. Формула видео (картинка → видео)

Видео делается **только от утверждённого фото кадра** (уже обязательно в коде, `video_anchor`). Формат видео = формат фото. Промпт описывает **только то, что меняется**, картинку не пересказывает (`VIDEO_RULES`).

| № | Блок | Откуда |
| --- | --- | --- |
| 0 | Событие кадра — то же предложение, что у фото | карточка кадра |
| 1 | Роли референсов: Image 1 — первый кадр (утверждённое фото), дальше — герой, машина | автоматически |
| 2 | **Действие героя по времени**: начало → главное → финал; одна видимая перемена (взгляд, решение, реакция) и время её прочитать; кто говорит | вы, 1–2 строки |
| 3 | **Камера**: один мотив с причиной — наезд (к эмоции), отъезд (масштаб), сопровождение (действие), раскрытие (новое) или неподвижная; скорость и амплитуда; в машине — где камера | меню `camera_movements.py` |
| 4 | **Движение среды** (бывшее «атмосферное»): 1–2 живые детали — пар, снег, фары на фоне, мигающий фонарь, пейзаж за окном машины | автоматически по сцене + правка |
| 5 | **Пластика** — как двигаются персонажи в этом проекте; поле паспорта (для мульта: ясные позы, читаемые лица, естественный вес, без суеты) | паспорт проекта |
| 6 | **Ограничения** — короткий постоянный хвост из паспорта + специфичное для кадра: лицо и кепка как на Image 1; машина: четыре круглые фары, шашечки; время суток и свет не меняются; новые люди не появляются; обычная земная физика; без морфинга и мерцания | паспорт + кадр |

Настройки (длительность, разрешение, seed) — не в тексте.

**Правила:**
- одно главное действие и одно движение камеры на генерацию; диалог за рулём — чаще неподвижная камера;
- длина генерации 4–6 с; длиннее — больше дрейф лица и машины. Сцена 12 с собирается из 2–3 кадров;
- **финальная поза = стык со следующим кадром**: последний кадр клипа можно сохранить как старт следующего (`clip_chain.py`, `POST /api/library/{id}/last-frame`) — для непрерывного действия внутри сцены;
- сначала дешёвый черновик (480p), понравилось — финал в высоком качестве (Seedance 2.5 умеет черновик → финал по `draft_task_id`);
- звук видеомодели нам не нужен (голос и шумы делаем отдельно), но у MiniMax он входит в цену;
- кнопки «Что не так?» у дубля: «лицо меняется», «машина плывёт», «камера дёргается», «слишком много движения» — добавляют нужное ограничение и запускают повтор через подтверждение цены.

## 7а. Как референсы попадают в модель

Модель ничего не «помнит»: в каждый запрос прикладываются картинки и текст, где каждая подписана ролью — «Image 1 — лицо Грэма анфас: идентичность», «Image 2 — Грэм в полный рост: костюм и пропорции», «Image 3 — фон двора на Немиге, ночь: геометрия места». Студия **не шлёт весь пакет из 8**: под каждый кадр выбирает 2–4 нужных вида (крупный план → лицо в нужном повороте; общий → полный рост с нужной стороны) плюс фон места. Выбор виден в шторке «Что уйдёт в запрос» и меняется вручную.

| Модель | Как передаём сейчас | Состояние |
| --- | --- | --- |
| Nano Banana 2.1 | до 10 картинок по публичным ссылкам (`image_urls`), подписи в тексте промпта | с референсами вживую **не проверена** |
| GPT Image 2.5 через API студии | референсы **заблокированы** до проверки эндпоинта правок (`adapters.build_gpt_image`) | нужно подключить и проверить |
| GPT Image через ChatGPT (ручной маршрут) | картинки прикладываются в чат, подписи те же | работает вручную |

**Нужен короткий живой тест** (по разрешению владельца, до $1): для Nano Banana и GPT Image сравнить три способа — (А) одна картинка-лист со всеми 8 видами, (Б) 2–3 отдельных вида, (В) только лицо анфас. Критерий: узнаётся ли Грэм, не копирует ли модель раскладку листа, сохраняется ли костюм. Результат закрепить в правилах каждой модели (`model_catalog.py`, скиллы).

## 8. Расходы

- Сумма в шапке всегда с масштабом текущего места: кадр, сцена, серия или проект. Дневной лимит действует всегда.
- Сводки объединяют задания по номеру, поэтому одно задание учитывается один раз на любом уровне. Создание героя или фона учтено один раз на проекте; использование по ссылке денег не стоит.
- Отдельно показываются оценка, подтверждённое списание, резерв и неизвестный исход. Неизвестный исход автоматически не повторяется. API-эквивалент бесплатного маршрута — отдельной строкой, в итог не входит.
- Уже есть: серия (`series_economics.py`). Нужно сделать: проект, сцену и кадр — новыми чтениями поверх тех же записей.
