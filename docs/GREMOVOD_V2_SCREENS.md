# ГремоВОД v2 — логика экранов

Дата: 24.10.2026. Ветка `claude/gremovod-v2`. Статус: ТЗ на согласование владельцем. По нему уже сделана только серверная часть мира (коммит `f4e5110`).

ГремоВОД v2 — новая оболочка в одном окне поверх прежнего сервера и базы. Делаем **мультфильм**: простой объёмный мульт-стиль, архитектура Минска по реальным фото — место должно узнаваться, суперреалистичная чёткость не нужна. Чем меньше сложных элементов, тем проще генерация. Цель — полная серия: фото → шоты → кадры → сцены → серия → звук → комплект для CapCut. Сначала десктоп, телефон — позже, как пульт.

**Студия не привязана к ГремоВОДу.** Уровни, состояния, отбор референсов, формулы и расходы — общие для любого проекта. Всё, что делает ГремоВОД ГремоВОДом (стиль, мир, «Запрещено», слои), лежит в **паспорте проекта** и меняется без кода. Следующим проектом может быть другой мультфильм или реалистичное кино: создаём проект, выбираем режим, заполняем паспорт.

## 1. Структура и термины (решение владельца 24.10.2026)

```
Сериал (проект ГремоВОД)
└─ Серия            ≈ 4 мин, много сцен
   └─ Сцена         несколько кадров
      └─ Кадр       6–12 с, черновая склейка нескольких шотов
         └─ Шот     короткое видео из одного фото (дубли, в кадр идёт один)
            └─ Фото генерация картинки, варианты, доработка
```

Снизу вверх: **фото → шот → кадр → сцена → серия → сериал**. Сбоку — **Мир** (общие герои, места, реквизит, паспорт).

- **Фото** — основа всего: картинка (Nano Banana, GPT Image и др.), её варианты и «Допилить». Генерацию картинки называем только «фото».
- **Шот** — короткое видео (обычно 4–6 с), сгенерированное **из одного утверждённого фото**. У шота дубли; выбранный дубль можно подрезать (начало/конец).
- **Кадр** — 6–12 с, собирается **из нескольких шотов** простым редактором в студии: порядок, подрезка, склейка. Пример — кадр № 1: (1) Грэм подходит к машине → (2) общий план города → (3) крупно его лицо → (4) машина сзади, дым из трубы: 4 фото → 4 шота → 1 кадр. Кадр может быть и визуалом без героев: проезды, пролёты над едущей машиной под музыку.
- **Сцена** — из кадров; **серия** — из сцен; **сериал** — из серий.
- Финальный монтаж серии — в CapCut/DaVinci; редактор студии — только черновая сборка кадра (нарезать, расставить, склеить), без эффектов. Склейка — локально через ffmpeg (уже используется в `clip_chain.py`), бесплатно.
- Масштаб — ориентир: серия ≈ 4 мин; число сцен, кадров и шотов свободное. Короткие версии (Shorts) пока не делаем — и слово «шортс» для шота не используем.

**Правило слова «кадр».** В ГремоВОДе **кадр — только структурная часть сцены 6–12 с** из нескольких шотов. Всё, что про содержимое картинки («в кадре свет», «что видно в кадре», «экспозиция кадра»), относится к **фото** или **шоту**:
- в интерфейсе, подсказках и промптах студии для содержимого картинки пишем «на фото», «в шоте», «в изображении», а не «в кадре»;
- если владелец или помощник говорит «кадр» и по смыслу непонятно, о чём речь, — переспросить одной строкой: «Это про кадр сцены (6–12 с) или про фото/шот?», и только потом менять;
- обиходное «в кадре» в речи владельца по умолчанию понимается как «на фото» (то, что видно на картинке), если рядом нет номера кадра или слов «кадр сцены».

Слова интерфейса: проект, серия, сцена, кадр, шот, фото, место, вариант, герой, образ, дубль. Слов «эпизод» и «ролик» в интерфейсе нет; в коде сцена остаётся `episode`, кадр — `frame`.

## 2. Общие правила оболочки

| Зона | Правило |
| --- | --- |
| Шапка | ◆ ГремоВОД и путь с реальными названиями («ГремоВОД › Пилот › Сцена 06 › Кадр 03 › Шот 2»); каждое звено ведёт на свой уровень. Справа — сумма с масштабом («Сцена 06 · $3.10») и счётчик очереди; оба открывают шторку. |
| Левая панель | Одна на всех уровнях: **Мир** (Герои, Места, Реквизит, Паспорт), **Серии** (текущая раскрыта до сцен), **Фото** (раздел с главного экрана), **Библиотека** (Без привязки, Пробы). Внизу свёрнуты «Инструменты» и «Настройки». |
| Центр | Основную площадь занимает рабочий материал. Вкладки — только этапы текущего уровня. |
| Шторка справа | Открывается по кнопке, постоянно не висит: «Что уйдёт в запрос», «Допилить», свойства, расходы, очередь (`Dock.tsx`). |
| Дорожка внизу | У сцены — её кадры; у кадра — его шоты; в «Сборке» серии — вся серия. Сворачивается. |
| Текст | Ни одно название не повторяется на экране дважды. Пояснения — за «И». На экране одно главное действие; редкие — в «⋯». |
| Адрес | У каждого места свой адрес; кнопка «Назад» в браузере поднимает на уровень выше. |
| Деньги | Навигация, восстановление и просмотр ничего не запускают. Цена любого платного запуска считается заранее и видна на кнопке. Подтверждение — только для дорогих запусков (§16). |

## 3. Состояния — одинаковые на всех экранах

Готовность считается только по данным, никогда — по посещённым экранам.

| Объект | Состояния | Откуда берётся |
| --- | --- | --- |
| Фото | нет → есть варианты → **утверждено** | файлы шота, `selected_image_file_id` |
| Шот | нет → идёт → есть дубли → **дубль выбран** → **принят** (+ подрезка) | файлы шота, `selected_video_file_id`; «принят» — отметка владельца после просмотра |
| Кадр | **собран** (склейка есть) → **готов** = все шоты приняты + кадр собран + реплики озвучены | вычисляется |
| Звук кадра | реплик нет / реплики без файла / **озвучено** | `frame_sound_cues` |
| Сцена | **готова** = все кадры готовы, назначены место и герои | вычисляется |
| Серия | **к выгрузке** = все сцены готовы; **проверена в CapCut** — отметка владельца после импорта | вычисляется + отметка |
| Материал мира | загружен → **утверждён** (основной) → в архиве (бывший основной) | `selected_image_file_id` узла, у героя — `working_asset_id` |
| Герой | **готов** = утверждён пакет из 8 ракурсов и назначен голос | слоты пакета героя |
| Место | **готово** = утверждён основной фон; ракурсы пакета — по мере надобности | слоты пакета места |
| Оценка сцены | 7 фильтров по 0–2 (§7), сцена смотрится на фоне всей концепции | отметка владельца |

Пока отметки «принят» нет, интерфейс пишет «дубль выбран», а не «готово».

## 4. Проект — главная

**Зачем:** понять, где остановился, и вернуться туда одним нажатием.

**Видно:**
- большая кнопка **«Продолжить работу»** с точкой и временем («Пилот › Сцена 06 › Кадр 03 › Шот 2 · Фото · вчера») и меткой «есть черновик», если он есть;
- серии: номер, название, число сцен, хронометраж по плану и по факту, «кадров готово N из M», сколько потрачено; кнопка «+ серия»;
- вход в раздел **«Фото»** (пробы и отдельные картинки);
- одна строка пропусков по миру («у Грэма нет голоса · 3 сцены без места»).

**Не показываем:** общую ленту материалов, конвейер этапов, круги бюджета.

**Главное действие:** «Продолжить работу».

**Как работает «Продолжить работу»:**
- Точка хранится на сервере (таблица `workspace_cursor`): серия, сцена, кадр, шот, этап, просматриваемый вариант. Записывается только при переходах внутри серий; Мир, Библиотека, Расходы и Настройки её не меняют.
- Восстановление не меняет выбранные фото и дубли: просматриваемый вариант хранится отдельно от выбранного.
- Если кадр или шот в архиве или удалён, открывается ближайший доступный уровень выше с объяснением («Кадр 03 в архиве — открыта сцена 06»). Соседний не подставляется, черновик не удаляется.
- Черновики текстов хранятся в браузере, как сейчас, с меткой «не сохранено»; при уходе студия спрашивает «сохранить или отбросить».

## 5. Мир

**Зачем:** один источник героев, мест, реквизита и стиля для всех серий. Отсюда в запрос уходит только утверждённое. Карточки Мира работают уже на уровне фото.

**Слева — дерево:**
```
Герои
  Грэм
    Зима            (образ)
    Карнавал        (свой образ)
  Массовка
Транспорт
  Шестёрка
Места
  Минск
    Немига
      Двор на Немиге
        Ночь        (вариант)
        Зима        (вариант)
Реквизит
Паспорт
Без привязки  26
```

**В центре — папка выбранного узла:**
- заголовок с типом («Ночь · вариант места „Двор на Немиге“»);
- два фильтра: **Референсы** и **Все изображения**; утверждённое помечено ✓ и стоит первым;
- под галереей одна строка: что узел берёт у родителя («Геометрия: фон двора ✓» или «Лицо: основной образ Грэма ✓») и «Где используется: Пилот › Сцена 06, 07».

**Действия:**
- «Загрузить» — с компьютера или перетаскиванием файлов, в том числе из `!GREM TAXI`;
- у картинки — «Сделать утверждённым», в «⋯» — «В корзину» и «Перенести»;
- в дереве — «+ место», «+ вариант» (только у места), «+ образ» (только у героя).

**Реальные фото** (места, люди) — отдельная скрытая папка `Real Reference` у узла: загружаются и хранятся, но **нигде в интерфейсе не показываются** — ни в галереях, ни в «Что уйдёт в запрос», ни в «Без привязки». Видит их лишь владелец через «⋯ → Исходные фото»; помощники не видят никогда. Сервер не отдаёт их в запрос фото и не даёт сделать их утверждёнными. Позже — в меню «Перегенерировать референс» их можно будет приложить к запросу GPT Image / Nano Banana. **Пока не используем:** перегенерация идёт от наших стилизованных референсов, стиль уже задан ими.

### 5.1. Паспорт проекта

Общая основа каждого промпта. Принадлежит проекту (у каждого проекта свой), читается при каждом запросе, в шот не копируется.

- **Режим** — заготовка, с которой начинается паспорт: «3D-мульт», «реалистичное кино» и др. Режим заполняет уровень стилизации, блок стиля, базовый список «Запрещено» и набор осей лестницы вариантов (§10.3); дальше всё правится вручную. Библиотека режимов общая для всех проектов.
- **Эталон стиля** — одна утверждённая картинка, задающая отрисовку. У ГремоВОДа пока не выбран: владелец делает пробные фото, выбирает лучшее — «Сделать эталоном стиля». До выбора паспорт помечен «стиль не утверждён».
- **Поля:** место и время; главная идея мира; **правило мира** (одна строка, §14); уровень стилизации; архитектура (для ГремоВОДа — реальный Минск по фото, узнаваемо, без лишних деталей); материалы и фактуры (как упрощаются поверхности); палитра; логика света («свет с причиной»); настроение; камера; **пластика** — как двигаются персонажи (для мульта: ясные позы, читаемые лица, естественный вес, без суеты; микро-игра в разговорах); **Запрещено** (единый список проекта; в запрос уходит утверждениями, а не «no …»).
- **Палитра и время суток в паспорте не фиксируются.** Прежние значения «баклажан, янтарь, ночной Минск» отменены владельцем.
- **Надписи разрешены:** точный короткий текст пишется в промпте в кавычках; сложные и «красивые» надписи — в монтаже.
- **Слои** — описываются в паспорте, включаются у сцены: «воспоминание» и «фантазия». Для ГремоВОДа «Воспоминание 2014» — более старый, менее яркий, ближе к ч/б, с шумом. Детали эпохи (машины, телефоны, вывески 2014) идут в промпт; сам вид «старой записи» лучше накладывать фильтром в монтаже, а не просить у генератора: дешевле, одинаково на всех шотах, отменяется.

### 5.2. Герои и образы

**Карточка героя:** описание внешности, голос (сервис, голос, пример), образы и **обязательный пакет из 8 ракурсов**: лицо анфас, 3/4 слева, 3/4 справа, профиль; полный рост спереди, сзади, слева, справа. Пока пакет не утверждён, герой не «готов» и сцена показывает это как пропуск. Генерация пакета — существующий `SheetPanel`/`sheetShots.ts` (сейчас там другой набор: эмоции вместо видов сзади и сбоку — привести к 8 видам).

**Образы появляются из сценария.** Основной пакет героя один на весь сериал и не меняется. Если сцене нужен «Молодой Грэм» или «Грэм зимой», а такого образа нет — «Образа нет — создать из основного пакета?». Образ делается **из основного пакета** и ложится подпапкой героя со своим пакетом из 8 ракурсов:
- **меняет внешность** («Молодой Грэм», «Старый Грэм») — лицо и фигура берутся из пакета образа;
- **только одежда** («Зима», «Новый год») — лицо всегда из основного пакета, из образа — одежда. Это значение по умолчанию;
- **«+ Свой образ»** — в карточке героя: вписываете описание («бразильский карнавал») → «Применить» → цена на кнопке → студия генерирует такой же пакет из 8 ракурсов **из основного пакета**, сама называет подпапку («Карнавал») и привязывает её к герою. Вид по умолчанию — «только одежда».

**Образ в работе:** у героя в составе сцены, кадра или шота — выпадающий список его образов («Основной», «Зима», «Карнавал»…). Выбор ниже по уровню действует только там (например, «Сцена 3 › Кадр 5 › Шот 2: Грэм представляет себя на карнавале»); остальное наследуется сверху.

**Главные герои и массовка.** Сначала утверждаются пакеты топ-5 главных героев. Затем — **массовка**: отдельная группа в «Героях», простые люди в той же стилистике, без особой детализации, с настроениями (грустные, весёлые и т.д.). Массовка уходит в запрос с ролью «люди на фоне» и никогда не подменяет главного героя.

**Машина — отдельный герой.** «Шестёрка» — вымышленная машина по мотивам ВАЗ-2106; владелец моделирует её в Blender, чтобы она была одинаковой во всех шотах. Своя карточка (группа «Транспорт»), свой **пакет ракурсов**: спереди, сзади, слева, справа, две 3/4, салон с места водителя, салон с места пассажира. Рендеры из Blender загружаются как референсы и утверждаются как пакет.

### 5.3. Места и варианты

**Пакет места** (по желанию, слоты): общий, средний, деталь, обратная точка, с героем внутри. Ночная или зимняя версия — не ракурс, а **вариант** места.

**Время суток и погода** (кнопки сцены, §7; кадр и шот могут переопределить):
- **По умолчанию — день:** основной фон места дневной, большинство действия идёт днём.
- **Утро, вечер, пасмурно, дождь** — описываются словами поверх дневного фона, отдельный вариант не нужен.
- **Ночь, зима** и другие сильные перемены — **вариант места**. Нет варианта — «Варианта „Ночь“ нет — создать?», дневной фон молча не подставляется.
- Для разработки это не первоочередное: сначала дневной фон.

**Реквизит** — предметы, которые должны быть одинаковыми во всех сценах (самоделка серии, ключи Грэма): своя карточка с утверждённым изображением, как у места.

**Без привязки:** старые файлы, которым нет места в дереве. У каждого видно, откуда он: дата, промпт, модель. Действие — «Перенести в…» с выбором узла. Автоматически ничего не раскладывается.

**Правила Мира:**
- место задаёт геометрию, вариант — тот же план с другим светом или сезоном; вариант внутри варианта создать нельзя;
- герой — одна карточка; герой и его образ не могут стоять в одной сцене одновременно;
- если у варианта нет утверждённого фона, сцена показывает «варианта Ночь ещё нет» и не подменяет его похожим;
- фото шота само в мир не попадает; «В Мир» — отдельное действие.

**Готово:** у каждого используемого героя есть утверждённый образ и голос, у каждого используемого места или варианта — утверждённый фон.

**Уже есть в коде:** дерево мест, варианты, образы и отбор утверждённого (`production_folders.py`, `production_entities.py`, `test_world_tree.py`); загрузка в папку узла; галереи героев (`CharactersScreen`, `CharacterReferences`) и мест (`LocationsTab`). **Нужно сделать:** экран дерева, «Без привязки», «Где используется», «Реквизит», «Транспорт», «Массовка», отметку образа «меняет внешность / только одежда», скрытую папку `Real Reference`, паспорт, читаемый при каждом запросе.

## 6. Серия

**Зачем:** история серии и сборка всей серии из готовых кадров.

**Три режима центра:**

1. **История** — сюжетная доска.
   - Исходный сценарий сохраняется как есть.
   - Карточки сцен: название, кратко, герои, место, **чего хочет / что мешает**, что меняется; порядок.
   - Необязательные поля серии: **символ серии** (ссылка на реквизит) и **сквозные детали** (§14).
   - ИИ предлагает разбиение по кнопке; карточки принимаете вы.
   - «Применить к сценам» — отдельное действие после просмотра изменений.
   - Уже есть: `StoryPlanBoard.tsx`, `story_plan.py`.
2. **Сцены** — сетка сцен по порядку: номер, название, место, герои, миниатюры кадров, состояние («кадров готово 3/5»), план и факт по времени. Нажатие открывает сцену. Уже есть: `ProductionStoryboard.tsx`, `storyboard.py`.
3. **Сборка** — дорожка серии.
   - Собранные кадры по порядку сцен, реальные длительности, реплики; сквозная музыка и атмосфера отдельными дорожками.
   - Список «чего не хватает».
   - Кнопка «Собрать комплект для CapCut», после импорта — отметка «проверено в CapCut».
   - Уже есть: `edit_list.py`, `EditListPanel.tsx`, `MotionPanel.tsx`. Нужно сделать: кадры из шотов, подрезку, отметку проверки.

**Главное действие** зависит от режима: «Применить к сценам», вход в сцену или «Собрать комплект».

**Следующий шаг:**
- нет сцен → «Разбить сценарий на сцены»;
- у сцены нет места или героев → указать;
- есть незаконченные кадры → к первому такому.

**Хронометраж:** план — из карточек сцен, факт — сумма длительностей собранных кадров (с учётом подрезки). Число сцен и их длина не фиксированы.

**Готово:** все сцены готовы, комплект собран, импорт в CapCut проверен владельцем.

## 7. Сцена

**Зачем:** поставить сцену и довести её кадры до готовности.

**Видно:**
- сверху — название, место (с вариантом) и герои сцены с кнопкой «Изменить»; две строки смысла из карточки истории: **«Чего хочет / что мешает»** («Прохор хочет сала, рынок закрывается») и **«Что меняется»** (было → стало);
- **кнопки сцены** (по умолчанию для всех её кадров и шотов): **время суток**, **погода**, **слой** (основной / воспоминание / фантазия). Свет по умолчанию следует из времени суток и источников места;
- в центре — кадры сцены крупными миниатюрами (утверждённое фото первого шота); под каждой — «шоты 3/4 ✓ · собран · звук ✓» и кнопка «+ кадр»;
- дорожка внизу — кадры по порядку с длительностями и реплики под ними; на стыках кадров — **тип стыка** (§14) и значок сверки (§15).

**Главное действие:** открыть кадр, которому нужен следующий шаг («Дальше: кадр 03 — выбрать дубль шота 2»).

**Следующий шаг:**
- нет места → выбрать место;
- у места нет утверждённого фона → перейти в Мир к этому месту;
- нет кадров → «Добавить кадры»;
- дальше — первый незаконченный кадр.

**Правила:**
- кадры и шоты наследуют место, героев и кнопки сцены; ниже можно заменить ракурс места или образ героя, но не само место без явного действия;
- порядок кадров в сцене и шотов в кадре — монтажный; очередь производства может быть другой и этот порядок не меняет.

**Оценка сцены — 7 фильтров** (по 0–2, итог 0–14: 0–6 переделать, 7–10 рабочая, 11–14 сильная). Смотрим сцену на месте, насколько она выбивается из общей концепции:
1. Смысл сцены в одном предложении. 2. Взгляд сразу на главном. 3. Ритм: события на акцентах. 4. Крупности чередуются осознанно. 5. Пластика: движения естественные, без «плывущих» тел. 6. Консистентность: герой, место и стиль стабильны. 7. Детали второго плана, которые хочется пересмотреть.
Слабый пункт ведёт к нужному кадру или шоту.

**Уже есть:** состав и место сцены (`SceneCast.tsx`), карточка сцены (`ProductionEntityEditor.tsx`), состояния (`frameStatus.ts`).

## 8. Кадр

**Зачем:** собрать 6–12 секунд истории из нескольких шотов и озвучить реплики.

**Видно:**
- сверху — **смысл кадра одним предложением** («Грэм решает подвезти звезду»); если не формулируется — кадр переделать;
- в центре — шоты кадра по порядку миниатюрами (утверждённое фото шота) с состоянием «фото ✓ / дубль ✓»; кнопка «+ шот»; нажатие открывает шот;
- **черновая сборка**: порядок шотов (перетаскиванием), подрезка выбранного дубля (начало/конец), «Собрать кадр» — склейка ffmpeg, предпросмотр; без эффектов и переходов;
- **звук кадра**: реплики (кто говорит, в кадре или за кадром, текст, голос героя), «Озвучить · $…», «Прослушать», «Заменить»; шумы кадра; сквозная музыка — на серии. Уже есть: `FrameSoundTab.tsx`, `sound.py`, ElevenLabs и Fish Audio;
- дорожка внизу — шоты с длительностями, под ними реплики.

**Главное действие:** «Дальше: шот 2 — выбрать дубль» или «Собрать кадр».

**Готово:** все шоты приняты, кадр собран, реплики озвучены. Вертикальная версия 9:16 — позже.

## 9. Шот

**Зачем:** одно короткое видео (4–6 с) из одного утверждённого фото.

**Вкладки:** **Фото** (§10) · **Видео**.

**Сверху** — действие шота одной строкой («Грэм подходит к машине слева»); отметка **«говорит в шоте»** — тогда фото и видео строятся под липсинк (голова почти неподвижна, рот виден, мягкий свет).

**Видео:**
- опора — утверждённое фото шота; без него вкладка подсказывает «сначала утверди фото»;
- поле действия по времени, меню камеры, модель, длительность, цена на кнопке;
- лента дублей шота: «Выбрать», после просмотра — «Принять»; подрезка — в кадре;
- кнопки «Что не так?» у дубля: «лицо меняется», «машина плывёт», «камера дёргается», «слишком много движения» — добавляют нужное ограничение и запускают повтор;
- уже есть: `VideoScreen.tsx`, `video_anchor`, выбор дубля в карточке.

**Формула видео** (картинка → видео). Промпт описывает **только то, что меняется**, фото не пересказывает (`VIDEO_RULES`). Формат видео = формат фото.

| № | Блок | Откуда |
| --- | --- | --- |
| 0 | Действие шота — одна строка | шот |
| 1 | Роли референсов: Image 1 — первый кадр (утверждённое фото), дальше — герой, машина | автоматически |
| 2 | **Действие героя по времени**: начало → главное → финал; одна видимая перемена (взгляд, решение, реакция) и время её прочитать; кто говорит; направление движения («подходит к машине слева») | вы, 1–2 строки |
| 3 | **Камера**: один мотив с причиной — наезд (к эмоции), отъезд (масштаб), сопровождение (действие), раскрытие (новое) или неподвижная; скорость и амплитуда; в машине — где камера | одна кнопка из меню `camera_movements.py` |
| 4 | **Движение среды**: 1–2 живые детали — пар, снег, фары на фоне, мигающий фонарь, пейзаж за окном машины. Свет заново не описываем: он уже в фото | автоматически по сцене + правка |
| 5 | **Пластика** проекта | паспорт |
| 6 | **Ограничения** — короткий хвост из паспорта + специфичное для шота: лицо и кепка как на Image 1; машина: четыре круглые фары, шашечки; тот же свет и время суток; новые люди не появляются; обычная земная физика; без морфинга и мерцания | паспорт + шот |

Настройки (длительность, разрешение, seed) — не в тексте.

**Правила видео:**
- одно главное действие и одно движение камеры на шот; разговор за рулём — чаще неподвижная камера;
- **микро-игра по умолчанию** для разговорных шотов: дыхание, лёгкое движение головы, одно моргание, перемена выражения на реплике;
- оживлять только нужное (дым, фары, волосы, край одежды) — у моделей с «кистью движения» (Motion Brush у Kling) это отдельная настройка; Kling пока не включён;
- длина шота 4–6 с; длиннее — больше дрейф лица и машины;
- **финальная поза = стык со следующим шотом**: последний кадр видео можно сохранить как старт следующего (`clip_chain.py`, `POST /api/library/{id}/last-frame`) — для непрерывного действия;
- сначала дешёвый черновик (480p), понравилось — финал в высоком качестве (Seedance 2.5 умеет черновик → финал по `draft_task_id`);
- звук видеомодели не используем (голос и шумы делаем отдельно); у MiniMax он входит в цену, при выгрузке не берём.

## 10. Фото (нижний уровень)

**Зачем:** генерация картинки, её варианты и доработка. Сейчас разрабатываем этот уровень первым.

**Вход:** раздел **«Фото» с главного экрана** и вкладка «Фото» внутри шота.

**Куда сохраняется:** фото, сделанное в шоте, принадлежит шоту. Фото из раздела «Фото» — в **«Пробы»** проекта (видно, что без привязки), с действием «Перенести в шот…» или «В Мир…». Перед генерацией — строка «Сохранится в: Пилот › Сцена 06 › Кадр 03 › Шот 2» или «в Пробы». В общую кучу ничего не падает.

**Карточки Мира прямо в фото:** одна карточка героя и одна карточка места со своими функциями — у героя образ и одежда, у места время суток, погода и вариант. Выбор у каждого свой.

**Экран:**
- в центре крупно просматриваемый вариант, под ним лента вариантов только этого фото;
- внизу — поле промпта, кнопки (свет, крупность, ракурс, композиция; объектив — свёрнуто), модель и «Сгенерировать · $0.04»;
- «заполнялка» (свёрнута): доминанта, символический предмет, статус героя, свет с причиной;
- шторка «Что уйдёт в запрос»: миниатюры утверждённых материалов (лицо героя, образ, фон места, ракурс) и список «не хватает» (из `missing_approved`);
- у варианта: «Утвердить для шота», кнопки-направления (§10.3) и скрытая «✎ Допилить» (§10.4);
- уже есть: `CreateScreen.tsx`, `GenerationReview.tsx`, `context()`.

### 10.1. Формула фото

Владелец пишет 0–1, при желании выбирает 3–5; остальное студия собирает сама и пишет связным текстом, а не склейкой ярлыков (`prompt_rules.py`). Порядок совпадает с официальными профилями GPT Image и Nano Banana (`prompt_profiles.json`).

| № | Блок | Откуда |
| --- | --- | --- |
| 0 | Смысл — действие шота одним предложением | шот |
| 1 | Герой и действие: одна строка-якорь («Грэм с Image 1, та же кепка») + что делает и чувствует; внешность словами не расписываем | шот + пакет героя |
| 2 | Место: что изменилось в сцене (время, погода, люди, предметы) и что видно в этом плане; архитектуру словами заново не описываем | сцена + утверждённый фон |
| 3 | План и композиция: крупность через содержимое («лицо на весь кадр»), ракурс, где герой; в машине — всегда где камера | кнопки `cameraFrameCatalog` |
| 4 | Свет с причиной | из кнопок сцены; кнопка — ручная замена |
| 5 | Оптика — только проверенные фразы, описывающие видимый эффект (`LENS_PROMPT_TESTS_2026-10-17.md`); марки камер и «film grain» не пишем | по желанию |
| 6 | Стиль — неизменный блок | паспорт + эталон стиля |
| 7 | Роли референсов (Image 1 — лицо, Image 3 — место) | «Что уйдёт в запрос» |
| 8 | Ограничения утверждениями («сохрани лицо и кепку как на Image 1») | паспорт: «Запрещено» |

Формат и разрешение — настройки запуска, не текст. Отдельного «Negative prompt» для GPT Image и Nano Banana нет: такой текст модель читает как обычные слова.

### 10.2. Путь промпта (решение владельца)

1. Кнопки (свет слева, крупность, наезд камеры и т.д.) добавляют **заранее отработанные английские фразы** из каталогов (`cameraFrameCatalog.ts`, `camera_movements.py`).
2. Перед отправкой **LLM переписывает собранный промпт под выбранную модель** — в том виде, который эта модель понимает лучше (профили `prompt_profiles.json`, скиллы `video-*`), не теряя смысла фраз и ролей референсов.
3. Владелец видит русскую сводку «что получится»; английский текст — по нажатию, с возможностью правки.
4. Качество переписывания проверяется на живых тестах: генерация → просмотр картинок → правка фраз и профилей (как проверка «таксист во дворе», `LENS_PROMPT_TESTS_2026-10-17.md`).

Переписывание (платный LLM, копейки) идёт без подтверждения; его цена добавляется к цене запуска на кнопке. Путь общий для фото и шота.

### 10.3. Лестница вариантов («Секрет реалистичного AI-видео»)

Из документа берём не промпты (они про фотореализм), а **способ работы**: базовый вариант → сдвиг по одной оси → доработка выбранного без потери основы.

1. **Базовый вариант** — по формуле фото, в 1–3 моделях.
2. **Кнопки-направления у варианта** — новый вариант, где меняется **одна ось**, остальное держится:

| Ось | Что меняется | Для ГремоВОДа |
| --- | --- | --- |
| Ближе | крупность: от среднего к крупному, эмоция в глазах | да |
| Глубже | три плана: передний (размытый) — герой — фон | да |
| Свет | мягче ↔ драматичнее, при той же причине света | да |
| Масштаб | эпичнее: шире, ниже камера, больше воздуха | да |
| Реализм | документальнее ↔ кинематографичнее, фактура кожи | **нет** у мульта; ось включает режим «реалистичное кино» |

Набор осей задаёт режим проекта. Варианты автоматически не генерируются — только по нажатию.

### 10.4. «Допилить»

Правка готового варианта через мини-чек-лист «Что не так?».

**Где:** на экране не висит. Маленькая кнопка **«✎ Допилить»** появляется в углу просматриваемого варианта при наведении (и есть в «⋯» у варианта в ленте). Нажатие открывает шторку справа — ту же, где «Что уйдёт в запрос».

```figure
┌──────────────────────────────────────────────────────────────────────┐
│ ГремоВОД › Пилот › Сцена 03 › Кадр 05 › Шот 2    Фото · Видео        │
├────────────────────────────────────────────┬─────────────────────────┤
│ ┌────────────────────────────────────────┐ │ ДОПИЛИТЬ ВАРИАНТ 3      │
│ │                                        │ │ ○ Исправить этот        │
│ │      просматриваемый вариант 3         │ │ ● Новый шот из этого    │
│ │                                        │ │ Что не так?             │
│ │                             ✎ Допилить │ │ ▸ Свет                  │
│ └────────────────────────────────────────┘ │ ▾ Камера                │
│ ▢1 ▢2 ■3 ▢4   варианты фото                │   [только глаза]        │
│ промпт...            Сгенерировать $0.04   │ ▸ Глубина               │
│                                            │ ▸ Атмосфера             │
│                                            │ ▸ Стиль и лицо          │
│                                            │ Хочу увидеть: щурится   │
│                                            │ Допилить · $0.04        │
└────────────────────────────────────────────┴─────────────────────────┘
```

**Два режима:**
- **«Исправить этот»** — правка самого варианта: результат — новый вариант того же фото с пометкой «доработка варианта 3».
- **«Новый шот из этого»** — производный план из готового фото с тем же героем, светом и местом: «камера ближе, только глаза, он прищуривается — задумал схитрить». Результат становится фото **нового шота сразу после текущего** в том же кадре. Это способ показать видимую перемену мысли отдельным планом.

**Чек-лист «Что не так?»** — пункты свёрнуты, раскрывается только нужный; выбранное превращается в отработанные английские фразы:

| Пункт | Вопрос | Варианты |
| --- | --- | --- |
| Свет | Откуда и какой? | источник: окно / фонарь / солнце / лампа салона / фары; сторона: слева / справа / сверху / сзади (контровой); мягче / жёстче |
| Камера | Как снято? | ближе / дальше / только глаза / только руки; выше / ниже / на уровне глаз; в машине — с места водителя / пассажира / через лобовое |
| Глубина | Есть ли планы? | добавить передний план (размытый) / размыть фон / убрать лишнее с заднего плана |
| Атмосфера | Не стерильный ли фон? | добавить воздух: дымка / пар / пыль / снежинки — или наоборот проще и чище (для мульта чаще «проще») |
| Стиль и лицо | Не уплыло ли? | ближе к эталону стиля; вернуть лицо героя (пакет героя вторым референсом); меньше пластика |
| **Очистить** | Шум, фрактальность, муар? | убрать зернистость, цифровой шум, фрактальные и повторяющиеся узоры, перешарп; три уровня (ниже), необязательное поле «где»: земля, деревья, фон, камни |
| Фактура кожи | — | только в режиме «реалистичное кино»; у мульта скрыт |
| Своё | Что хочу увидеть | одно поле: «щурится», «убери второго прохожего», «кепка краснее» |

**«Очистить» — тексты владельца** (источник: `убрать паттерн и шум.txt`, 24.10.2026). Нужен, когда генерация «перегрелась»: мелкая фрактальная структура, муар, зерно. По умолчанию — «Универсальный».
- **Простой** (с полем «где»): «Убери зернистость и шум с этого изображения. А также избавься от фрактальности в деталях: на {зоны}. Композицию и лицо не трогай.»
- **Универсальный**: «Изображение чрезмерно детализировано, из-за чего возникают фрактальные артефакты, муар и повторяющиеся узоры. Уменьши количество мелких деталей, упрости текстуры поверхностей, убери искусственную микродетализацию. Сделай изображение более гладким и естественным, сохранив композицию, внешность персонажей и художественный стиль.»
- **Подробный**: «Очисти загруженное изображение от визуальных артефактов генерации, сохранив его исходный вид. Удали зернистость, цифровой шум, фрактальные структуры, муар, повторяющиеся паттерны, искусственные текстуры и избыточную микродетализацию. Упрости чрезмерно сложные участки изображения. Замени хаотичные, повторяющиеся и неестественные текстуры на чистые, органичные поверхности с нерегулярным распределением деталей. Устрани искусственную резкость, пятнистость и эффект цифрового перешарпа. Сделай тональные переходы плавными, цвета чистыми, а текстуры естественными и визуально цельными. Сохрани необходимую детализацию, объём и фактуру материалов. Избегай чрезмерного сглаживания, размытия и пластикового эффекта. Строго сохрани исходную композицию, расположение объектов, внешность персонажей, пропорции, позы, освещение, цвета, перспективу и художественный стиль. Не добавляй новые объекты, не переосмысливай сцену и не увеличивай детализацию.»

Тексты хранятся как есть (каталог пресетов «Допилить»); перед отправкой LLM переписывает их под модель (§10.2). Совет «уровень размышления: Высокий» относится к ручному маршруту через ChatGPT; в API такой настройки нет.

Внизу шторки — сводка «Что изменится» и кнопка с ценой «Допилить · $0.04» (картинки без подтверждения, §16). После результата — «было / стало» и «Утвердить» или «Ещё раз».

**Правила:**
- исходник не перезаписывается;
- **не строить длинные цепочки**: после 2–3 доработок подряд — подсказка «качество может поплыть, вернитесь к исходному варианту» (так же в `world-lock.md`);
- работает в моделях, умеющих правку: Nano Banana (понимает «оставь всё, поменяй X») и GPT Image sunburst (пока заблокирован, нужна проверка, §11);
- в основе — существующий маршрут «Допилить» (`backend/refinement.py`: `source_asset_id` как `edit_target`, необязательная деталь-референс); отдельный экран «Допилить» уходит в эту шторку.

**Проверка перед генерацией** — тихий значок «5 вопросов» (`cinema-five-pillars`) плюс: есть ли у света причина; есть ли три плана (если нужны); не перегружено ли фото — для мульта лучше меньше элементов. «Фактура кожи» — только в режиме «реалистичное кино». Не запрет.

**Апскейл** — не шаг пайплайна: фото генерируются в 2K/4K. Необязательная кнопка для финала или по требованию клиента (`UpscaleButton`; модель `image-upscale` не включена и не проверена).

### 10.5. Расстановка на холсте (решение владельца 24.10.2026)

**Идея:** локация одна на фото, героев может быть два, три, четыре. Расстановка нужна, чтобы модель поняла, кто где стоит. Рисовать героев «как в жизни» на холсте не нужно: это схема из условных фигурок. Остальное владелец дописывает в промпте.

**Экран фото:**
- слева постоянные панели **«Герои»** и **«Локации»** (карточки + «＋» для быстрого создания: имя и референс, довести можно в «Мир»). Клик по герою добавляет его на холст и в строку «Выбрано», повторный клик убирает. Локация выбирается одна;
- в центре холст фиксированного размера (16:9), на нём фон локации и фигурки героев;
- **под холстом справа «＋ Допилить»** (§10.4). Первый набор пунктов: источник света, 3 плана, воздух (пространство и туман), фактура кожи. Остальные пункты и «Очистить» возвращаются позже;
- под холстом лента вариантов, строка **«Выбрано»**, поле «Что они делают», модель и «Сгенерировать».

**Правила расстановки:**
1. **Три колонки:** холст делится на «слева», «в центре», «справа». Фигурку перетаскивают, при отпускании она встаёт в колонку. Сетка точнее не нужна.
2. **План:** передний, средний, задний. Выбирается в строке «Выбрано»; размер и высота фигурки на холсте от него зависят.
3. **Поворот героя:** выбирается из обязательного пакета в 8 ракурсов (§5.2); выбор поворота выбирает картинку героя, которая уйдёт в запрос. Полный рост и взгляд в камеру по умолчанию.
4. **Номера Image N:** каждой фигурке соответствует номер референса. Герои идут по порядку (Image 1, Image 2…), локация получает следующий номер. Тот же номер виден на фигурке и в запросе.
5. **Слова в запрос:** позиция превращается в текст с номером картинки, например: «Грэм (Image 1, Основной): слева, средний план; Прохор (Image 2): в центре, передний план. Место (Image 3): Двор на Немиге, ночь». Текст виден в «Что уйдёт в запрос»; дальше он идёт по обычному пути промпта (§10.2).
6. Время суток, погода и вариант места (Ночь, Зима) выбираются в строке «Выбрано» у локации. Подмены варианта нет (§5.3).
7. Лимиты референсов на модель берутся из `model_catalog.py` (`ref_limits`). Если героев и места больше лимита, студия предупреждает до запуска.

**Этапы реализации:**
1. Холст, три колонки, план, номера Image N и слова в запросе. Работает на любой модели с референсами, ничего платного.
2. Выбор поворота из 8 ракурсов.
3. **Набросок расстановки как дополнительный референс** (локация с метками «Image 1», «Image 2» на нужных местах; позже склейка с вырезанными героями, для неё нужны прозрачные фоны). Включать только после платного теста, см. ниже.

**Платный тест (владелец разрешил позже, вместе с ним, до $1):** 3–4 расстановки на Nano Banana 2.1 и Seedream, с наброском и без него. Смотрим, насколько точно модель ставит героев. Сейчас референсы GPT Image заблокированы в `adapters.build_gpt_image`, а у Nano Banana не проверены вживую, поэтому начинать с Nano Banana или Seedream. В новой сессии разрешение спрашивать заново.

**Уточнения после просмотра макета (24.10.2026):**
- Отдельной строки «Выбрано» нет: она дублировала холст. Образ и план героя меняются по клику на фигурку (окошко: образ, план, «Убрать с кадра»). У места одна строка: вариант, время суток, погода.
- Время суток: день, утро, вечер (ночь и зима — вариант места, §5.3). Погода отдельно: ясно, пасмурно, дождь, снег. «Пасмурно» — погода, а не время.
- Кнопки «Что уйдёт в запрос» нет, она повторяла экран. Текст запроса виден по значку «И»; отдельно показывается только то, чего не хватает.
- После генерации готовое фото **заменяет** схему расстановки: имён и колонок на нём нет. Вернуться к схеме — кнопка «Расстановка»; смена героя, места, варианта или времени тоже возвращает схему.
- «Утвердить» есть только внутри шота. В «Пробах» утверждать не для чего: там «В шот…» и «В Мир…».

**Свет и камера на экране «Фото» (макет, 24.10.2026):** под холстом две кнопки с иконками.
- **«Свет»:** схема вида сверху, фигурка в центре, восемь точек вокруг (слева, спереди-слева … сзади), отдельно «сверху» и «снизу», характер (мягкий, жёсткий) и источник с причиной (окно, фонарь, солнце, лампа, фары). Положение уходит в промпт словами, например «soft front light from camera right, motivated by a window». Работает на любой модели.
- **«Камера»:** крупность и ракурс с иконками, рисунок объектива словами (широкий угол, нормальный, телевик), и «точные параметры»: фокусное (24–85 мм), диафрагма, камера (ARRI, плёнка, цифровая).
- **Блокировка под модель:** точные параметры включаются только там, где модель их понимает; недоступные кнопки гаснут, и пишется почему. Нельзя смешивать «камеру» (плёнка/цифра) и «объектив» (рисунок) с фокусным расстоянием (docs/CAMERA_OPTICS_PROPOSAL_2026-10-15.md).
- **Что известно по GPT Image 2.5** (книга `GPT-Image-2.5-promptbook.pdf` и `docs/official-prompts/openai-image-prompting.md`): «35mm film photograph, 50mm lens» — подсказка внешнего вида, а не точная физика; диафрагму гайд не разбирает; негатива-параметра нет, исключения пишутся текстом («no watermarks»); референсы нумеруются «image 1», «image 2», каждому дают роль; правки по одной с «change only X». Для остальных моделей данных нет: значения в макете условные, нужен тест (в `model_catalog.py` такой таблицы нет, завести рядом с `ref_limits`).
- **Выбор места и условий наверху (24.10.2026):** место, время суток, сезон и погода выбираются кнопками-выпадашками в одной строке с заголовком «Фото · пробы». Место можно не выбирать: пункт «Без локации (белый фон)» оставляет на холсте нейтральный светлый фон, в запросе «plain seamless white studio background», а меню времени, сезона и погоды прячутся. Так можно быстро посмотреть двух героев вместе. Слева остаются только герои.
- **Модель выбирается чипами под полем промпта** (GPT Image 2.5, Nano Banana 2.1, Seedream 5 Pro, Seedream 5 Lite, Qwen Image 2.1) до нажатия кнопки запуска: от неё зависит, как пишется промпт.
- **Кнопка «play» (LLM / txt):** жёлтый «ютубовский» play с подписью режима. Левый клик запускает, правый открывает меню «LLM — составить промпт» и «txt — отправить текст как есть». Режим LLM: все выбранные кнопки уходят самой дешёвой LLM (`gpt-5.6-luna`) по мастер-промпту под выбранную модель; результат показывается в окне «Готовый промпт» (две строки, по клику разворачивается), затем «Сгенерировать с этим промптом». Для GPT Image 2.5 промпт структурируется как Scene / Subject / Action / Camera and light / Constraints, с номерами Image N и ролями референсов; для Qwen — простые слова без технических терминов. LLM без галочки подтверждения, но через оценку цены и лимиты (`llm_guard`). Режим txt отправляет собранный из кнопок и поля текст как есть. План работ: TODO.md, пункты 5–6.
- **Дополнения 24.10.2026 (после просмотра макета):** карточка локации стоит в левой колонке над героями, того же размера, что карточки героев, и по клику открывает меню мест; герои «вшиты», кнопки правки на карточках нет, героя редактируют в «Мире». Чипы моделей стоят **над** полем промпта: сначала модель, потом текст; кнопка play справа от поля, видна всегда. Выбор модели подгружает её мастер-промпт (`docs/master-prompts/`, правила хранения в файле мастер-промпта, §1а), в окне «Готовый промпт» указана версия «без изменений». Новое в кнопках: «Главный в кадре ★» (доминанта) в окошке фигурки; типы света «рембрандт» и «золотой час»; ракурсы «заваленный» и «симметрия» с подсказками смысла (низкий — сила, верхний — уязвимость); диапазоны мм под словами объектива (14–24, 35–50, 85–100); «размытый передний план (капли, стекло)» в «3 плана».
- **Компоновка экрана «Фото» (уточнено владельцем 24.10.2026):** сверху над холстом, от его левого края, одна строка кнопок-выпадашек: место, время суток, сезон, погода. Слева только колонка героев. - **Кнопка LLM внутри поля промпта (24.10.2026):** жёлтый play стоит в правом нижнем углу самого поля ввода, подпись «LLM» (или «txt») крупно под ним. Рядом жёлтый «i»: в подсказке написано, какая LLM (gpt-5.6-luna), какой мастер-промпт и цена, и что **правый клик по кнопке переключает на отправку текста (txt)** и обратно. Меню правого клика открывается вверх.
- **«Править» = объединённые «Допилить» и «Исправить» (решение владельца 24.10.2026).** Кнопка «✎ Править» под холстом и карандаш рядом с корзиной на холсте открывают одну панель. Режим правки: параметры сцены (место, время, свет, камера, расстановка, модели) затемняются и в запрос **не идут**, на холсте плашка «Режим правки». Do not add new elements or text.» Для меток и области вторая картинка — копия с нанесёнными номерами («метки — подсказка, не рисовать их»).

У OpenAI API есть маска (картинка, где указана область замены, действует на первое изображение, работает как подсказка, не жёсткий запрет), но на PiAPI правки GPT Image не подключены и не проверены (`adapters.build_gpt_image`, планируется `gpt-image-2.5-sunburst`). У места: «Варианты» (＋ Ночь, ＋ Зима, свой), картинки фона, «★ Сделать утверждённым», «▶ Перерисовать в наш стиль»; без утверждённого фона предупреждение «подмены нет». - **Цепочка LLM → генерация (24.10.2026):** клик по LLM сразу отправляет запрос, без подтверждений (правило владельца для LLM). Появляется окно «Готовый промпт» (две строки, «развернуть и прочитать»), а слева от него такая же жёлтая кнопка «Генерировать». При наведении на кнопки LLM и «Генерировать» крупно показываются модель, формат, качество и цена (у LLM плюс «LLM ≈ $0.001»). «Сбросить промпт» убирает окно.
- **Модель = выпадающее меню** (то же оформление, что у остальных): клик по чипу выбирает модель и раскрывает меню по порядку: 1) формат кадра (16:9 и 9:16 всегда первые), 2) разрешение или качество, 3) цена, затем короткое описание модели. Выбранный чип показывает свёрнутую сводку «16:9 · 2K · $0.06». Отдельной кнопки размера нет.
- **Размер, качество и цена по модели (24.10.2026):** кнопка «▣ 2K · 16:9 · $0.06 ★» открывает меню с вариантами **по спецификации выбранной модели** (`model_catalog.py`: Nano Banana 1K/2K/4K, Seedream Lite 2K/3K, Seedream Pro 1K/2K, GPT Image — качество low/medium/high и размер), форматом кадра и ценой каждого варианта. Цены подтягиваются **в начале сессии**; источник: API провайдера, если он отдаёт цены, иначе фактические списания из истории заданий (`meta.usage.consume` в ответах), иначе оценка по документации (`price_basis`). Сейчас в коде цена одна на модель и «по документации», таблицы по разрешениям нет. **Рекомендация (★):** картинки идут в видео, поэтому берём самый большой размер, который стоит не больше ×1,5 от самого дешёвого в группе «от 2K» (1K $0.05 / 2K $0.06 → 2K; 2K $0.10 / 4K $0.50 → 2K по цене). В макете цены условные.
- **Удаление варианта (24.10.2026):** ленты вариантов под холстом только растут, поэтому при просмотре готового фото в правом верхнем углу холста бледная иконка корзины (темнеет при наведении). Нажатие убирает выбранный вариант из ленты **в корзину владельца** (мягкое удаление, 30 дней, запись в `cleanup_journal`; не навсегда). Вариант, который утверждён и используется шотом, убрать нельзя: сообщение «сначала выберите другое фото для шота» (правило «используемые файлы не удаляются»). После удаления выбран соседний вариант; если вариантов не осталось, показывается схема расстановки.
- **Место, время и погода — три выпадающих меню в том же стиле (24.10.2026), вместо трёх селектов:**
  - **Время суток:** утро, день, вечер, ночь. **Сезон:** зима, весна, лето, осень. **Погода:** ясно, пасмурно, дождь, снег. Каждое меню — маленькие иконки, закрывается после выбора.
  - **Ночь и зима по-прежнему требуют варианта места в Мире (§5.3), подмены нет:** если у места нет варианта «Ночь» или «Зима» (или «Зима · ночь» при обоих), рядом с меню появляется «⚠ нет варианта», а «Сгенерировать» объясняет, что делать. Утро, вечер, весна, лето, осень — слова в промпте, варианта не требуют. Странные сочетания (снег летом) помечаются ⚠.
  - **Фразы в запрос (первая версия, проверить на моделях при генерации):** утро — «early morning, soft low sun, long shadows, cool light»; вечер — «evening, warm low sun or dusk, first lit windows and street lamps»; ночь — «night, dark sky, lit only by artificial light sources». Зима — «snow on the ground and roofs, bare trees, frost, visible breath»; весна — «patches of melting snow, wet asphalt and puddles, first buds on bare branches» (так зима отличается от весны); лето — «lush green foliage, dry asphalt, strong sunlight»; осень — «yellow and orange fallen leaves, damp ground, thinning trees». Дождь — «wet reflective asphalt, raindrops, puddles»; пасмурно — «overcast sky, flat diffuse light»; снег — «falling snow».
  - **Открыто:** отдельный вариант «Зима · ночь» заводить в Мире или считать ночь зимой через слова.
- **Компактная панель (решение владельца 24.10.2026):** вместо раскрытых блоков под холстом одна тонкая строка кнопок-выпадашек с текущим значением: «Крупность», «Ракурс», «Свет», «Объектив» и справа «＋ Допилить». Меню открывается поверх, ничего не сдвигает; крупность и ракурс закрываются после выбора, свет и объектив остаются открытыми до клика вне меню. Камера и значок света на холсте тоже кликабельны и открывают те же меню. Приоритет настройки кадра: 1) что происходит и кто где, 2) крупность и ракурс, 3) свет, 4) точные параметры (мм, диафрагма, марка), они в «Объективе» и только там, где модель их понимает.
- **Прозрачная камера на холсте (решение владельца 24.10.2026):** пока показана схема расстановки, в центре холста бледно (около 50%, без мыши, не мешает) рисуется камера сбоку с пунктирным лучом на сцену и «цифрами как на старой видеокамере»: крупность (WS/MS/CU/ECU), фокусное, диафрагма, марка. Ракурс виден по положению: «снизу» — камера ниже и смотрит вверх по диагонали (20°), «сверху» — выше и смотрит вниз (30°), «на уровне глаз» — на одной высоте. Всё, что нарисовано, вписано в тот же текст запроса. После готового фото исчезает вместе со схемой.
- **Источник света на холсте:** в схеме расстановки бледно рисуется значок источника (солнце, фонарь, лампа, фары, окно) с мягким свечением, на краю холста в том месте, которое выбрано на схеме света (слева, справа, сверху, снизу, спереди, сзади). Смена источника меняет значок; в готовом фото значка нет.
- **Типы света (кнопки «Тип света»), как называть для моделей:** контровой — «backlight with a rim light (contre-jour)», силуэт — «subject in silhouette against a bright background»; уличный фонарь — «practical street-lamp light visible in frame, warm sodium-vapor glow» (practical — источник виден в кадре; motivated — свет объяснён, но источника в кадре нет); точечный — «single hard spotlight, pool of light with falloff»; лучи — «volumetric light, visible light shafts through haze». Термина «point light» модели изображений не знают, это 3D-термин: вместо него «spotlight» или «pool of light». Эти фразы нужно проверить на моделях тестом.
- **Два каталога света** в коде (`backend/frame_composition.py` и `frontend/src/cameraFrameCatalog.ts`, по 8 штук, id разные): при реализации свести в один.

Макет: `docs/design/gremovod-v2-prototype.html`, маршрут `#/photo`. Колонки, план и номера Image N там работают; поворот и набросок не сделаны.

## 11. Как референсы попадают в модель

Модель ничего не «помнит»: в каждый запрос прикладываются картинки и текст, где каждая подписана ролью — «Image 1 — лицо Грэма анфас: идентичность», «Image 2 — Грэм в полный рост: костюм и пропорции», «Image 3 — фон двора на Немиге, ночь: геометрия места». Студия **не шлёт весь пакет из 8**: под каждое фото выбирает 2–4 нужных вида (крупный план → лицо в нужном повороте; общий → полный рост с нужной стороны) плюс фон места. Выбор виден в «Что уйдёт в запрос» и меняется вручную.

| Модель | Как передаём сейчас | Состояние |
| --- | --- | --- |
| Nano Banana 2.1 | до 10 картинок по публичным ссылкам (`image_urls`), подписи в тексте промпта | с референсами вживую **не проверена** |
| GPT Image 2.5 через API студии | референсы **заблокированы** до проверки эндпоинта правок (`adapters.build_gpt_image`) | нужно подключить и проверить |
| GPT Image через ChatGPT (ручной маршрут) | картинки прикладываются в чат, подписи те же | работает вручную |

**Живой тест** (разрешён владельцем, до $1; проводится на разборе построения фото на реальных примерах): для Nano Banana и GPT Image сравнить (А) одну картинку-лист со всеми 8 видами, (Б) 2–3 отдельных вида, (В) только лицо анфас. Критерий: узнаётся ли Грэм, не копирует ли модель раскладку листа, сохраняется ли костюм. Результат закрепить в правилах каждой модели (`model_catalog.py`, скиллы).

## 12. Смысл по уровням: пять столпов

Смысл рождается в сценарии и спускается вниз; промпт его только переводит на язык модели, придумать не может. Мультфильм здесь ничем не отличается от кино: столпы одинаковые, у мульта лишь ярче позы и реакции (поле «Пластика»).

| Столп | Уровень | Где записано | Что пишет владелец | Что делает LLM-помощник уровня |
| --- | --- | --- | --- | --- |
| 4. Сценарная механика: желание, препятствие, вопрос | **Серия → сцена** | карточка сцены: «Чего хочет / что мешает», «Что меняется» | две строки | проверяет, что у каждой сцены есть желание, препятствие и перемена, и чем сцена держит зрителя к следующей; если нет — предлагает варианты |
| 4 → 1–2. Раскладка мини-истории | **Сцена → кадр → шот** | смысл кадров, действия шотов | смысл кадра одной строкой | раскладывает желание → препятствие → попытку → результат → вопрос по кадрам сцены и шотам кадра; следующий отвечает на вопрос предыдущего |
| 1. Композиция: куда смотреть | **Фото** | действие шота + «заполнялка» | одно предложение | предлагает доминанту и что приглушить |
| 2. Визуальная коммуникация: символ, статус, недосказанность | **Фото** | «заполнялка» | по желанию | предлагает символ и статус только из того, что уже есть в сцене; новых предметов и людей не выдумывает |
| 3. Операторская логика: чей взгляд, зачем движение | **Шот: видео** | действие по времени + кнопка камеры | действие героя | подбирает мотив камеры по смыслу шота |
| 5. Ритм монтажа | **Кадр и сборка серии** | сборка кадра, монтажный лист | ничего | подсвечивает ровный «метрономный» ритм шотов и кадров и слишком длинные куски (частично уже в `edit_list.py`) |
| Все пять | **Перед запуском и приёмка** | — | ничего | тихий значок «5 вопросов» перед генерацией; после — 7 фильтров сцены (§7) |

Своя сценарная механика ГремоВОДа (основа сериала) — готовый каркас конфликта для сцен с самоделками: обещание комфорта → гаражное исполнение → реакция звезды → убедительное объяснение Грэма.

Правила помощников по уровням — это «законы уровней» из TODO: при пересборке движка скилл сценариста получает правила серии и сцены, скилл постановщика — правила кадра, шота и фото. Сборщик промпта уже переводит смысл по пяти столпам (`PILLARS_RULES` в `backend/prompt_rules.py`).

**Хранение поля** «Чего хочет / что мешает» — новое необязательное поле карточки сюжетной доски (`story_plan.py`) и заметок сцены; схема базы не меняется (карточки хранятся JSON). Пустое поле не блокирует работу.

## 13. Пять столпов как проверка, а не форма

Значок «5 вопросов» и 7 фильтров ничего не запрещают и не требуют заполнять поля. Обязательных полей во всей цепочке два: смысл кадра и действие шота — и то лишь как подсказка, не блок.

## 15. Сверка с «10 ошибками AI-кино» и сверка соседних шотов

| Ошибка | Как закрыто у нас |
| --- | --- |
| 1. Начинать с генерации, а не с мира | Мир и паспорт — первые. До эталона стиля генерации идут как «пробы стиля»; в фото — предупреждение «стиль не утверждён». |
| 2. Каждое фото — новый промпт без базы | Формула фото + паспорт. **Исправить в коде:** сейчас стиль мира копируется в проект кадра при создании (`production_folders.py`, `open-project`) и дальше не обновляется — паспорт должен читаться при каждом запросе. |
| 3. Не описывать свет | Фото: свет из кнопок сцены и источников места, кнопка — замена. Шот: свет заново не описываем; «тот же свет» в ограничениях; фары и мигание — в движении среды. |
| 4. Камера и объектив | Фото: крупность, ракурс, композиция; объектив — по желанию. Шот: одна кнопка движения камеры. **Добавить позиции «в машине»:** с места водителя, с места пассажира, через лобовое стекло, с капота, сбоку у двери. |
| 5. Общий стиль «cinematic» | Свой блок стиля из паспорта + эталон стиля. |
| 6. Нет character sheet | Обязательный пакет 8 ракурсов у героя и у машины; образы — подпапки, создаются из основного пакета. **Исправить в коде:** образ сейчас всегда берёт лицо у основного героя (`production_entities.context`) — нужна отметка «меняет внешность / только одежда». |
| 7. Нет референсов мест | Реальное фото (скрытая `Real Reference`) → перерисовка в наш стиль → утверждённый фон → варианты подпапками. Кнопки сцены выбирают вариант; нет варианта — «создать?», без подмены. |
| 8. Анимировать без понимания камеры | Направление движения — в действии шота («подходит к машине слева»), камера — одной кнопкой. |
| 9. Встроенный звук без проверки цены | Звук видеомодели не используем; у MiniMax H3 выключить нельзя — при выгрузке не берём. |
| 10. Игнорировать монтаж и звук | Финальный монтаж — в CapCut/DaVinci, но **план звука в студии**: реплики и шумы у кадра, музыка у серии. Выгрузка: кадры по порядку + отдельные дорожки + монтажный лист; для DaVinci позже — EDL/XML, если понадобится. |

**Сверка соседних шотов и кадров** — функция помощника, тихая подсказка, ничего не запрещает.
- **Что проверяет:** направление движения (ушёл вправо — в следующем шоте входит слева); где стоят герой и машина (машина слева — не прыгает направо без причины); взгляды в разговоре (водитель слева, пассажир справа — по всей сцене, «правило 180°»); свет и время суток; образ героя (не сменился случайно).
- **Как:** (1) бесплатно — по тексту действий шотов («подходит к машине слева»); (2) кнопка «Сверить» — LLM смотрит утверждённые фото соседних шотов (центы, без подтверждения, §16). Локальный `frame_analysis.py` уже даёт смену зоны внимания, но направление движения и расстановку не понимает.
- **Где видно:** у стыка двух шотов в кадре и двух кадров в сцене — значок с подсказкой («Грэм уходит вправо, в шоте 3 входит справа — так задумано?»).

## 16. Расходы и подтверждение

- Сумма в шапке всегда с масштабом текущего места: шот, кадр, сцена, серия или проект. Дневной лимит действует всегда.
- Сводки объединяют задания по номеру, поэтому одно задание учитывается один раз на любом уровне. Создание героя или фона учтено один раз на проекте; использование по ссылке денег не стоит.
- Отдельно показываются оценка, подтверждённое списание, резерв и неизвестный исход. Неизвестный исход автоматически не повторяется. API-эквивалент бесплатного маршрута — отдельной строкой, в итог не входит.
- Уже есть: серия (`series_economics.py`). Нужно сделать: проект, сцену, кадр и шот — новыми чтениями поверх тех же записей.

**Подтверждение (решение владельца 24.10.2026, заменяет «подтверждать каждый платный запуск»):**

| Что | Подтверждение |
| --- | --- |
| LLM (сценарий, переписывание промпта, сверка) | нет |
| Фото: GPT Image, Nano Banana, Seedream Lite, Qwen | нет |
| **Фото Seedream 5 Pro** | **да** — галочка «Сделать картинку в Seedream 5 Pro» |
| Шот до $0.50 за запуск (например, MiniMax H3 480p 5 с = $0.15) | нет |
| **Шот дороже $0.50** (Seedance, Kling и т.п.) | **да** — галочка с ценой |

Граница $0.50 — по оценке конкретного запуска, а не по названию модели.

**Главная защита — от повторной отправки:**
- Пока запрос **той же модели с тем же текстом и теми же референсами** не получил ответ (готово или ошибка), такой же не уходит: «Такой запрос уже ждёт ответа». Проверяет сервер.
- **Другая модель — можно сразу.** GPT Image завис — отправляете в Nano Banana.
- Завис без ответа и без ошибки (как бывает у GPT Image): у задания кнопка «Снять ожидание» — после проверки в истории PiAPI владелец снимает блок, такой же запрос снова можно отправить. **Резерв бюджета остаётся** до сверки: снятие ожидания не доказывает, что списания не было. Автоматического платного повтора нет.
- Дневной лимит и лимит проекта остаются молчаливым стопом «если что-то пойдёт не так».

Сейчас в коде: подписанная оценка (`quote_token`), защита по номеру запроса (`request_id`) и по содержимому среди незавершённых заданий проекта (модель + текст + референсы + параметры). «Снять ожидание» переводит задание в ошибку и снимает блок повтора, резерв бюджета сохраняется. Нужно: сверка списания (чтобы освобождать резерв по факту) и галочка по правилу выше вместо окна подтверждения. Оценка цены остаётся — без неё не работают лимиты и цена на кнопке.

## 17. Хранение (предложение, решить при реализации)

- Сейчас в коде уровень `frame` = одно основное фото + один выбранный дубль (`production_entity_state`). По смыслу это **шот**.
- Минимальный путь без поломки данных: `frame` остаётся **кадром**; под ним — дочерние узлы `shot` с теми же полями (`selected_image_file_id`, `selected_video_file_id`) + подрезка (начало/конец) в JSON; у кадра — порядок шотов и путь к собранному файлу.
- Существующие кадры со своим фото и дублем читаются как кадры из одного шота — без переноса данных.
- «Пробы» — фото проекта без шота; перенос в шот — существующее назначение файла узлу.
