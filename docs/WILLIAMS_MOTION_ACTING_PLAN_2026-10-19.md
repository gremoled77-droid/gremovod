# Motion & Acting Layer: решения по Ричарду Уильямсу для GremoVOD

Статус: **приняты к планированию; программные функции не реализованы**. Дата: 19.10.2026.
Источник текущего разбора — загруженный `Richard_Williams_The_Animators_Survival.pdf`: **150 страниц PDF, от обложки до печатной страницы 145**. Это не полная книга; главы после этой страницы в данном файле отсутствуют. Уже существующий [разбор актёрской игры](WILLIAMS_CHARACTER_ACTING_2026-10-16.md) опирается также на ранее изученное русское издание и сохраняется без повторения. Ни одна идея об API, хранении данных или UI ниже не заявляется как утверждение Уильямса: это **наша адаптация** к AI-видео.

## Решение

На текущем этапе **не создавать нового агента или обязательную схему данных**. Разнести конкретные правила по имеющимся скиллам «Мир», «Раскадровка», «Кадры», «Видео» и использовать их при ручном/агентском составлении задания. В будущем построить поверх них **Motion & Acting Layer** между раскадровкой и генерацией видео; использовать существующий Character Vault, Shot/Storyboard, Prompt Agent, QA, бюджет и подтверждение платных вызовов.

Ценность: удерживать **актёрское намерение, понятность, физические контакты и характер движения**, а не просто совпадение исходного/последнего изображения.

## Что использовать прямо сейчас в скиллах (P0, только инструкции)

1. **Сначала смысл, потом траектория.** Отделять сюжетные ключи от экстремумов, breakdown и inbetween; один план может содержать несколько фаз без новых монтажных кадров. Основание: печ. с. 47–67.
2. **Timing не равно spacing.** Для сложного действия описывать отдельно порядок/длительность событий (включая паузу) и характер промежутков (разгон, замедление, резкость, удержание); не задавать фиктивную покадровую точность неподдерживаемой модели. Основание: печ. с. 35–39, 49–52.
3. **Физические опоры важнее красивого перехода.** Отмечать контакт ноги/сиденья/руки с предметом, перенос веса, положение массы, направление движения; во время QA искать скольжение, зависание, потерю опоры, разрыв предметного контакта. Основание: печ. с. 92–95, 102–117, 136–145.
4. **Подготовка — акцент — реакция по смыслу.** Различать подготовительное движение, основное действие и остаточное/вторичное движение; не навязывать крупные «мультяшные» замахи на каждую реплику и не насыщать все части тела активностью. Основание в доступном PDF: демонстрации изменения фаз, распределения внимания и хвостовых движений на печ. с. 63–69, 120–135; общая актёрская интерпретация — в прежнем [разборе](WILLIAMS_CHARACTER_ACTING_2026-10-16.md).
5. **Проверка раньше детализации.** Для трудного действия по возможности сделать дешёвую последовательность выбранных поз + временный звук/паузы; после генерации оценить конкретный просмотренный клип, а не достоверность промпта. Основание: печ. с. 61–69 и производственная адаптация.

### Компактная Motion Direction Note (не обязательное поле и не универсальный шаблон промпта)

- **Намерение и повод:** что герой хочет сделать и на что отвечает.
- **Видимые состояния:** начало → смысловая перемена/контакт → результат; только необходимые опоры.
- **Ритм:** где пауза, разгон/торможение, решающий акцент; численные таймкоды лишь при реальной нужде.
- **Вес/контакты:** какая опора и предмет должны оставаться непрерывными, что недопустимо «скользит».
- **Вторичное движение:** что естественно запаздывает; что намеренно остаётся неподвижным.
- **Критерий просмотра:** по чему узнаем, что движение удалось и что нельзя терять между соседними планами.

Эта записка — **внутренняя постановка**, а не готовый текст для любого API: Prompt Agent берёт только поддерживаемые конкретной видеомоделью указания. Для простого статичного/разговорного плана её можно сократить до одной строки.

## Позже: продуктовый TODO

**P1 — первый практический выпуск (после проверки текущих схем и экранов).**

- **Shot Motion Note:** необязательное версионируемое дополнение к существующему кадру/плану: намерение, сюжетные опоры, важные контакты, timing/spacing, оценка риска и требуемая моделью поддержка. Не переписывать существующие кадры и JSON задним числом.
- **Acting DNA в Character Vault:** индивидуальный рисунок походки, осанки, жестов, скорости реакции, поведения при стрессе/слушании; отдельные статусы **канон / гипотеза / состояние сцены**. Никаких автоматически утверждённых личностных признаков.
- **Preview-аниматик:** локальная сборка из имеющихся изображений и временного звука/пауз с возможностью переставить момент реакции; не считать её доказательством корректной физики финального видео.
- **Prompt Adapter:** перенос только релевантных полей Motion Note в настройки и видео-промпт конкретной поддерживаемой модели. Отдельно `supported / unsupported / unverified`; не обещать frame-accurate контроль, если API его не предоставляет.
- **Подключение скиллов к экранным LLM-запросам:** сейчас Markdown-скиллы можно читать агенту, но это не значит, что Studio автоматически включает их в промпт. Включить подходящие правила адресно для «Мир/Раскадровка/Кадры/Видео», без перегрузки контекста.

**P2 — после пилотов и проверенной ценности.**

- **QA движения** с чек-листом/ручной разметкой: скольжение стоп, непрерывность касаний, предмет/дверь, перенос веса, инерция, задержка вторичных элементов, видимость актёрского акцента, целостность лица; возможная автоматизация — только после корпуса реальных ошибок.
- **Digital X-Sheet:** при необходимости линейка действий, речевых акцентов, пауз, звуков и камеры для сложных сцен. Без требования покадрово управлять моделью и без отдельного полномасштабного движка.
- **Библиотека эталонных тестов движения:** повторяемые короткие сцены, полезные именно для нашего сериала, с фиксацией версии референсов, модели, результата и дефекта.

## Два контрольных примера, не утверждённые сцены

1. **Грэм садится в ВАЗ-2106:** читаемый доступ к дверной ручке → контакт руки → открытие двери с правильной геометрией → перенос веса и касание сиденья → завершение. Тестировать отдельно от красоты кадра. Не менять утверждённую конфигурацию машины.
2. **Грэм отвечает на неприятное уточнение:** слышит → прекращает текущий жест/короткая пауза → новый взгляд/решение → сдержанный ответ. Проверять момент перемены мысли, а не число жестов.

## Критерии внедрения и ограничения

- **Сейчас:** скиллы доступны в репозитории, ссылки и правила согласованы; ни UI, ни API не изменены, ни модель не вызывалась.
- **P1 завершён, когда:** пользователь может сохранить Motion Note у конкретного шота, выбрать поведенческий профиль с явным статусом, увидеть черновой аниматик из локальных материалов и получить модельно-адаптированное задание с отметками unsupported; всё это без платных вызовов.
- **P2 завершён, когда:** QA связывает дефект с конкретной фазой/контактом и позволяет выбрать точечный возврат («Кадры», «Раскадровка», «Видео»), сохраняя историю версий.
- Любая платная генерация — только через уже существующее подтверждение стоимости. Не писать исходные PDF или крупные фрагменты защищённого текста книги в Git.
- Не считать произвольные версии походки и характера Грэма/Кати каноном без утверждения владельца.
