# AnimioS: reverse engineering 31.7-секундного AI-мультфильма с пингвинами

Дата анализа: 2026-10-24. Источник: `AnimioS_2106689861562323210.mp4` (пользовательский файл). Первичный пост: https://x.com/AnimioS/status/2106689872014852375

## Уровни достоверности

- **Наблюдение:** определено из кадров/звука итогового MP4.
- **Сообщение автора:** «Not one prompt»; character sheets для каждого пингвина и повара, карта корабля, keyframes для сложных сцен, затем Seedance 2.5.
- **Реконструкция:** предполагаемые материалы/параметры, не подтверждённые исходными проектными файлами.

Технические параметры файла: 1280×720, 24 FPS, H.264, звук AAC, контейнер 31.718 с (760 видео-кадров = 31.667 с видео). Визуально установлены **11 монтажных планов и 10 жёстких склеек**. Сигнал автоматического детектора на 28.0 секунде — ложноположительный, вызван быстрым ударом пиццы; камера/фон остаются прежними.

## Минимальная реконструкция production assets

**Characters:** C01 — крупный пингвин с красной банданой, C02 — более короткий и округлый пингвин, C03 — высокий худой пингвин с торчащими перьями, C04 — маленький пушистый серый птенец, C05 — грузный рыжебородый повар в белом колпаке и синей полосатой рубашке. Для каждого нужен единый model sheet: фронт, профиль, 3/4, масштаб, эмоции и отличительные признаки.

**Spaces:** L01 — общий вид грузового корабля под луной, L02 — мокрый внешний борт/лодка, L03 — открытая палуба и вход в камбуз (дверь, иллюминаторы, ограждение), L04 — основной камбуз (деревянный стол, металлическая задняя стена, медная вытяжка, печь, подвешенная утварь), L05 — зона камбуза с клетчатым полом и полками. L04/L05 могут быть зонами одного помещения — установить это только по итоговому видео невозможно.

**Props:** P01 мусорный бак; P02 коробка для пиццы (закрытая/открытая); P03 пицца (в коробке, вращение, вид снизу, в момент удара, после удара); мокрая палуба и блики света.

**Keyframes, наиболее вероятно нужные:** (K01) прыжок/подъём по борту; (K02) повар выходит из двери, пингвины прячутся; (K03) раскрытие коробки при четырёх персонажах; (K04) пицца отделяется от коробки и пролетает по кухне; (K05) пицца вращается рядом с высоким пингвином; (K06) пицца летит в лицо повару; (K07) забрызганное лицо повара и реакция. K06/K07 желательно задавать несколькими фазами, а не одной текстовой инструкцией.

## Предполагаемый монтажный метод

1. Разбить 31.7 секунды на 11 коротких шотов (в проектной реконструкции проще делать каждый независимо).
2. Для каждого шота хранить `location_id`, `character_ids`, `prop_ids`, `start_frame`, `end_frame`, `camera_setup`, `action`.
3. Передавать отдельные изображения персонажей и окружения как референсы; для сложных действий — самостоятельные ключевые изображения либо серый Blender previz, если поддерживается выбранный провайдер.
4. Для сценария с одной строго заданной стартовой и финальной картинкой использовать first/last frame task. Для набора разнотипных референсов использовать reference-to-video; параметры и роли зависят от API.
5. Монтировать по cut points, обрезать нестабильные начала/концы и контролировать непрерывность звуков.

**Замечание:** 11 видимых планов ≠ 11 отдельных вызовов генератора. Модель может делать внутренние смены планов, а при монтаже один шот может происходить из нескольких генераций. Без project files и логов ни модель, ни точное число генераций по MP4 доказать нельзя. По официальной информации ByteDance лимит базовой генерации Seedance 2.5 — 30 секунд, доступны расширения. Значит 31.7-секундный готовый ролик не является одним *нерасширенным* исходным 30-секундным результатом.

## Наблюдаемая режиссёрская хитрость

В самые сложные физические переходы поставлены склейки: исчезновение бака из внимания (04→05), перенос коробки (07→08), переход «коробка/пицца в воздухе» (08→09), а также переброска пиццы от пингвинов к повару (10→11). Внутри заключительной сцены удар пиццы в лицо происходит непрерывно, без отдельной монтажной склейки на 28-й секунде. Это сильный keyframe-кандидат.

## Тест для GremoVOD

**Цель:** повторить метод не сюжетом о пингвинах, а 8–12-секундным раскрытием жёлтого лимузина ВАЗ-2106.

1. Использовать утверждённый модельный лист Грэма + утверждённую 3D-модель ВАЗ-2106 (без морфинга длины).
2. Создать одну схему локации с постоянной осью движения и координатами камеры.
3. Нарисовать/рендерить четыре опорных кадра: штатный фасад, заводская передняя дверь, начало прохода камеры вдоль борта, общий вид удлинённого лимузина.
4. Для одного сложного движения использовать Blender headless graybox video и сравнить с генерацией только по keyframes.
5. Выполнить по несколько повторов для 3 условий: text only, персонаж+локация+keyframes, плюс Blender video ref; оценить consistency violations, количество принятых MP4 и стоимость одного принятого MP4.
6. Разделить технический QC (`ffprobe`, длительность/частота кадров, битые файлы) и визуальный ручной QC (геометрия, число дверей, форточки, положение камеры, идентичность Грэма).

## Пример реконструкции промпта для финального шота (11)

```text
Create a 5.4-second, 16:9 stylized cinematic animated shot.
@Image1: approved character sheet for the stocky red-bearded chef.
@Image2: fixed reference of the galley door facing the nighttime ocean.
@Image3: approved pepperoni pizza prop, top and underside.
@Image4: layout keyframe showing the chef at the doorway.
@Image5: impact keyframe showing the pizza covering the chef's face.
The camera is locked in a symmetrical medium front shot facing the door.
The pizza enters the frame, spins toward the chef, sticks flat to his face,
then slowly slides down, revealing the chef's stained hat and shocked-to-angry expression.
Maintain exact chef identity, apron, stripes, lighting, door dimensions and ocean background.
No cut in this shot. No extra characters. No morphing of the pizza.
```

Имена `@ImageN` — иллюстративная роль референсов; для исполнения адаптер должен преобразовать их в параметры конкретного API, а при использовании strict first/last-frame роли могут отличаться.
