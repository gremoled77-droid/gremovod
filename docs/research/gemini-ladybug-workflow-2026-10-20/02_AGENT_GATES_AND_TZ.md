# Какие уроки раздать существующим агентам GremoVOD

**PROPOSED / NOT IMPLEMENTED.** Цель: меньше ручных правок и оплаченных повторов при написании сериала «Таксист Грэм» и Shorts/Reels. **Не создаём семь новых LLM агентов:** использовать уже имеющиеся stages, skills и простые офлайн-валидаторы.

## Архитектура работы на реальной истории

| Шаг | Ответственный логический этап | Вход | Выход | Проверка перед следующим |
|---|---|---|---|---|
| A | Idea / Producer, backend/producer_stage.py | Идея, ограничения серии, выбранный канон и референсы | Логлайн, скелет событий, минимальные альтернативы | Автор выбирает версию; не переписывать канон |
| B | Writers' Room / Script Editor, backend/story_plan.py + screenplay skill | Утверждённая структура, цель 3:30–4:00 или отдельный Short | Версионированный beat sheet со сценами и диапазонами секунд | Есть понятная завязка, ставки, развитие, комедийный payoff; не автоматически дробить на 8 секунд |
| C | Continuity / Character Vault | Список персонажей и утверждённые reference IDs | roster сцены, одежда, предметы, состояния до/после | Неизвестный герой или одежда → UNKNOWN / запрос владельцу, не выдумывать |
| D | Director / Storyboard | Сцены, утверждённая география/кузов авто | Shot cards: функция кадра, угол, крупность, расположение и взгляд, действие, вход/выход | Аниматик/черновой монтаж читаются без готовой генерации; пространственная логика совпадает |
| E | Prompt Adapter / выбранная видео-модель | Shot card + модель/ограничения/референсы | Ограниченный prompt + параметры, refs, audio/dialogue mapping | Локальный lint: ID, диапазоны, поддерживаемые поля модели, точная реплика, где допустимо |
| F | Video QA + владелец | 2–5 результативных клипов, actual usage, исходные фото | Approved / Retry / Needs redesign + причины | Не утверждать удачу по одному тексту. Цена нового вызова = отдельное согласование |
| G | Audio Lab | Сценарные реплики и voice references, scene pacing | TTS/диалоги/звуковая карта/музыкальные треки | Язык, прослушивание, паузы, соответствие таймингу и эмоции |
| H | Editing / Release/Reels | Утверждённые клипы, раздельные дорожки | Аниматик → версия мастера, Shorts 9:16, метрики и handoff | QC, фрейминг, канон, хук и завершённый гэг; отдельные готовые версии |

## Шесть быстрых offline-гейтов, полезных раньше новых LLM вызовов

**GATE-1. Beat completeness:** требовали N отдельных битов → есть N уникальных идентификаторов, без групповых «бит 41–50». Пустой акт / дубликат / дырка → FAIL. Умышленно пропущенные после монтажа биты помечаются OMITTED, их IDs не переиспользовать.

**GATE-2. Pacing by events:** показать автору шкалу значимых событий по времени: первое понятное действие, инцидент, главная перемена, кульминация, развязка, хук. Если модель «добавила 20 кадров дороги/погони», спросить: какая смена ситуации в каждом? Не требовать жёсткого процента экранного времени без решения автора.

**GATE-3. Canon identity and unknown:** ID из утверждённого Character Vault, правильный reference, роль, outfit version; все UNKNOWN маркируются. Для битов с массовкой отделять named characters от абстрактных силуэтов. Никого не заменять похожим цветом волос.

**GATE-4. Spatial continuity:** reference выбранной локации; in/out камеры, входная/выходная дверь, ориентация, положение объекта, сторона машины и точка контакта. Для Грэма особо проверять геометрию удлинённого ВАЗ-2106: разные двери/стороны/петли и раскрытие кузова согласно актуально утверждённому чертежу, не по старым противоречивым описаниям.

**GATE-5. Per-model prompt contract:** один ID shot → один проверяемый запрос; часть информации может быть in-app reference, а не текст. Внутренняя карточка сохраняет персонажа по имени; экспорт под модель — проверенные визуальные признаки и файл референса, звук/реплики только если режим поддерживает. Никакого универсального запрета на имена и универсального требования 500+ символов.

**GATE-6. Audio validity:** выходные тексты без нежелательных пояснений, заданный язык, допустимый объём для длительности/темпа; «lyrics» ≠ «music style». Отдельный музыкальный слой, если исходное видео снято без BGM; preview слушать реально.

## Нужна не магическая фраза, а переносимый контракт

Пример **концептуального**, не production API, объекта задачи:

    story_revision: pilot-rough-02
    scene_id: airport-transfer-01
    shot_id: airport-transfer-01-s03
    duration_target_s: 6
    required_character_ids: [graham]
    approved_reference_ids: [approved-ref-placeholder]
    location_id: minsk-airport-approach
    view: interior-facing-driver
    character_action: reacts to a VIP booking confirmation
    spatial_anchors: driver seat, steering wheel, windshield
    dialogue: null
    audio_policy: no_bgm_in_source
    canonical_status: DRAFT
    render_status: NOT_REQUESTED

Это иллюстрация полей, не существующая схема backend. ID локации и ref — **плейсхолдеры**, не реальные ресурсы. При реализации использовать существующие Pydantic/SQLite сущности без миграции до принятого ТЗ. Никаких несанкционированных ключей или paid calls.

## Одна проверка качества на трёх независимых взглядах (без трёх оплачиваемых агентов)

- **Story:** пользователь заказывает завершённый смысл, не текстовую длину; beat timing и payoff.
- **Continuity:** совпадают approved character/outfit/vehicle/location/prop states.
- **Production:** реально ли этот shot сделать выбранной моделью и референсами с разумными затратами.

Первые версии этих проверок — обычные локальные функции и тестовые фикстуры. LLM критик уместен позже и только с бюджетным разрешением.

## Не делать сейчас

1. Не переписывать backend/main.py, охрану, бюджет, SQLite и модельный реестр на основе кейса.
2. Не переносить чужой мастер-промпт в root AGENTS.md / CLAUDE.md или автоматическую загрузку всего PDF.
3. Не копировать известных персонажей или отличительные сцены; брать учебные принципы.
4. Не генерировать и не публиковать ролики без подтверждения владельца.
5. Не запускать платный N-agent loop для исправления ошибок, которые можно поймать обычной проверкой.
