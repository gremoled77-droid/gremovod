# Малые задания MiniMax из кейса Gemini/Ladybug

**Research task backlog; approval required before execution.** Проверять предварительно уже существующий код, не дублировать. Роль Codex — независимая проверка; основная P0-интеграция mavis/work → main имеет приоритет.

## MM-WRITE-01 — валидатор битов (лучший первый модуль)

**Цель:** ловить ошибки, которые пользователь PDF исправлял многократно на стр. 16–29: пропущенный бит, повтор ID, «биты 41–50» вместо десяти самостоятельных пунктов.

**Область:** независимый локальный скрипт или чистая функция, без подключения к backend/main.py и без изменения SQLite. Сначала изучить backend/story_plan.py и связанные модели.

**Выход:** результат проверки с missing_ids, duplicate_ids, unexpanded_ranges, wrong_order, unknown_character_ids, severity и human-readable report; никакого автопереписывания сценария.

**Тесты:** 1–5 правильно; нет 3; два раза 4; запись «6–10»; намеренно OMITTED 7; Unicode/кириллица; незаданные ID; повтор текста под разными ID (warning, не блок). Доказать no-network/no-spend.

**Definition of Done:** CLI/функция + 8+ offline tests + README + пример JSON отчёта + handoff с SHA. Не изменять рабочие сценарии.

## MM-VIS-02 — контракт пространственной постановки

**Цель:** избежать фургона, где непонятно, кто стоит внутри, где прилавок, в какую сторону смотрит камера (стр. 35–41, 58–60).

**Область:** определение маленького опционального списка проверяемых полей к существующим shot cards (если уже есть — адаптировать без новой базы): location_ref, camera_side, subject_position, prop_anchors, visible_background, desired_action.

**Тесты:** один герой внутри салона, другой снаружи; крупный план объекта без parent reference → warning; кабинет охраны / изображение на мониторе как второй визуальный уровень; фиксированные стороны ВАЗ-2106 через тестовые плейты. Не требовать средний план в каждой сцене.

**Definition of Done:** только спецификация/валидатор в изоляции; UI и схема БД не меняются.

## MM-CANON-03 — канон персонажей до генерации

**Цель:** не выдавать уверенные выдумки вида «у Джину синие волосы, Зоуи розовые» вопреки утверждённому описанию (стр. 89–97).

**Область:** проверить существующий Character Vault и доступ к approved/reference статусам. Спроектировать read-only input audit, не второй Character Vault.

**Тесты:** approved ref проходит; герой UNKNOWN блокируется; конфликт имени с alias ID; NPC только в одной сцене; похожие по внешности персонажи остаются разными; rejects не используются как позитивные.

**Definition of Done:** отчёт с полем unknowns и ссылками на утверждённый источник; никакого исправления канона по догадке.

## MM-SOUND-04 — lint текста и музыки

**Цель:** избежать русских текстов с режиссёрскими скобками вместо английской лирики, а также слишком большого вокального объёма для короткого трека (стр. 118–120).

**Область:** чистая функция, не ElevenLabs/FishAudio/Lyria API.

**Тесты:** target_lang=en/ru, lyrics_only, запрет stage directions когда запрошено, длинный текст для 30s → flagged for review; стиль «мрачное пианино» не заменять «весёлым быстрым»; note unknown actual singing pace.

**Definition of Done:** только диагностические предупреждения, а не автоматическая редактура художественного текста.

## MM-REVIEW-05 — журнал ручных поправок как регрессионные кейсы

**Цель:** из списка ошибок создать минимальный набор fixtures; при обновлении сценарных или prompt адаптеров проверять, не вернулись ли ошибки.

**Сначала:** проверить аналогичные тесты и реестры в mavis/work; не записывать сюда реальные чужие текстовые промпты целиком и не сохранять неподтверждённые generated images.

**Хороший результат:** пять коротких синтетических JSON фикстур с ожидаемыми FAIL/WARN, без копирования персонажей из чужого IP и без реальных API.
