## Стандарт доказательности (обязателен)
1. Каждое утверждение о поведении системы подкрепляй ссылкой на файл и строки
   из присланных материалов, либо прямо помечай как «не проверено — нет данных».
2. Не достраивай отсутствующее. Нет файла — «файл не найден», нет поведения в коде —
   «поведение не найдено». Молчаливый додум — худший вид ошибки в аудите.
3. Различай четыре зрелости и всегда указывай, к какой относишь вывод:
   - IMPLEMENTED — исполняемый код это делает;
   - PARTIAL — код есть, но не покрывает весь заявленный случай;
   - SPEC-ONLY — описан в спецификации/документе, исполнения нет;
   - MOCK — заглушка, намеренно возвращающая фиктивный результат.
4. Зелёный тест — это не доказательство отсутствия дефекта, а свидетельство, что
   заявленный сценарий не сломался. Тест, который проверяет заглушку, доказывает
   только то, что заглушка работает.
5. В репозитории встречается намеренный fail-closed (нет доказательства → BLOCKED,
   а не «пройдено»). Это сильное решение. Не называй его дефектом автоматически —
   оценивай, соответствует ли он заявленной цели.
6. Проектируй как владелец денег, а не как эстет: цена вопроса — «сколько реальных
   кредитов может уйти мимо учёта, при каких гонках, и кто может это вызвать».

# PROJECT_CONTEXT — GremoVOD

Разделы A–E. Этот документ даёт Opus достаточно контекста, чтобы оценивать

## A. Назначение

**GremoVOD** — однопользовательская (private, self-hosted) студия производства
ИИ-контента. Пользователь описывает идею, студия превращает её в сценарий, раскадровку,
набор изображений, видео, нативный звук, TTS, SFX и музыку, монтирует и выпускает.

Продуктовая идея: **видео-канал, где сценарий, визуальный канон, звук и монтаж
согласованы между собой**, а не собраны из независимых генераций. Отсюда вся
архитектура: канон (canon) — источник правды для всех последующих стадий; каждый
артефакт должен быть привязан к ревизии канона.

Пользователь — владелец студии (один человек), поэтому «пользователь» в коде почти
всегда означает владельца, а не многопользовательскую роль.

## B. Технологический стек (проверено в коде)

- **Backend:** Python 3.13, FastAPI, stdlib `sqlite3`. Зависимости зафиксированы в
  `backend/requirements.lock.txt` (снимок проверенного Windows-окружения).
  `backend/requirements.txt` — верхние границы диапазонов.
- **Frontend:** React 18 + TypeScript + Vite. `frontend/package.json`:
  `@xyflow/react` (графы воркфлоу), `lucide-react`, `typescript`.
- **Оркестрация:** n8n. JSON-описания воркфлоу в `workflows/`, скрипты импорта в
  `backend/workflow_import.py`.
- **Провайдеры:** PiAPI (основной шлюз), KIE, ElevenLabs, Fish Audio — см. `backend/kie.py`,
  `backend/adapters.py`, `backend/sound.py`.
- **Хранилище:** один SQLite (`studio.sqlite3`) + файловые каталоги под медиа.

## C. Канонические документы репозитория

- `AGENTS.md` — регламент работы с агентами, ветвление, правила коммитов, гейт
  «PR = треугольник + скриншот + текст», запрет пушить `main` напрямую.
- `CLAUDE.md` — описание архитектуры для ИИ-агента (backend-карта, стек, команды).
- `docs/CODEX_DECISIONS.md` — принятые решения владельца (D-001… и далее). Это
  источник истины по «почему так», а не «как».
- `docs/specs/n8n-production-2026-10-19/` — спецификация боевого конвейера.

> ⚠️ `CLAUDE.md` — **описание**, а не доказательство. Где оно расходится с кодом,
> приоритет у кода. Расхождения зафиксированы в `OPEN_ISSUES.md`.

## D. Ключевые решения владельца (из `docs/CODEX_DECISIONS.md`, PR #29)

- **D-010.** Формирование QA-вердикта: N34 = только техконтроль, без LLM; N35 = замороженное
  evidence; три независимых A6/A7/A8 — только с реальным покрытием.
- **Платные провайдеры.** Не тратить реальные кредиты без подтверждённого API,
  доступного лимита, модели/цены и **явной авторизации конкретного запроса**, которую
  должен обеспечивать защищённый runtime FastAPI.
- **Одна рабочая БД.** Второй экземпляр SQLite, работающий с продакшен-данными,
  запрещён. Это прямое требование к P0-контуру (см. `P0_EVIDENCE.md`, B-05).
- **Fail-closed.** Отсутствие доказательства = BLOCKED, а не «пройдено».

## E. Честное состояние на дату пакета

Это не жалоба и не оценка — это факты, которые аудитор обязан знать, чтобы не
принять MOCK за production.

1. **`main` не содержит P0-контура.** Ни бюджета, ни capability-авторизации, ни
   запрета второй БД. Это в PR #29.
2. **WF_00–WF_06 в репозитории — MOCK.** Их `name` содержит `MOCK ONLY (SOURCE EXPORT)`,
   `active=false`, WF_01–WF_06 содержат по 2 узла. Манифест сам объявляет
   `status: "MOCK_FIRST_NOT_PUBLISHED"`, `real_provider_enabled: false`,
   `real_media_evidence_available: false`. Подробно — `WORKFLOW_EVIDENCE.md`.
3. **A8 отключён.** Ремесленная оценка (native audiovisual) требует реального
   пользовательского MP4 и разрешения владельца, которых нет. `STATUS.md`:
   `MEDIA-01 → BLOCKED_NO_USER_MP4`.
4. **Реальные платные вызовы в конвейере не выполнялись.** По матрице N34–N41
   A8 — `DISABLED и BLOCKED, не SKIPPED`.

Что при этом **реализовано и покрыто тестами** — P0-контур PR #29 (свой бюджет,
HMAC-подписанные capability, запрет второй БД, UNKNOWN-состояние, дедупликация) и
бэкенд на `main` (242 теста, 345 в PR #29). Это важный баланс: проект не пустой и не
«нарисованный», но и не доведён до production.

### Как исправлено

    ...

                       "exp_ms": now_ms() + int(ttl_ms)}, sort_keys=True, separators=(",", ":"))
    signature = _b64(hmac.new(signing_key(), body.encode("utf-8"), hashlib.sha256).digest())
    return f"{_b64(body.encode('utf-8'))}.{signature}"


def verify(token: str, *, purpose: str, binding: dict) -> dict:
    ...
    expected = _b64(hmac.new(signing_key(), body.encode("utf-8"), hashlib.sha256).digest())
    if not hmac.compare_digest(signature, expected):
        raise AuthzError("capability signature is not valid")
    ...
    if payload["purpose"] != purpose:

    if payload["binding"] != binding:
        raise AuthzError("capability is bound to a different request")

- **HMAC-SHA256**, сравнение через `hmac.compare_digest` (защита от timing-атак).

- **Привязка к binding** — не принимается для другого запроса/run/envelope.
- Два типа capability: `mint_owner_capability(run_id, envelope_id, cap_cents, stage, provider, model)`
