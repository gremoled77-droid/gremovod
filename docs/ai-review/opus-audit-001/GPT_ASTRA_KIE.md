# GPT_ASTRA_KIE — платный вызов GPT-6 Astra через KIE: проверено

**Дата проверки:** 2026-10-20 · **Модель:** `gpt-6-astra` · **Маршрут:** `POST https://api.kie.ai/openai/v1/responses`
**Ключ:** `KIE_API_KEY` из окружения · **Баланс:** 922.87 → 884.77 кредита (израсходовано **38.10** ≈ **$0.19**)

Это **живые платные вызовы**, а не вывод из документации. Все цифры — измеренные.

## 1. Главный вывод

> **`.md` и `.json` отвергает только Claude-маршрут KIE.**
> На маршруте GPT-6 Astra (`/openai/v1/responses`) **принимается любой media_type**,
> включая `text/markdown` и `application/json`, — потому что тип задан явно
> в data-URI, а `filename` это просто метка.

То есть для GPT Astra **не нужна** переименовка в `.txt` из `KIE_SETUP.md` §8.
Трюк с `.txt` нужен только для Claude Opus 5.5.

Проверено сентинелами: модель эхо-нула содержимое каждого вложения.

| Файл | media_type | Результат |
|---|---|---|
| `alpha.md` | `text/plain` | `SENTINEL-ALPHA-7Q1` — прочитан |
| `beta.json` | `application/json` | `SENTINEL-BETA-3M9` — прочитан |
| `gamma.md` | `text/markdown` | `SENTINEL-GAMMA-5K2` — прочитан |
| `delta.txt` | `text/plain` | `SENTINEL-DELTA-8R4` — прочитан |

## 3. Форма запроса

```json
{
  "model": "gpt-6-astra",
  "instructions": "системные правила",
  "input": [
    { "type": "message", "role": "user", "content": [
        { "type": "input_file", "filename": "P0_EVIDENCE.md",
          "file_data": "data:text/markdown;base64,<...>" },
        { "type": "input_text", "text": "вопрос" }
    ]}
  ],
  "max_output_tokens": 900,
  "stream": false
}
```

### Две ловушки, обе проверены на себе

**1. `input` — это массив ИТОКОВ, а не частей контента.** Попытка положить
`input_file` прямо в `input` даёт:

```
HTTP 400 {"error":{"type":"server_error","message":"Invalid value: 'input_file'.
Supported values are: 'additional_tools', 'agent_message', ..., 'message', ...
```

Части контента (`input_text`, `input_file`) живут **внутри** элемента типа `message`.

**2. Поле `text` в ответе — это конфиг формата вывода, а не ответ.**
Ответ лежит в `output[].content[].text` (в ответе есть элементы типов
`reasoning` и `message`). При попытке напечатать `p["text"]` получится
`{"format":{"type":"text"},"verbosity":"medium"}`.

## 5. Тариф, посчитанный по факту

Измерено балансом до/после и сверено с полем `credits_consumed` в ответе.

| | Токенов | Кредитов | $/MTok | KIE $ |
|---|---:|---:|---:|---:|
| Вход | 15 133 | 8.47 | 560 | $2.80 |
| Выход | 167 | 0.47 | 2 800 | $14.00 |
| **Итого** | | **8.94** | | |

**gpt-6-astra на KIE = 560 кредитов/MTok вход + 2 800 кредитов/MTok выход**
(1 кредит = $0.005 → $2.80 и $14.00). Это на 72 % дешевле официальных
$10.00 / $50.00. Совпадает с опубликованным тарифом KIE.

Повторный вызов **с тем же содержимым** вложений:

| Вызов | input | output | Списано |
|---|---:|---:|---:|
| Первый (без кэша) | 10 956 | 73 | **6.34** |
| Второй (тот же вход) | 10 956 | 79 | **0.92** |
| Третий (тот же вход) | 10 956 | 72 | **0.92** |

Кэш даёт **≈ 6.9-кратное** удешевление повторов. Значит: если пакет уходит
в GPT Astra несколько раз (разбор замечаний, повторная проверка, доработка),
платить полную цену придётся **только за первый вызов**.

## 7. Наблюдение о расхождении замеров (честно)

Между вызовами 5 и 6 баланс упал на **20.45 кредита**, хотя между ними я
ничего не отправлял. Дальнейшие замеры (6 и 7) сошлись с `credits_consumed`
**до копейки**.

Возможные причины: задержка списания, фоновая корректировка или несколько
параллельных списаний за один ответ (reasoning-токены могут тарифицироваться
отдельно). Точного объяснения у меня нет.

**Практический вывод:** для контроля расхода полагаться на **баланс до и
после**, а не на `credits_consumed` из тела ответа — и замерять баланс с
запасом по времени, а не сразу после ответа.

## 8. Сравнение с тем, как модель вызывается в самом проекте

**Важно: в GremoVOD GPT-6 Astra зовётся не через KIE, а через PiAPI.**

```python
# backend/llm_guard.py:150 (main, pr/29, все ветки)
value = await studio.request_piapi('POST', '/v1/chat/completions', key,
                                   {'model': body.model, 'messages': messages, 'max_tokens': body.max_tokens})
```

```python
# backend/llm_guard.py:14 — тарифная таблица проекта
PRICES = {'gpt-5.6-luna': (0.02, 0.12), 'gpt-5.6-terra': (0.2, 1.2),
          'gpt-5.6-sol': (0.5, 3.0), 'gpt-6-astra': (2.0, 10.0)}
```

| | Маршрут проекта | KIE (проверено) |
|---|---|---|
| Провайдер | PiAPI `https://api.piapi.ai/v1/chat/completions`, заголовок `X-API-KEY` | KIE `https://api.kie.ai/openai/v1/responses`, `Authorization: Bearer` |
| Формат | chat/completions | Responses |
| Цена gpt-6-astra | **$2.00 / $10.00** за MTok | $2.80 / $14.00 |
| Ключ в этом окружении | **нет** `PIAPI_API_KEY` | есть `KIE_API_KEY` |

То есть KIE для gpt-6-astra **дороже проектного PiAPI примерно на 40 %**.
Если PiAPI-ключ появится, маршрут проекта выгоднее. Но у KIE есть то, чего нет
у PiAPI-пути: **вложения** — поэтому для аудита с файлами KIE практичнее.

> `backend/llm_response.py:1` — «Разбор ответа LLM от PiAPI (/v1/chat/completions)
> для разных моделей, **включая GPT-6 Astra**». То есть проект уже умеет
> разбирать ответ Astra; при переходе на KIE Responses формат ответа другой,
> и разбор нужно будет дополнить.

## 10. Что это меняет в плане аудита

1. **Для GPT Astra переименование в `.txt` не нужно** — `.md` и `.json`
   принимаются как есть. Переименование остаётся обязательным только для
   Claude Opus 5.5 (`KIE_SETUP.md` §8).
2. **GPT Astra — реальный второй аудитор.** Дороже Opus 5.5 по цене вывода
   ($14 против $8 за MTok), но это флагманская модель OpenAI с контекстом
   1 050 000 токенов и 128 000 выходных — весь пакет AUDIT-001C (~22k токенов)
   помещается в один выход без обрезки.
3. **Промпт-кэш делает повторные раунды почти бесплатными** — 0.92 кредита
   вместо 6.34. Значит, разбор замечаний и повторная проверка не требуют
   нового бюджета.
4. **Ответ приходит полностью в одном HTTP-вызове** — `output[]` с элементами
   `reasoning` и `message`, текст в `output[].content[].text`.
5. **Файлы читаются целиком** — модель процитировала строку с SHA ревизии,
   то есть содержимое дошло без потерь.
