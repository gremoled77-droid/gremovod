# Модель угроз Blender-пилота

**Граница:** запуски P0 в текущем хосте заблокированы по G1. Разрешаемый будущий P0 ограничен reviewed встроенным builder и синтетической сценой в подтверждённой одноразовой изолированной VM/учётной записи без секретов. Интернет-загрузка, paid provider и live MCP отключены.

| Угроза | Контроль / состояние | Остаточный риск / реакция |
|---|---|---|
| Вредоносный `.blend`, автоисполнение Python | Не принимать произвольные файлы; `--factory-startup`, `--disable-autoexec`; builder создаёт сцену из reviewed source | Эти флаги не дают OS-изоляцию. Недоверенный файл запускать только в отдельной VM без секретов |
| Инъекция аргументов/пути | Проверяется список аргументов и фиксированный script; URL и выход путей за runtime root запрещены. Pin executable и isolated launcher ещё не реализованы | Проверять нормализованный resolved path; при нарушении отказ до запуска |
| Утечка ключей через окружение/логи | Чистое allowlist-окружение процесса; не логировать значения env; paid API не вызываются | Процесс не является sandbox: его обычные полномочия Windows остаются. Никаких ключей в тестовом профиле |
| Повреждение пользовательской сцены или канон-ассета | ПЛАН: immutable proxy master, SHA и отдельная копия для попытки. Текущий planner ничего не рендерит; master copy/reopen orchestration отсутствует | До утверждённой геометрии результат не считается каноном. При изменении master остановить и создать новую ревизию |
| Загрузка неверного или чужого материала | В P0 нет upload/network provider вызовов | HTTP reference transport не принимается этим планом; P1 требует отдельной проверки ownership/version/hash и approval |
| Платные повторы/неизвестная стоимость | Вызовы API отсутствуют; `UNKNOWN` не освобождает бюджетный hold и не разрешает retry | Любой будущий live тест требует явного quote, лимита и approval существующего процесса |
| Неожиданный расход диска/памяти | Preflight проверяет свободный диск. Отдельный primitive имеет timeout 120 s и отбрасывает логи. ПЛАН: diagnostic gate, memory/disk/process-tree limits; пока не реализованы | На C: было около 4.6 GB свободно на дату аудита. При достижении лимита запуск остановить, не чистить пользовательские каталоги |
| MCP-команды произвольного Python | Live MCP не включать в P0 | Будущий MCP только в отдельной VM без секретов, без сетевых/файловых прав по умолчанию, с отдельной проверкой плагина |
| Технический QC принимается за визуальную истину | Отчёты разделяют `PASS_TECHNICAL` и человеческое решение | Никакой автоматический тест не выставляет `APPROVED`; требуется владелец канона |

## Границы контроля

Контрактные проверки, хеши, диапазон путей и preflight могут выполняться офлайн без Blender. В текущем хосте нет подтверждённой одноразовой Windows VM/учётной записи с отсутствием секретов и ограниченной сетью/файловыми правами; поэтому Blender и MCP execution имеют статус `BLOCKED_G1`. Очищенное окружение процесса, `--factory-startup` и `--disable-autoexec` не заменяют OS sandbox. Разблокировка требует owner-provided isolation receipt с идентификатором VM/учётной записи, отсутствием credential mounts/env, доступными каталогами, сетевой политикой и лимитами ресурсов. Одного receipt недостаточно: нужен reviewed isolated launcher и проверки реального отказа доступа. До этого нет рендера, render benchmark, недоверенных `.blend`, MCP, внешней передачи или платного вызова.
