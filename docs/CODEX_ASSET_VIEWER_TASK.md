Claude продолжает рецепты рилсов в своей ветке. App.tsx, StageNav.tsx, ReelsScreen.tsx, main.tsx и оформление сцены/правки Codex в этой задаче не меняет.

Область Codex: Lightbox.tsx, lightbox.css, новые MediaAssetActions.tsx/mediaAsset.ts, подключения HomeScreen.tsx/CreateScreen.tsx/ProductionStoryboard.tsx, маршрут чтения деталей в backend/temp_cleanup.py и соответствующие тесты.

Первый законченный этап: единые избранное/скачивание/промпт/корзина, исходный GPT-чат при наличии ссылки; из «Кадров» — использование как референса и подготовка видео. Закрытие, клавиатура, фокус, блокировка фоновой прокрутки, мобильная панель. Генерации и загрузки во внешнее облако по нажатию в просмотрщике не запускаются.

Проверка: изолированные временные данные и порты; рабочая SQLite и API-ключи не копируются. После реализации добавить сюда результаты и ограничения.

## Готово для объединения

Первый этап реализован в `codex/work`. Финальное объединение main должен выполнять один интегрирующий рабочий чат; эта задача сама main не меняет.

- Общая панель в Lightbox: избранное с сохранением на сервере, скачивание оригинала, модель/размеры, промпт и копирование с ручным вариантом при отказе буфера, корзина с подтверждением. Для результатов native GPT — ссылка на исходный чат по thread_id; для заданной chat_url принимаются только HTTPS-адреса настоящего ChatGPT. Универсальная отправка любой картинки в новый чат пока не добавлена.
- В «Кадрах»: кнопки «В референсы» (повторное нажатие не дублирует и не снимает выбор) и «Оживить» (только открывает существующую подготовку видео, не отправляет генерацию и не загружает файл в облако).
- Клавиатура: Escape, стрелки, Tab/Shift+Tab внутри модального окна; стрелки не переключают кадр при работе с текстом. Фокус возвращается к вызвавшей кнопке, фон инертен, прокрутка фона заблокирована. При удалении соседнего кадра сохраняется выбранный кадр, при удалении последнего просмотр закрывается.
- GET `/api/library/{asset_id}/details` возвращает существующий формат library_record под обычной защитой локальной сессии. Ошибки сервера отображаются в просмотрщике; защита используемых ассетов не обходится.
- На «Старте» устранено применение позднего ответа библиотеки/бюджета после смены проекта; просмотр использует стабильный снимок выбранных изображений.

## Следующий отдельный пункт Codex

При подготовке тестовой доски обнаружен прежний Windows MAX_PATH в `production_folders.write_text`: имя временного JSON включает длинное исходное имя плюс UUID, и глубокая папка worktree даёт FileNotFoundError при записи sidecar. Само изображение и запись production_files успевают сохраниться. Это отдельный дефект записи папок; в текущий блок просмотрщика не включён. Следующий этап: короткие имена временных файлов и согласованность файлов/БД при отказе записи, с регрессионным тестом Windows и без изменения файлов App/Reels.
