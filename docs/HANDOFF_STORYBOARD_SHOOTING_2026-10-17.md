# Настройки съёмки в раскадровке — 17.10.2026

По запросу владельца в карточку кадра на доске добавлена «Постановка съёмки». Кнопка входа: «Съёмка и файлы ↗».

- Крупность: Wide / Full / Medium / Medium close-up / Close-up / Extreme close-up.
- Объект съёмки: персонажи сцены по умолчанию; собственный список кадра; явно пустой список для предмета или окружения.
- Движение: существующий каталог 19 приёмов, включая Dolly in, Dolly out, Static, Pan, Tilt, Tracking.
- Уточнения: фокусное расстояние в мм (эквивалент полного кадра), диафрагма, фокус, свободная задача кадра.

Параметры сохраняются в `production_entity_state.data.shooting` и в локальной `КАРТОЧКА.json`. Смена параметров меняет ревизию карточки; задания привязаны к сохранённой ревизии. Старые клиенты, не приславшие shooting, сохраняют его прежнее значение. Существующие карточки без shooting не требуют миграции.

Контекст заданий карточки включает выбранных персонажей и постановку. Для изображений движение описывает начальный кадр, для видео — движение. Это режиссёрские указания для промпта; параметры провайдера не подменяются. Платных запусков нет.

Проверено:

- 4 новых интеграционных теста: сохранение БД/диска, ревизии, фото/видео, наследование/пустой состав, отклонение чужих персонажей и некорректных значений, совместимость старого клиента.
- 16 существующих тестов production, production_workspace и camera.
- 38 тестов frontend; сборка TypeScript/Vite.
- Отдельный временный браузерный стенд формы: выбор Close-up, Dolly in, Грэма, 50 мм, f/2.8, фокуса и текста задачи. Проверено отображаемое состояние формы. Полный путь карточки проверен через API в тестовой базе, а не на рабочих данных.

Изменения находятся в codex/work. Рабочая main не изменена: там есть незакоммиченные пользовательские документы; перед объединением их нужно сохранить. Перезапуск рабочего backend не выполнялся. В codex/work уже были и продолжали появляться чужие правки скиллов; они не входят в этот коммит. Fetch origin выполнен, синхронизация отложена из-за этих незавершённых правок согласно AGENTS.md. Общий HANDOFF_CLAUDE_CODE.md также обновляется параллельно, поэтому передача по этой задаче сохранена отдельным документом.
