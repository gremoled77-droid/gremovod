# Универсальный интерфейс ревьюера и переключение MiniMax → Argon

Дата: 19.10.2026 · Issue: [#27](https://github.com/gremoled77-droid/gremovod/issues/27)

Задача этапа P1 — не «добавить MiniMax», а **заложить место, где провайдера можно поменять
одним значением**. После 25.10.2026 MiniMax-M3.1-Flash перестаёт быть доступен как
Subscription Key, и вместо него встаёт Argon. Архитектура при этом не меняется.

---

## 1. Слои

```
                    ┌──────────────────────────────────────────┐
  вызывающий код    │  ReviewRequest  →  ReviewOutcome         │
  (CLI / n8n / CI)  │  один контракт, один интерфейс           │
                    └────────────────────┬─────────────────────┘
                                         │
              ┌──────────────────────────┼──────────────────────────┐
              │                          │                          │
        ┌─────▼─────┐            ┌───────▼───────┐          ┌───────▼───────┐
        │   mock    │            │    minimax    │          │     argon     │
        │ офлайн,  │            │ OpenAI-совмест│          │ обёртка над   │
        │ без ключа│            │ API, M Plan   │          │ PR #22        │
        └───────────┘            └───────────────┘          └───────────────┘
```

- **Контракт** (`contract.py`) — `dev-run-summary/1`: поля, статусы, владелец решения.
- **Интерфейс** (`reviewer.py`) — `ReviewRequest` (что показать ревьюеру) и
  `ReviewOutcome` (что он ответил). Вызывающий код не знает провайдера.
- **Адаптеры** (`adapters/`) — единственное место, где живут URL, модели и формат ответа.

## 2. Контракт `dev-run-summary/1`

Ключевые поля:

| Поле | Значения |
| --- | --- |
| `schema_version` | всегда `dev-run-summary/1` |
| `mode` | `MOCK` \| `OFFLINE` \| `LIVE` |
| `provider` | `mock` \| `minimax` \| `argon` |
| `tests_status` | `PASS` \| `FAIL` \| `NOT_RUN` \| `UNKNOWN` |
| `review_status` | `PASS` \| `FINDINGS` \| `UNCERTAIN` \| `API_ERROR` \| `QUOTA_EXHAUSTED` \| `STALE_REVIEW` \| `NOT_RUN` |
| `owner_decision` | `PENDING` \| `APPROVED` \| `REJECTED` |
| `provider_usage` | токены — только в `LIVE`; в `MOCK` обязательно `null` |
| `actual_cost` | только при подтверждённом источнике; в `MOCK` обязательно `null` |
| `quota` | снимок остатка M Plan или `null` |
| `reviewed_sha` | SHA, к которому привязан вердикт (основа `STALE_REVIEW`) |

Смысловые правила валидатора (не формальные):

- `review_status = PASS` ⇒ список `findings` пуст;
- `tests_status = FAIL` ⇒ `review_status` не может быть `PASS`;
- в `MOCK`/`OFFLINE` запрещено указывать usage и cost — нечего расходовать и нечего подтверждать;
- `NOT_RUN` / `QUOTA_EXHAUSTED` / `API_ERROR` ⇒ `owner_decision` остаётся `PENDING`;
- нераспознанный enum ⇒ ошибка контракта, а не тихое «успешно».

## 3. Почему это работает для Argon

Argon (PR #22) отдаёт текстовый отчёт, а не JSON. Адаптер `argon_adapter.py`:

- переиспользует **тот же** локальный скан (`localscan.py` → `argon_review.snapshot`),
  поэтому лимиты и поиск секретов не могут разойтись между провайдерами;
- переиспользует `argon_review.make_prompt` — тот же независимый системный промпт;
- переводит текстовый ответ в общий формат: `PASS` → без замечаний,
  иначе → одно замечание с отчётом Argon в `evidence`, `НЕУВЕРЕННО` → `UNCERTAIN`.

Переключение в n8n — это значение `provider` на входе узла 01. Узел 06 уже содержит
оба адаптера (MiniMax и Argon) — менять структуру не нужно.

Переключение в Python — это `get_reviewer("argon")` вместо `get_reviewer("minimax")`.

## 4. Что должно остаться неизменным после 25.10

| Слой | Меняется? |
| --- | --- |
| Контракт `dev-run-summary/1` | Нет |
| `localscan.py`, `quota.py`, `contract.py`, `report.py` | Нет |
| CLI `review` / `validate` / `report` | Нет |
| Структура n8n-воркфлоу (13 узлов) | Нет |
| Адаптер `minimax_adapter.py` | Отключается по сроку |
| Адаптер `argon_adapter.py` | Включается (новый credential) |
| `provider` во входных данных | `minimax` → `argon` |

## 5. Что нужно владельцу для переключения

1. Назначить credential для Argon в узле 07 (после 25.10 — снять галочку «выключен»).
2. Передать `provider: "argon"`, `mode: "LIVE"`, `consent: true`.
3. Если MiniMax-ключ ещё активен — оставить отсечку 25.10 как есть: она защищает от
   запросов после закрытия окна.

Переход обратно на MiniMax (например, при продлении M Plan) — то же самое в обратную
сторону: `provider: "minimax"`, ключ в окружении, отсечку сдвинуть осознанно.

## 6. Проверки, которые это страхуют

Офлайн-набор `tests/test_review_*.py` не привязан к MiniMax: он фиксирует контракт,
поведение охранника квоты и то, что MOCK/Argon/MiniMax подчиняются одним правилам.
Если после 25.10 новый адаптер нарушит контракт — тесты это покажут.
