# CapCut Handoff v1 — пакет материалов для ручного монтажа

**Статус эксперимента:** независимая задача, не связанная с GA-01–GA-06 и не связанная с
автоматической эстафетой Codex ↔ MiniMax. Ветка `experiment/capcut-handoff-v1`, база
`origin/mavis/work`.

**Что это.** Офлайн-модуль `tools/capcut_handoff.py`, который превращает утверждённый
монтажный лист серии в аккуратный пакет файлов, который человек вручную импортирует в CapCut:
исходники клипов в порядке монтажа, отдельные звуковые дорожки, изображения-референсы,
монтажный лист в CSV и JSON, манифест с SHA-256 каждого файла и инструкция на русском.

**Что это не.** Это **не** импортируемый нативный проект CapCut и не его замена. Версия 1 —
это пакет исходных материалов плюс инструкции по монтажу. Причина: решение владельца D4
(см. `docs/decisions/2026-10-21-beta-acceptance-D1-D4.md`) разделяет роли — **CapCut** монтирует
и рендерит, **GremoVOD** готовит материалы, ведёт учёт, контроль и приёмку.

## Границы

- Только локальный диск. Нет сети, нет платных API, нет обращения к рабочей SQLite.
- Studio на портах 8000/5173 не запускается.
- Оригиналы не изменяются: в пакет попадают побайтовые копии с SHA-256.
- Выходная папка не может лежать внутри корня медиа (и наоборот) и должна быть пустой.
- Ничего из канона, генераторов, QC N34/N35, денежных модулей и Release Gate не меняется.

## Источник порядка кадров

Порядок берётся из **экспортированного JSON монтажного листа**, который строит существующий
`backend/edit_list.py` (HTTP-маршрут `/api/productions/{pid}/series/{sid}/edit-list?format=json`).
Модуль не пересобирает монтажный лист и не дублирует его логику — он читает готовый JSON.

Ожидаемая форма входного JSON:

```json
{
  "summary": {"shots": 3},
  "warnings": [],
  "rows": [
    {"order": 1, "scene": 1, "frame": 1, "title": "Общий",
     "video": "путь/к/клипу.mp4", "image": "путь/к/референсу.png", "duration": 3.0}
  ]
}
```

Поле `video` — относительный путь **внутри корня разрешённых файлов**. Поле `image` — тот же
корень; пустое значение означает «референса нет». Строки сортируются по полю `order`; строка без
`order` сохраняет свою позицию в файле и не занимает номер другой строки.

## Запуск

Из корня репозитория:

```bash
# 1. Собрать пакет
python -X utf8 -m tools.capcut_handoff \
  --edit-list "C:/path/to/edit-list.json" \
  --media-root "C:/path/to/производство" \
  --output "C:/path/to/CapCut_Handoff"

# 2. То же с явными звуковыми дорожками и явной вертикальной версией
python -X utf8 -m tools.capcut_handoff \
  --edit-list "C:/path/to/edit-list.json" \
  --media-root "C:/path/to/производство" \
  --output "C:/path/to/CapCut_Handoff" \
  --audio "voice:озвучка/кадр01.wav,озвучка/кадр02.wav" \
  --audio "music:музыка/тема.wav" \
  --audio "sfx:звук/удар.wav" \
  --vertical "клипы/кадр01.mp4=вертикали/кадр01.mp4"

# 3. Проверить целостность готового пакета
python -X utf8 -c "import json; from tools.capcut_handoff import verify_package; print(json.dumps(verify_package(r'C:/path/to/CapCut_Handoff'), ensure_ascii=False, indent=2))"
```

Код возврата: `0` — пакет готов к монтажу, `1` — пакет собран, но есть блокирующие замечания,
`2` — отказ (небезопасный вход, непустая выходная папка, путь вне корня).

## Структура результата

```
CapCut_Handoff/
  01_Clips/
    001_scene01_shot01.mp4
    002_scene01_shot02.mp4
  02_Audio/
    voice/
    music/
    sfx/
  03_References/
    001_scene01_shot01.png
  edit-list.csv
  edit-list.json
  manifest.json
  README_RU.md
```

Имена клипов задают порядок монтажа: `NNN_sceneNN_shotNN` — номер в монтаже, сцена, кадр.
Расширение оригинала сохраняется. Вертикальная версия, если она реально есть, лежит рядом
с именем `NNN_sceneNN_shotNN_9x16.<ext>`.

## Что именно проверяется

| Требование | Как выполнено |
|---|---|
| Только выбранные клипы, в порядке монтажного листа | `rows` читаются по полю `order`, лишние файлы в пакете не попадают |
| Отдельные звуковые дорожки | Только явно переданные `voice` / `music` / `sfx`; не переданные дорожки остаются пустыми |
| Изображения-референсы | Копируются из поля `image`, когда файл существует; отсутствие — предупреждение, не блокировка |
| Оригиналы без изменения | `shutil.copy2` + сверка SHA-256 источника до и после копирования |
| SHA-256 каждого включённого файла | Поле `files` в `manifest.json` + проверка `verify_package()` |
| Длительность, разрешение, FPS | FFprobe, если доступен; иначе `null`, и это не блокирует пакет |
| Читаемый мастер | Копия проверяется FFprobe: файл, который не читается или в котором нет видеопотока, даёт блокирующее `UNSUPPORTED_MEDIA` |
| Отсутствующие клипы и другие проблемы | Раздел `issues` в `manifest.json` и таблица в `README_RU.md` |
| Неполный пакет не считается готовым | `status: "INCOMPLETE"`, `ready_for_montage: false` при блокирующих замечаниях |
| 16:9; 9:16 — только при фактическом наличии | Вертикаль ищется по явной карте или по соседнему `<stem>_9x16.<ext>`; отсутствующая версия не создаётся |

## Безопасность

- **Корень разрешённых файлов.** Читать можно только внутри `media_root`. Абсолютные пути,
  `..`-выходы и символические ссылки, ведущие наружу, отклоняются с `HandoffError` — до того,
  как на диск будет записано хоть что-то.
- **Выходная папка.** Должна быть пустой: непустая папка — отказ, пользовательские файлы не
  трогаются. Выходная папка внутри корня медиа (и наоборот) — отказ.
- **Гонка с исходником.** Если файл источника изменился между чтением и копированием, это
  фиксируется как блокирующее замечание `SOURCE_CHANGED_DURING_EXPORT`; если копия не совпадает
  с источником — `COPY_MISMATCH`.
- **Повторяющиеся имена.** Занятым считается **путь назначения**, а не имя файла: два клипа,
  претендующих на одно имя в `01_Clips`, дают блокирующее замечание `DUPLICATE_DESTINATION_NAME`,
  второй файл не копируется, первый не перезаписывается. Одноимённые файлы в разных дорожках
  (`02_Audio/voice/sound.wav` и `02_Audio/sfx/sound.wav`) не конфликтуют — они лежат в разных
  папках. Внутри одной дорожки одинаковое имя по-прежнему блокирует.
  Повторное использование одного исходника в двух кадрах — предупреждение `DUPLICATE_SOURCE`,
  оно допустимо.
- **Битый мастер.** Копия проверяется FFprobe: файл, который не читается как видео или в котором
  нет видеопотока, даёт блокирующее `UNSUPPORTED_MEDIA`. Копия остаётся в пакете, чтобы человек
  увидел, что именно сломано, но пакет не считается готовым. Если FFprobe в системе нет — проба
  не выполняется и пакет не блокируется.

## Уровни замечаний

| Severity | Что означает | Влияние |
|---|---|---|
| `blocking` | Пакет нельзя считать готовым к монтажу | `ready_for_montage: false` |
| `warning` | Пакет собран, но есть замечание к вниманию | На готовность не влияет |
| `info` | Справочная информация | На готовность не влияет |

Коды: `MISSING_CLIP`, `MISSING_AUDIO`, `MISSING_REFERENCE`, `MISSING_VERTICAL`,
`UNSUPPORTED_MEDIA`, `DUPLICATE_DESTINATION_NAME`, `DUPLICATE_SOURCE`,
`SOURCE_CHANGED_DURING_EXPORT`, `COPY_MISMATCH`, `EMPTY_EDIT_LIST`.

### Что блокирует экспорт, а что только предупреждает

Блокируют (`ready_for_montage: false`, статус `INCOMPLETE`):

| Код | Причина |
|---|---|
| `MISSING_CLIP` | У кадра нет видеофайла: файл отсутствует или в листе не выбран |
| `MISSING_AUDIO` | Объявленная звуковая дорожка не содержит файла |
| `UNSUPPORTED_MEDIA` | Клип не является читаемым видео: не тот формат, файл повреждён или в нём нет видеопотока |
| `DUPLICATE_DESTINATION_NAME` | Два разных файла претендуют на один путь внутри пакета |
| `SOURCE_CHANGED_DURING_EXPORT` | Исходник изменился между чтением и копированием |
| `COPY_MISMATCH` | Копия в пакете не совпадает с исходником |
| `EMPTY_EDIT_LIST` | Монтажный лист пуст: монтировать нечего |

Только предупреждают (пакет остаётся готовым):

| Код | Причина |
|---|---|
| `MISSING_VERTICAL` | Нет вертикальной версии 9:16 — по решению владельца 9:16 обязательна не для каждого кадра |
| `MISSING_REFERENCE` | У кадра нет референса |
| `DUPLICATE_SOURCE` | Один исходник использован в двух кадрах |

Отказом (исключение `HandoffError`, ничего не пишется на диск) считаются небезопасные пути:
абсолютный путь, `..`-выход за пределы корня медиа, символическая ссылка наружу, непустая
выходная папка, выходная папка внутри корня медиа, неизвестная звуковая дорожка, нечитаемый
монтажный лист.

## API модуля

```python
from tools.capcut_handoff import export_handoff, verify_package

manifest = export_handoff(
    "C:/path/to/edit-list.json",       # экспортированный монтажный лист
    "C:/path/to/proизводство",          # корень разрешённых файлов
    "C:/path/to/CapCut_Handoff",        # пустая выходная папка
    audio_tracks={"voice": ["озвучка/кадр01.wav"], "music": [], "sfx": []},
    vertical_map={"клипы/кадр01.mp4": "вертикали/кадр01.mp4"},
)
report = verify_package("C:/path/to/CapCut_Handoff")
```

`export_handoff` возвращает тот же манифест, который лежит в `manifest.json`.
`verify_package` перечитывает готовый пакет и сверяет его с манифестом: возвращает
`{"ok": bool, "checked": int, "mismatches": [...], "status": ..., "ready_for_montage": ...}`.
Проверка ловит и обратную ситуацию: файл, который лежит в пакете, но не описан в манифесте,
попадает в `mismatches`. Манифест при этом остаётся точкой доверия: подделать `ready_for_montage`
внутри самого `manifest.json` проверка не обнаружит — для этого нужен внешний хеш пакета.

## Тесты

```bash
python -X utf8 -m unittest tools.test_capcut_handoff -v
```

Синтетическая медиа генерируется существующим локальным движком `tools/mock_media_pilot.py`
(`make_video`, `make_png`, `make_voice`) — второй mock-media engine не создаётся. Тесты
пропускаются, если в системе нет `ffmpeg`/`ffprobe`.

Покрытые сценарии (36 тестов): три синтетических MP4 в правильном порядке; отдельные дорожки
voice/music/sfx; отсутствующий второй клип; повторяющиеся имена файлов; изменение SHA
исходника между чтением и копированием; попытка выхода за пределы разрешённой папки
(`..`, абсолютный путь, символическая ссылка); экспорт в непустой каталог; проверка целостности
конечного манифеста; повторное чтение готового пакета; повреждённый MP4 и MP4 без видеопотока;
отсутствующая звуковая дорожка; одноимённый файл в разных дорожках и в одной дорожке; строка
без `order`; пустой монтажный лист; лишний файл в готовом пакете; кириллические пути Windows;
предупреждения монтажного листа в README пакета.

## Ограничения версии 1

- Нет импортируемого проекта CapCut: только исходники и инструкции.
- Нет автоматической сборки таймлайна, склейок, переходов и звукового микса.
- Нет проверки художественного качества: длительность, разрешение и FPS — это техническая
  метрика, а не оценка кадра.
- Нет работы с каноном, QC N34/N35, Release Gate и бюджетом — модуль ничего из этого не знает.
- Требование отдельного согласования области задачи: ни ветка `experiment/capcut-handoff-v1`,
  ни ветка проверки `minimax/capcut-02-retest` не зарегистрированы в
  `tools/minimax_task_scopes.json`, поэтому scope guard их не проверяет. Перед интеграцией нужны
  отдельное согласование области и ревью Codex. Запрос на область: `docs/capcut-handoff/SCOPE-REQUEST.md`.
