# Запуск студии в облаке и доступ с телефона

Студия остаётся локальной по умолчанию. Удалённый доступ включается только переменными окружения.

## Что нужно
- Сервер (VPS) с Docker и Docker Compose, открытые порты 80 и 443.
- Домен, A-запись которого указывает на сервер. HTTPS-сертификат выпустит Caddy сам.

## Шаги
1. Скопируй проект на сервер (без файлов `*_API_KEY.txt` и без `.venv`, `node_modules`).
2. `cp .env.cloud.example .env.cloud` и заполни: домен, `STUDIO_ACCESS_PASSWORD` (12+ символов), `PIAPI_API_KEY`.
3. `docker compose up -d --build`
4. Открой `https://<домен>/login` на телефоне, введи пароль. Сессия действует 14 дней.

## Как это защищено
- Без `STUDIO_REMOTE_HOSTS` любой запрос с чужим именем хоста отклоняется (403), как и раньше.
- Снаружи каждый запрос требует подписанную cookie входа; 5 неверных паролей с одного адреса блокируют вход на 5 минут.
- Cookie `HttpOnly`, `Secure` (за HTTPS), `SameSite=Lax`. Пароль и ключи живут только в окружении сервера.
- Платные запуски по-прежнему требуют оценки, подтверждения и лимита; серверные бюджеты проекта и дня действуют и в облаке.
- Все данные (база, библиотека, проекты) лежат в томе `studio-data`. Копия: `docker run --rm -v studio-data:/d -v $PWD:/b alpine tar czf /b/studio-backup.tgz -C /d .`

## Что не проверено
Файлы `Dockerfile`, `docker-compose.yml` и `Caddyfile` написаны, но образ не собирался в среде разработки (там нет Docker). При первой сборке на сервере возможны мелкие правки.
Вход, cookie, ограничение попыток и проверка хостов покрыты тестами (`backend/test_remote_access.py`).
