# N34 — техническое QC итогового файла

Дата: 20.10.2026. Статус: реализовано в ветке `mavis/work`, 0 LLM, без платных вызовов.
Спецификация: `docs/specs/n8n-production-2026-10-19/N34_N41_RUNTIME_MODEL_MATRIX.md`, узел N34.

## Что это

Проверка готового файла выпуска по объективным признакам: потоки, длительность,
частота кадров, разрешение, кодеки, битрейт, декодируемость. Плюс сигналы —
громкость LUFS, тишина, чёрные кадры, зависание.

Сигналы — это **наблюдения, а не вердикт**. По спецификации N34 громкость, тишина
и чёрные кадры не дают художественного PASS: «−40 LUFS» не значит «плохо снято».
Вердикт по манифесту касается только технических требований.

## Вердикты

| Вердикт | Когда | Что означает |
|---|---|---|
| `PASS_TECHNICAL` | измерили, ожиданиям соответствует | технически годится; **не** значит «хорошо снято» |
| `FAIL` | измерили, ожиданиям не соответствует | есть конкретная несовпавшая проверка |
| `BLOCKED` | измерить нельзя | файл недоступен, хеш не сошёлся, нет ffprobe/ffmpeg, нет обязательной дорожки, файл не декодируется |

`BLOCKED` — это не ошибка запроса и не «плохо». Это «не хватает данных, чтобы
сказать». Согласно спецификации, в этом состоянии последующие критики N36–N38
остаются `BLOCKED` по медиа-областям.

## Роли

```
Воркер (CLI)                         Студия (доверенный backend)
────────────                         ───────────────────────────
ffprobe + ffmpeg                     принимает отчёт
  → измерения                           → проверяет подпись (HMAC)
  → подпись отчёта                      → сверяет хеш мастера со своим файлом
                                       → САМА считает вердикт по измерениям
```

Воркер: `python -m backend.media_qc master.mp4 --artifact-id id --project-id pid --manifest manifest.json --out report.json`

Воркер можно запускать на другой машине: ключ подписи — в переменной окружения
`GREMOVOD_QC_SIGNING_KEY`. **Без неё ключ живёт только до перезапуска студии**,
и отчёт, подписанный до перезапуска, перестаёт проверяться.

Граница доверия: воркер доверен (он держит ключ), подпись защищает отчёт от
правки по дороге, а хеш привязывает отчёт к байт-в-байт тому же файлу. Готовый
вердикт из отчёта **не принимается** — его считает студия, иначе воркер мог бы
просто объявить PASS.

## Маршруты

| Маршрут | Что делает |
|---|---|
| `POST /api/projects/{pid}/release-artifacts/{aid}/qc/measure` | студия меряет файл сама, подписывает и сохраняет вердикт |
| `POST /api/projects/{pid}/release-artifacts/{aid}/qc` | приём подписанного отчёта воркера: подпись → хеш → вердикт |
| `GET /api/projects/{pid}/release-artifacts/{aid}/qc` | сохранённый вердикт, проверки, измерения, наблюдения |

Манифест ожиданий (тело запроса, задаётся доверенным вызывающим):

```json
{"width": 1920, "height": 1080, "fps": 24, "duration_ms": 12000,
 "container": "mp4", "video_codec": "h264", "audio_codec": "aac",
 "require_audio": true, "duration_tolerance_ms": 500, "fps_tolerance": 0.5}
```

Пустой манифест = проверяется только базовое (файл декодируется, есть видеопоток).
Манифест берётся из запроса, а не из отчёта: отчёт — данные воркера, манифест —
ожидание владельца.

## Где лежит

- `backend/media_qc.py` — измерения, вердикт, маршруты, CLI воркера.
- `backend/security.py` — `qc_sign()` / `qc_verify()`.
- Таблица `release_artifact_qc` — вердикт по артефакту (один актуальный).
- `backend/test_media_qc.py` — 20 тестов, без сети.

## Чего не делаем

- Не судим художественно. Композиция, актёр, темп, юмор — не наша задача.
- Не объявляем, что видео «просмотрено». Измерение файла не равно просмотр.
- Не считаем громкость и тишину причиной `FAIL`.
- Не генерируем и не покупаем ничего: N34 стоит ноль и не требует ключей.

## Что дальше

- **N35** — freeze и `MediaEvidenceManifest`: зафиксировать мастер, его хеш,
  подтверждённый канон и собрать три отдельных пакета ревью на один раунд и хеш.
  Основа уже есть: вердикт N34 хранит `master_sha256`.
- **N36–N38** — требуют видео-capable модели (Gemini-класс). Ключа в проекте нет,
  n8n умеет только текст и картинки. До появления модели эти узлы остаются
  `BLOCKED` по медиа-областям — обойти это нельзя, можно только не выдавать
  недоказанное «просмотрено».
