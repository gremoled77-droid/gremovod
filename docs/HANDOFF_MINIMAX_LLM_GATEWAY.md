# MiniMax — LLM Gateway: входная точка задачи

Дата: 2026-10-20. Статус: docs/specification committed; реализация нового шлюза не проверена.

## С чего начинать

1. Выполни git fetch origin; прочитай docs/LLM_GATEWAY_MINIMAX_TASK_2026-10-20.md и docs/LLM_GATEWAY_COST_DISPLAY_POLICY_2026-10-20.md в ветке origin/minimax/llm-gateway.
2. Прочитай AGENTS.md, CLAUDE.md, docs/GIT_WORKFLOW.md, docs/HANDOFF_CLAUDE_CODE.md. Учитывай фактические более новые изменения репозитория, если найдешь.
3. Работай только в отдельном worktree на ветке minimax/llm-gateway (она уже существует в origin). Сохраняй чужие изменения. Не правь корневую main.
4. Проверь backend/main.py, backend/llm_guard.py, backend/connections.py, backend/economics.py и UI. Начни с короткого аудита, потом реальной реализации и офлайн-моков.
5. Главное требование: **на карточке LLM вызова первым выводится тарифный ориентир Kie.ai/PiAPI даже для бесплатного исполнения; Бюджет агрегирует только фактические расходы**. Если ориентир взят по другой модели, прямо указывай «другая модель». Платные маршруты подтверждаются по реальной ожидаемой стоимости до оплаты.
6. Используй config/llm_gateway.prices.example.json лишь как пример, цены/модели проверяй. Не включай непроверенную модель; не трать деньги без отдельного разрешения.
7. Тесты: бесплатный ориентир не попадает в бюджет, платный попадает, неизвестное списание отдельно, fallback без двойных списаний, старые маршруты не ломаются.
