# Проверка текущей версии после Claude Code — 16.10.2026

Прочитаны docs/HANDOFF_CLAUDE_CODE.md, CLAUDE.md, CHANGES.md. Отчёт описывает намерения и результаты прошлой сессии; рекомендации из него не выполнялись автоматически. Старые версии исходников не восстанавливались. Проверена текущая рабочая папка, включая незакоммиченные изменения.

## Подтверждённые ошибки

### 1. Высокий приоритет: ручная корзина может убрать только что назначенный референс

backend/temp_cleanup.py:140–164: trash_one читает строку и used_reason в одном соединении, закрывает его, затем перемещает файл и удаляет строку в другом. Между этими действиями другой запрос может привязать ассет к проекту. Повторной проверки под блокировкой записи нет.

Воспроизведено на временной БД: сразу после used_reason другой запрос сохраняет ID ассета в state проекта. POST /trash отвечает 200; проект продолжает ссылаться на этот ID, а GET файла отвечает 404. Рабочие файлы владельца не удалялись.

Исправление: занять блокировку записи BEGIN IMMEDIATE до проверки, повторно читать актуальные связи и выполнять изменение журнала/строки согласованно с перемещением. Предусмотреть компенсацию перемещения при ошибке БД. Добавить регрессию для ручного удаления и конкурентного назначения.

### 2. Высокий приоритет: очистка использует устаревший список кандидатов

backend/temp_cleanup.py:81–106: run_cleanup получает candidates до изменения файлов. Внутри последующего соединения перечитывается строка, но favorite/keep/использование/возраст повторно не проверяются. Файл, которому после сканирования поставили сердце, всё равно может уйти в корзину. Та же проблема касается новых привязок к сценам и персонажам.

Воспроизведено на временных данных: candidates находит старый файл, затем устанавливается favorite=true; run_cleanup всё равно переносит его в корзину. Это отдельный сценарий от ручного /trash, но исправлять оба лучше одним общим механизмом защищённого перемещения.

### 3. Средний приоритет: новый экран «Кадры» теряет черновик при навигации

frontend/src/CreateScreen.tsx:53–57: prompt, refs, options, queue и прочие параметры живут только в локальном состоянии компонента. При уходе на другой экран компонент размонтируется. Поле и выбранные референсы не сохраняются как черновик проекта.

Воспроизведено в живом браузере: пустое поле → тестовый промпт → «Старт» → «Кадры» → поле снова пустое. Генерации не запускались. Нужен черновик по projectId с восстановлением, отдельно от подтверждённой очереди платных запусков; очередь не следует автоматически повторять после восстановления.

## Дополнительные замечания по коду

- CreateScreen.tsx:external подавляет отказ clipboard.writeText, но затем сообщает, что промпт скопирован. При запрете буфера это вводит пользователя в заблуждение. Нужна явная ошибка и ручной способ копирования.
- useActivity.ts не очищает старые items при переходе от одного непустого projectId к другому; старые результаты могут оставаться до первого ответа нового проекта. reset меняет только version и не прерывает текущий long-poll: видимый результат может задержаться до окончания ожидания. Это замечания по коду, не отдельные воспроизведённые UI-регрессии этой проверки.
- StageNav.tsx: «Видео» и «Звук» открывают studio/«Идея»; «Монтаж» и «Выпуск» пока являются переходами в папки/экономику. Это известная незавершённость навигации, а не готовые отдельные разделы.
- Lightbox работает через портал, но не блокирует фоновую прокрутку и не удерживает фокус внутри окна. Требуется отдельная проверка клавиатуры и мобильного просмотра.

## Выполненные проверки

- npm run build: TypeScript/Vite прошли. Основной JS около 387 КБ; WorkflowPanel около 198 КБ отдельным файлом.
- npm test: 10/10 тестов прошли.
- Python unittest discover: 115/115 тестов прошли, внешние вызовы подменены тестовым окружением.
- Ещё две изолированные проверки воспроизвели ошибки ручной корзины и фоновой очистки. Эти проверки подтверждают дефекты, а не успешность требуемого поведения; основной код не исправлялся.
- pytest в текущей .venv отсутствует. Инструкция из CLAUDE.md о pytest здесь не работает; использован существующий unittest. Установка пакетов не выполнялась.
- На работающем сервере присутствуют /trash, /api/activity/refresh/{job_id} и editor API. Совет старого handoff о необходимости перезапуска ради этих маршрутов для текущей сессии уже не актуален. Сервер не останавливался.
- В браузере открыты новый «Старт» и «Кадры», подтверждена потеря тестового черновика. Реальные сердечки, корзина и платные кнопки не нажимались.

Это проверка затронутых экранов/механизма хранения, не полный аудит облака, новых моделей и всех денежных сценариев. Платных запросов, публикации и переноса ключей не было.

## Как продолжать здесь и в Claude Code

Да, обе среды работают с одним исходным проектом. Передача должна идти через текущие файлы и Git, без распаковки старых экспортов поверх новой версии. На начало проверки HEAD=9f86b82. Уже были правки App.tsx, WorkflowPanel.tsx, design.css, main.tsx, новый workflow.css и другие неотслеживаемые материалы — они не менялись этой проверкой.

Работать по очереди: завершить задачу → записать изменения/проверки/остатки в handoff → передать следующему агенту. Для параллельной работы использовать отдельные ветки/worktree с явным разделением модулей; один каталог и одни файлы одновременно не редактировать. Код и тесты фиксировать в Git, ключи/БД/медиа оставить вне него. Снимок данных нужен отдельно от коммитов исходников.

Рекомендуемый следующий шаг: исправить обе гонки корзины и сохранение черновика «Кадров», затем продолжать новый дизайн и связывание экранов. Текущий дизайн можно развивать здесь без отката изменений Claude Code.
