## Проблема и исправление

Раньше POST `/api/jobs/{id}/stop-waiting` переводил незавершённое задание в `failed`
и заменял ответ объектом с `detail`. Учёт бюджета воспринимал его как доказанный
бесплатный отказ провайдера: резерв обнулялся, такой же запрос мог уйти повторно.
Это происходило даже с известным Task ID или с `submission_unknown` после потери ответа.

Теперь endpoint читает состояние и возвращает 409 без записи в базу, изменения
ответа провайдера, Task ID, резерва или блокировки дубля. Для отсутствующего задания
остаётся 404. Это намеренный запрет ручного освобождения неизвестного списания;
endpoint не выполняет сверку и не обращается к провайдеру.

В `Dock.tsx` опасная кнопка и обещание освобождения бюджета удалены. Вместо них
показано «Резерв сохранён» с пояснением о сверке и выборе другой модели. Серверное
сообщение о дубле больше не предлагает нажать «Снять ожидание».

Одинаковый запрос блокируется, другая модель доступна в пределах существующих лимитов.
После обычного окончательного ответа провайдера работает прежнее поведение.
Правила освобождения по подтверждённому нулевому списанию в `security.released()`
не менялись. Миграций и исправления старых данных нет.

Отдельно перенесена только проверенная правка трёх тестов LLM из `a623ef6`:
она сохраняет `submission_unknown` и оценочный резерв после неопределённой ошибки.
Исходные файлы совпадали; применён файловый diff без слияния веток. Код LLM не менялся.
