## Дефект и первопричина

`verify_package()` сохранял в `seen` **строковое написание** пути (`Path(relative).as_posix()`)
до безопасного resolve. Поэтому один и тот же файл мог пройти проверку дважды:

- `01_Clips/clip.mp4` и `01_Clips/../01_Clips/clip.mp4` — на базе `ok=true`, файл хешировался
  дважды (`checked: 5` при четырёх записях манифеста);
- на Windows `01_Clips/clip.mp4` и `01_CLIPS/CLIP.MP4` — то же самое (файловая система не
  различает регистр).

Вдобавок сверка «файл есть в пакете, но его нет в манифесте» сравнивала разрешённые пути с
написанными строками, поэтому псевдоним давал ложное «лишний файл» и ломал учёт обязательных
документов (`edit-list.csv` и др. переставали считаться указанными в манифесте).

## Исправление

1. **Повтор — по разрешённому пути.** Сначала `resolve_pack_path()` (тот же безопасный
   разрешитель, что и для корня медиа), затем ключ сравнения `_path_key()` = `os.path.normcase`.
   Платформенная семантика: на Windows регистр не различает файлы, на POSIX различает.
   Повтор фиксируется **до** хеширования — файл читается один раз.
2. **Перечисленные пути считаются от разрешённого корня** (`_relative_in_pack()`), поэтому
   псевдоним не даёт ложного «лишнего файла» и не ломает учёт обязательных документов.
3. Сверка «лишнего файла» и проверка обязательных документов используют ту же платформенную
   семантику, что и поиск повтора.

Контракт экспортёра не менялся: `export_handoff()`, набор замечаний, формат манифеста и пакета
остались прежними.

## Замечания для Codex

1. **Изменена семантика повторов.** Раньше повтор определялся по написанной строке, теперь — по
   разрешённому пути с платформенной семантикой. Сообщение в `mismatches` прежнее по смыслу
   («тот же файл указан в манифесте дважды»), теперь в нём указывается и первое написание.
2. **`listed` теперь хранит нормализованные относительные пути** от разрешённого корня, а не
   написанные строки манифеста. Это чинит ложное «лишний файл» на псевдонимах; сверка с
   содержимым пакета использует ту же нормализацию, поэтому на Windows регистр не даёт
   ложных расхождений.
3. **Проверка обязательных документов** переведена на тот же нормализованный ключ, поэтому
   документ, указанный псевдонимом или в другом регистре, засчитывается как указанный.
4. **`_path_key()` и `_relative_in_pack()`** — две новые приватные функции; новый публичный API
   модуля не появился, сигнатуры существующих функций не менялись.
5. **Scope**: см. раздел «Scope» — skipped, не PASS; реальная проверка начнётся после #98.
