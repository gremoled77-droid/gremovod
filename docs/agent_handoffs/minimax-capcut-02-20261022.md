## Дефекты

### P1 — повреждённый MP4 проходил как готовый пакет

**Первопричина:** `probe_media()` возвращала `None` и когда FFprobe не установлен, и когда файл
не читается. Клип копировался, `media` в манифесте становился `null`, и замечания не возникало —
пакет с битым мастером получал `READY_FOR_MONTAGE`.

**Исправление:** `probe_media()` различает «нечем проверять» (`None`, FFprobe нет — не блокирует)
и «проверить не удалось» (`probe_error`). Копия каждого клипа и каждой вертикали 9:16 проверяется
пробой; нечитаемый файл или файл без видеопотока → блокирующее `UNSUPPORTED_MEDIA`. Копия
остаётся в пакете, чтобы человек увидел, что сломано, но пакет не готов.

### P1 — одинаковое имя звука в разных дорожках роняло экспорт и теряло файл

**Первопричина:** занятость имён считалась плоским множеством `taken_names` без учёта папки.
`voice/sound.wav` и `sfx/sound.wav` считались конфликтом: второй файл не копировался, в
пакете оказывался `DUPLICATE_DESTINATION_NAME` и статус `INCOMPLETE`.

**Исправление:** занятым считается **путь назначения** (`01_Clips/…`, `02_Audio/<трек>/…`,
`03_References/…`). Одноимённые файлы в разных дорожках больше не конфликтуют; два файла с
одинаковым именем в одной дорожке по-прежнему блокируются.

### P1 — строка без `order` ломала порядок монтажа

**Первопричина:** `_ordered_rows()` сортировала строки с явным `order` вперёд, а строки без него
— в конец; номер для них считался как позиция уже отсортированного списка. Строка без `order`
уезжала в конец монтажа и занимала номер другой строки (наблюдалось `[1, 3, 3]` вместо
`[1, 2, 3]`), из-за чего она же порождала ложный конфликт имён.

**Исправление:** `_ordered_rows()` возвращает `(эффективный номер, индекс строки в файле, строка)`.
Явный `order` выигрывает; строка без него сохраняет позицию в файле и не отнимает номер другой
строки.

### P2 — пустой монтажный лист считался готовым

Пакет без единого клипа получал `READY_FOR_MONTAGE`. Теперь это блокирующее `EMPTY_EDIT_LIST`.

### P2 — предупреждения монтажного листа не доходили до человека

`backend/edit_list.py` кладёт в `warnings` важные вещи («У кадра 1.2 нет видео», «Кадр длится
12 с»). В манифесте они были, но в `README_RU.md` пакета — нет, а читает именно README. Теперь
у пакета есть раздел «Замечания монтажного листа».

### P2 — `verify_package()` не замечал лишний файл

Проверка сверяла только файлы из манифеста. Случайно попавший в пакет файл не попадал в
`mismatches`. Теперь файл, который лежит в пакете, но не описан в манифесте, — это
`mismatch`.

### P2 — пробел в покрытии

`MISSING_AUDIO` был реализован, но не имел регрессионного теста. Добавлен.

## Классификация: что блокирует, а что предупреждает

| Блокирует (`ready_for_montage: false`) | Только предупреждает |
|---|---|
| `MISSING_CLIP` — нет видеофайла кадра | `MISSING_VERTICAL` — нет вертикали 9:16 (по решению владельца 9:16 не обязательна для каждого кадра) |
| `MISSING_AUDIO` — объявленная дорожка без файла | `MISSING_REFERENCE` — нет референса |
| `UNSUPPORTED_MEDIA` — клип не читается / нет видеопотока | `DUPLICATE_SOURCE` — один исходник в двух кадрах |
| `DUPLICATE_DESTINATION_NAME` — два файла на один путь | |
| `SOURCE_CHANGED_DURING_EXPORT`, `COPY_MISMATCH` — исходник изменился / копия не совпала | |
| `EMPTY_EDIT_LIST` — монтировать нечего | |

Отказом (исключение, на диск не пишется ничего) остаются небезопасные пути, непустая выходная
папка, выходная папка внутри корня медиа, неизвестная дорожка, нечитаемый монтажный лист.
Правило зафиксировано в `docs/capcut-handoff/README.md`.

4. **macOS и Linux** — не проверялись, всё под Windows (Python 3.13, FFmpeg 9.0.2).
5. **Большие пакеты и длинные пути** — порядка сотни файлов и пути длиннее 260 символов

6. **Точка доверия к манифесту** — `verify_package()` сверяет файлы с манифестом, но сам

   нужен внешний хеш.

## Замечания для Codex

1. `probe_media()` изменил контракт: раньше `None` означало «неизвестно», теперь `None` — «FFprobe
   недоступен», а нечитаемый файл возвращает словарь с `probe_error`. Внешних вызовов этого
   модуля в репозитории нет, но стоит проверить, не используется ли `probe_media` где-то ещё.
2. `_ordered_rows()` теперь возвращает тройки, а не строки. Функция приватная, вызывается в
   одном месте (`export_handoff`), но сигнатура изменилась — это стоит отметить при ревью.
3. Ключ занятости имён стал путём назначения. Проверьте, не ожидает ли где-то ещё, что имена
   сравниваются плоско.
4. `EMPTY_EDIT_LIST` — новый код замечания, его нет в исходном перечне README.
5. Scope: манифеста `capcut-02` не существует ни в одной ветке — см. `docs/capcut-handoff/SCOPE-REQUEST.md`.
   Сам манифест в PR не менялся намеренно: это control-файл guard'а.

## Рекомендации Claude Code по следующему реальному тесту CapCut

1. Собрать пакет из настоящего монтажного листа первого эпизода: взять JSON из
   `/api/productions/{pid}/series/{sid}/edit-list?format=json`, положить в отдельную папку,
   запустить `python -X utf8 -m tools.capcut_handoff` с `--media-root` на папку производства.
2. Отдельно прогнать `--audio voice:…` для настоящей озвучки и `--vertical` для настоящих
   вертикалей; проверить, что имена 9:16 находятся и упаковываются.
3. Открыть `README_RU.md` пакета и пройти монтаж строго по нему — это проверка инструкции
   человеком, а не кодом.
4. Прогнать `verify_package()` на скопированной в другое место папке: расхождений быть не должно.
5. Отдельно проверить, что в пакете нет лишних файлов (теперь это ловится).
6. Только после этого — ручной просмотр MP4 и решение, готов ли пилот.
