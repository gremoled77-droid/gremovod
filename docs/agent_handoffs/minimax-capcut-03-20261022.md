## Находки и исправления

### R1 (P1) — проверка пакета давала ложный `ok`

**Первопричина:** `verify_package()` не проверяла ни структуру манифеста, ни границы пакета.
Путь из манифеста подставлялся прямо в `target / relative` (`tools/capcut_handoff.py:646` в
базовой версии), поэтому:

- запись `../outside.txt` или абсолютный путь вели за пределы пакета, и файл **читался и
  хешировался** — проверка рапортовала `ok=true, checked=1`; тем самым подтверждала файл,
  которого в пакете нет;
- манифест с `ready_for_montage=true`, `status=READY_FOR_MONTAGE` и пустыми `files`/`documents`
  давал `ok=true, checked=0` — «готовый» пакет без единого файла считался целым.

**Исправление.** Проверка теперь идёт в четыре шага, и файл читается только на последнем:

1. **Структура манифеста** (`_manifest_structure_problem()`): объект JSON, схема
   `gremovod.capcut-handoff/1`, `files` и `documents` — списки. Иначе отказ `HandoffError` с
   причиной. `AttributeError`/`TypeError` не возникают.
2. **Границы пакета** (`resolve_pack_path()`): каждый путь разрешается внутри пакета **до**
   хеширования. Абсолютный путь, `..` за корнем и symlink/junction наружу отклоняются, и файл
   по такому пути не читается. Правила не дублировались: `resolve_media_path()` и
   `resolve_pack_path()` вызывают общий `_resolve_relative_inside()` — тот же контракт, что и
   раньше, для корня медиа; тексты ошибок прежние.
3. **Сверка файлов:** SHA-256 и размер каждого прочитанного файла против манифеста; лишний файл
   в пакете, которого нет в манифесте, — расхождение (это было в #93, здесь сохранено).
4. **Согласованность манифеста** (`_readiness_problems()`): обязательные документы экспорта
   `edit-list.csv`, `edit-list.json`, `README_RU.md` должны быть в пакете и указаны в манифесте;
   повтор пути — расхождение; расхождение `status` и `ready_for_montage` — расхождение; готовый
   пакет без единого файла — расхождение.

### R3 (P2) — повреждённый манифест без контролируемого отказа

Валидный JSON `[]` вместо объекта вызывал `AttributeError: 'list' object has no attribute
'get'` на строке чтения записей. Теперь это отказ `HandoffError` («Манифест пакета имеет неверную
структуру: ожидается объект JSON»). Ошибочная запись манифеста (не объект, пустой путь, неверный
тип пути) не роняет проверку, а попадает в `mismatches`.

### Целостность и готовность остались разными

`ok` — это целостность файлов и согласованность манифеста, а не готовность к монтажу. Корректно
собранный пакет `INCOMPLETE` с верными хешами даёт `ok=true` и `ready_for_montage=false`.
Проверено двумя тестами: на пакете, который собрал сам экспортёр, и на вручную собранном
синтетическом пакете. Готовый пакет с верными хешами по-прежнему `READY_FOR_MONTAGE`.

читал файл вне пакета. Никакие настоящие файлы владельца не используются: только синтетика в
`TemporaryDirectory`.

## Замечания для Codex

1. **Изменилось поведение `verify_package()` для повреждённого манифеста:** раньше — необработанный
   `AttributeError`, теперь — `HandoffError` с причиной. Любой вызывающий код должен ловить
   `HandoffError`; в репозитории внешних вызовов `verify_package()` нет.
2. **`checked` теперь считает только реально прочитанные файлы.** Раньше счётчик рос на каждую
   запись с непустым путём, включая отсутствующие файлы. Для успешного пакета значение не изменилось
   (все записи разрешаются и читаются), но при отказе по границе счётчик покажет меньше записей.
3. **`listed` хранит нормализованные posix-пути** (`Path(relative).as_posix()`), чтобы сверка с
   `rglob` не давала ложного «лишнего файла» при обратных слэшах в манифесте.
4. **`resolve_media_path()` теперь делегирует `_resolve_relative_inside()`.** Тексты ошибок для
   корня медиа прежние; добавлена публичная функция `resolve_pack_path()` для корня пакета.
5. **Обязательные документы проверяются для любого пакета, а не только готового.** Экспортёр
   всегда пишет `edit-list.csv`, `edit-list.json` и `README_RU.md`, поэтому настоящий пакет этому
   требованию отвечает; рукотворный пакет без документов — расхождение.
6. **Scope:** области `capcut-03` в манифесте нет, сам манифест в PR не менялся намеренно — это
   control-файл guard'а. Точный патч и три внешние зависимости — в разделе «Scope» этого отчёта.

в базе. Факты, проверенные на текущих remote-ветках после `git fetch origin --prune`:

Из этого следуют три зависимости, и все — **вне** этого PR:

1. **Манифест должен попасть в интеграционную базу.** Сейчас его нет ни в `main`, ни в
   `mavis/work`, а только в task-ветках.
2. **Запись `capcut-03` должна быть добавлена** в `tasks` манифеста — точный патч ниже.
3. **База PR #95 должна содержать enforced-guard и манифест.** Guard читает манифест из базовой
   ревизии (`origin/<base>`), а база PR #95 — ветка `minimax/capcut-02-retest`, в которой манифеста
   нет. Поэтому даже после слияния PR #87/#92 в `mavis/work` проверка этой ветки останется
   холостой, пока ветка-база не будет обновлена (или PR не перебазирован на ветку с манифестом).
