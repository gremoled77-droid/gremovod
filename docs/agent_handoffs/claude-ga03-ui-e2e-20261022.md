- Кэш хеша: `media_qc.cached_hashes()` включается только в `GET .../gate`; ключ — inode, размер, mtime, ctime (ctime нельзя вернуть через `utime`: правка на месте с восстановленным mtime кэш не обманывает — тест). Решения, N34 и заморозка N35 кэш не используют. Одно чтение `/gate` теперь хеширует файл один раз вместо двух (master_facts и N35 делят хеш), повторное — 0 раз. Остаточный риск: подмена, меняющая и ctime, и содержимое при неизменных inode/размере, возможна только манипуляцией системными часами; на решения не влияет.
- Найден и исправлен дефект (красный→зелёный): параллельные одинаковые запросы «Утвердить» создавали по строке решения на каждый (`3 != 1`), потому что проверка повтора шла до замка записи. Теперь `_record` перечитывает последнее решение внутри `BEGIN IMMEDIATE` и возвращает `duplicate:true`. Окно «файл подменён между хешем и записью» не даёт ложного утверждения: состояние пересчитывается из фактов при каждом чтении (подтверждено тестом), поэтому ранняя пометка P2 про TOCTOU снята.
