## 3. Что настроено

### Ruff

`pyproject.toml`, раздел `[tool.ruff]`. Включены правила:

- `F` — pyflakes: неопределённые имена, неиспользуемые импорты и переменные;
- `E4`, `E7`, `E9` — pycodestyle: ошибки импортов, операторов, синтаксиса;
- `B` — flake8-bugbear: типовые дефекты.

Исключения заданы явно и с обоснованием в комментариях конфигурации.
Каждое из них — не «замазывание», а защита от ложных срабатываний или от
накопленного долга, который требует отдельной ревью-правки:

| Правило | Причина исключения |
|---|---|
| `B008` | **Ложное срабатывание.** Ruff не знает FastAPI и считает ошибкой `fastapi.File(...)` / `fastapi.Form(...)` в аргументах по умолчанию — это стандартная идиома FastAPI для эндпоинтов загрузки файлов. 8 мест. Если это правило включить, агент «починит» 8 сигнатур эндпоинтов и сломает контракт загрузки файлов. |
| `E402` | **Обязательное поведение.** В `backend/main.py` роутеры регистрируются в конце модуля через `from backend.X import register; register(app, ...)` — импорты обязаны идти **после** создания `app`. Перенос их вверх приведёт к `NameError: app` при старте. 32 места. |
| `E701`, `E702` | Плотный компактный стиль репозитория (`if x: a; b`). 499 + 325 мест. |
| `E501` | Длина строки — задача форматтера, а не линтера. 1081 место при `line-length = 120`. |
| `E402`/`E401`/`E731` | Стиль: `import json, os` (4 места), присваивание лямбды (6 мест). |
| `B904`, `B023`, `B905`, `B007` | Технический долг: 27 + 15 + 4 + 1 = 47 мест. Требуют содержательной правки, а не включения вместе с настройкой линтера. Перечислены в разделе 4. |
| `F401`, `F841` в `backend/test_*.py` | Тесты импортируют модули ради доступности и подготовки состояния. |

Отдельно: `I001` (несортированные импорты, 95 мест) намеренно **не включено** —
это чистовое переформатирование 60+ файлов без изменения поведения. Его лучше
выполнить отдельным коммитом, чтобы не смешивать с содержательными правками.

`ruff format` доступен (`[tool.ruff.format]`, кавычки double, переводы строк LF),
но массово legacy-код не переформатировался.

### pytest

`[tool.pytest.ini_options]`: `testpaths = ["backend"]`, `python_files = ["test_*.py"]`,
`addopts = "-ra"`, `minversion = "7.0"`, `pythonpath = ["."]`.

Ключевое: `backend/` — неявный namespace-пакет (нет `backend/__init__.py`), а тесты
импортируют его как `from backend.xxx import ...`. Поэтому корень репозитория
обязан быть в `sys.path`.

**Найденный и устранённый дефект.** До изменений:

- `python -m pytest backend` — работало (текущий каталог попадает в `sys.path`);
- `pytest backend` — **36 ошибок сбора, 0 тестов** (`ModuleNotFoundError: No module named 'backend'`).

То есть запуск проверок зависел от способа вызова, и любая IDE или агент,
вызывавший `pytest` напрямую, получал пустой результат. Теперь оба способа
эквивалентны: `pythonpath = ["."]` в `pyproject.toml` покрывает сам pytest, а
`conftest.py` в корне даёт ту же гарантию для раннеров, которые этот параметр не
читают (IDE, unittest-обвязки).

### Frontend: единый запуск тестов

`frontend/package.json`, скрипт `test`, теперь вызывает `node run-tests.mjs`
вместо прямого `node --experimental-strip-types --test`. Новый скрипт
подставляет `STUDIO_PYTHON` перед запуском тестов, выбирая интерпретатор
в таком порядке:

1. `STUDIO_PYTHON` — явное переопределение (прежнее поведение сохранено);
2. `frontend/.studio-python` — локальный указатель на интерпретатор, файл вне Git;
3. `.venv` проекта или любого родителя — канонический корень студии и его worktree;
4. иначе ничего не подставляется, поведение как раньше.

Новый тестовый фреймворк не добавлялся: по-прежнему используется встроенный
раннер Node. Аргументы `npm test -- <файл>` пробрасываются без изменений.
