# GremoVOD — первая локальная бета: как пройти пилот вручную

Это инструкция для владельца. Она написана по результатам бесплатного тестового прохода BETA-01
(`REPORT.md`). Реальный пилот начинается только после решения D5: какие утверждённые референсы,
какой канон и какие конкретные файлы берём.

> Все шаги ниже бесплатны. Кнопки «Озвучить», генерация картинок и видео через PiAPI/ElevenLabs/Fish
> тратят деньги — их в этой инструкции нет, они идут отдельно и только через оценку цены и подтверждение.

## 1. Открыть студию
1. Запусти `START_WINDOWS.bat` (или `.\.venv\Scripts\python.exe scripts\start_studio.py`).
2. Открой http://127.0.0.1:5173/. Если пишет «already running» — старый процесс занимает порты 8000/5173, останови его.
3. Проверка: http://127.0.0.1:8000/api/health должен вернуть `{"ok":true,...}`.

## 2. Создать проект пилота
«Старт» → «Новый проект». Затем на экране «Файлы и монтаж» создай «Общий проект» — он создаст папки
`Персонажи / Локации / Серии` на диске.

## 3. Внести утверждённый канон
1. «Персонажи»: добавь героя, загрузи референсы и выбери категорию **«Реальные референсы»** или **«Утверждённые генерации»**.
2. Только эти две категории попадают в Producer. Кандидаты и отклонённые Producer отклонит с ошибкой «Референс не утверждён».
3. Это и есть решение D5: канон и референсы выбираешь ты, не агент.

## 4. Сцены и кадры
1. «Идея» → Producer. Модель `mock-producer` бесплатна, но пишет **шаблонную** структуру, не настоящий сценарий. Для настоящего текста нужен платный запрос с подтверждением.
2. «Раскадровка» → «Story Plan»: перенеси сцены в карточки, нажми предпросмотр и «Применить». Если план или раскадровка изменились — студия ответит конфликтом, обнови экран и повтори.
3. Добавь кадры: «Вставить сценарий» или «Отправить в раскадровку» из Библиотеки. У кадра отметь «основное фото».

## 5. Свои изображения, видео и звук
- Картинки: Библиотека → импорт, затем «Отправить в раскадровку».
- Видео и звук: в карточке кадра — загрузка в папки `03_Видео` и `04_Звук`.
- Реплики: экран «Звук» → «Звук по кадрам» → «＋ Реплика», приложи WAV/MP3/M4A.

## 6. Выгрузить материалы для CapCut
1. «Раскадровка» → блок «Список для монтажа (CapCut)» → «Собрать список» → «Скачать CSV».
2. CSV — это порядок кадров и пути к файлам, **не проект CapCut**. Клипы и звук забирай из папок серии.
3. Готовый пакет «клипы по порядку + звук + манифест с SHA-256» собирает `tools/capcut_handoff.py` из PR #71 (эксперимент, ещё не принят).

## 7. Собрать эпизод в CapCut
Импортируй клипы в порядке списка, положи звук из `04_Звук`, отрендери MP4 вручную. Монтаж — только в CapCut (решение D4).

## 8. Вернуть финальный MP4
Сейчас **только через API** (экрана нет): `POST /api/projects/{id}/release-artifacts` (multipart: `file`, `project_revision`, `title`).
Запись создаётся со статусом `ready` — это лишь «файл принят», не «выпуск разрешён».

## 9. Проверить N34 и заморозить N35
1. N34: `POST /api/projects/{id}/release-artifacts/{artifact}/qc/measure` с манифестом ожиданий (размер, fps, длительность, `require_audio`). Вердикт `PASS_TECHNICAL` — только техника.
2. N35: `POST /api/qa/reviews` (нужен сервисный токен `STUDIO_SERVICE_TOKENS`, браузерной сессии мало) с `media_asset_id` = id записи выпуска. Ответ `CONFIRMED` значит: хеш совпал с проверенным файлом.
3. Если файл изменён после QC, студия отвечает `BLOCKED: файл изменён после технической проверки` — повтори N34.

## 10. Утвердить конкретный мастер
Кнопки «утвердить» в студии пока **нет**: статусы `technical_pass` / `owner_approved` — задача GA-03, ещё не реализована.
До неё решение фиксируется вне студии: запиши SHA-256 файла, который смотрел (`Get-FileHash master.mp4`), и сверь его с `master_sha256` из ответа N34/N35.
Просмотр и художественное решение — твои; технический PASS их не заменяет.
