# Git для Codex и Claude Code

Настроено 16.10.2026. Это локальный Git; удалённого репозитория GitHub пока нет.

| Назначение | Каталог | Ветка |
|---|---|---|
| Проверенная студия, реальные файлы и база | `C:\AI_Workflow_Studio` | `main` |
| Работа Codex | `C:\AI_Workflow_Studio\.worktrees\codex` | `codex/work` |
| Работа Claude Code | `C:\AI_Workflow_Studio\.worktrees\claude` | `claude/work` |

Открывать нужный каталог как отдельный проект в соответствующем инструменте. Простой текст для Claude Code: «Открой C:\AI_Workflow_Studio\.worktrees\claude, работай в claude/work, сначала прочитай AGENTS.md. Не редактируй корневую папку main».

Worktree — отдельная копия исходников с общей историей Git. Незакоммиченные правки одной копии не меняют другую. Зависимости, ключи и рабочие данные не копируются. Для frontend нового worktree выполнить `npm ci` в его папке frontend; Python для проверок можно брать из корневого `.venv/Scripts/python.exe`. Тесты создают временную базу. Реальная студия продолжает работать из main.

## Обычная задача

В своей папке проверить `git status --short` и `git branch --show-current`. При чистой ветке подтянуть проверенную версию: `git merge --ff-only main`. Сделать изменения, проверить их, добавить конкретные файлы через `git add <пути>`, затем `git commit -m "Краткое описание изменения"`.

Не назначать двум агентам один и тот же файл одновременно. Worktree защищает файлы от немедленного затирания, но смысловые конфликты всё равно требуют проверки при объединении.

## Внести готовое изменение в студию

В корне проекта, после проверки чистого рабочего дерева:

```powershell
git diff --stat main...codex/work
git diff main...codex/work
git merge --no-ff codex/work
```

Для Claude использовать `claude/work`. Объединять по очереди. Если есть конфликт, разобраться в обеих правках и повторить проверки; не использовать автоматический выбор всей чужой/своей версии. Незавершённое объединение можно отменить `git merge --abort`, если перед началом main был чистым. Проверенный коммит отменяется новым `git revert`, без переписывания истории.

После объединения исходники main обновляются. Изменения backend требуют обычного перезапуска студии; Git сам сервер не перезапускает.

## Защита локальных данных

Ключи, `.env` (кроме примеров), SQLite и служебные файлы, backend/library, backend/media, backend/character_library, runtime, проекты постановки и вложенные worktree исключены из новых коммитов. Документы `projects/`, ранее попавшие под Git, сняты с отслеживания **без удаления локальных файлов**. Старые коммиты сохраняются и всё ещё содержат эти документы.

Локальный pre-commit проверяет имена добавляемых файлов и блокирует известные каталоги данных и секретов. Это не полный анализ содержимого и не замена проверке diff. Скрипт можно проверить отдельно: `python scripts/check_git_files.py --staged`.

Перед возможной публикацией на GitHub нужно отдельно проверить всю историю на секреты и пользовательские материалы; выбор приватности и публикация — отдельное решение. Git не является резервной копией SQLite и медиа. Использовать отдельные резервные копии данных.
