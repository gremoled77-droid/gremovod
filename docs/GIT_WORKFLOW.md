Worktree — отдельная копия исходников с общей историей Git. Незакоммиченные правки одной копии не меняют другую. Зависимости, ключи и рабочие данные не копируются. Для frontend нового worktree выполнить `npm ci` в его папке frontend; Python для проверок можно брать из корневого `.venv/Scripts/python.exe`. Тесты создают временную базу. Реальная студия продолжает работать из main.

## Обычная задача

В своей папке проверить `git status --short` и `git branch --show-current`. Выполнить `git fetch origin`; при чистой своей ветке подтянуть проверенную версию: `git merge origin/main`. Не переключаться на main в агентской копии — она занята корневым worktree. Сделать изменения, проверить их, добавить конкретные файлы через `git add <пути>`, затем `git commit -m "Краткое описание изменения"`.

После коммита отправить свою ветку: `git push -u origin codex/work` либо `git push -u origin claude/work`. Передавать в handoff хеш коммита, список изменённых файлов и результаты проверок.

Не назначать двум агентам один и тот же файл одновременно. Worktree защищает файлы от немедленного затирания, но смысловые конфликты всё равно требуют проверки при объединении.

## Внести готовое изменение в студию

В корне проекта, после проверки чистого рабочего дерева, обновить main и объединить проверенную агентскую ветку:

```powershell
git fetch origin
git merge --ff-only origin/main
git diff --stat main...origin/codex/work
git diff main...origin/codex/work
git merge --no-ff origin/codex/work
# После проверок объединённой версии:
git push origin main
```

Для Claude использовать `origin/claude/work`. Объединять по очереди. Если есть конфликт, разобраться в обеих правках и повторить проверки; не использовать автоматический выбор всей чужой/своей версии. Незавершённое объединение можно отменить `git merge --abort`, если перед началом main был чистым. Проверенный коммит отменяется новым `git revert`, без переписывания истории.

После объединения исходники main обновляются. Изменения backend требуют обычного перезапуска студии; Git сам сервер не перезапускает.

## Защита локальных данных

Ключи, `.env` (кроме примеров), SQLite и служебные файлы, backend/library, backend/media, backend/character_library, runtime, проекты постановки и вложенные worktree исключены из новых коммитов. Документы `projects/`, ранее попавшие под Git, сняты с отслеживания **без удаления локальных файлов**. Старые коммиты сохраняются и всё ещё содержат эти документы.

Локальный pre-commit проверяет имена добавляемых файлов и блокирует известные каталоги данных и секретов. Это не полный анализ содержимого и не замена проверке diff. Скрипт можно проверить отдельно: `python scripts/check_git_files.py --staged`.
