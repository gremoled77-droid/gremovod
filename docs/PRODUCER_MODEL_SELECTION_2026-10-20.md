# Выбор модели для этапа «Продюсер»

- **Ветка:** `minimax/producer-model-picker-20261020`
- **База:** `origin/mavis/work` (`0a28b32`) — там уже есть API этапа «Продюсер» (`backend/producer_stage.py`, `5a27517`).
- **Дата:** 2026-10-20

## Что сделано

Пользователь сам выбирает провайдера и модель для этапа «Продюсер» (идея → сценарная структура).
Готовый селектор в `frontend/src/AgentPanel.tsx` (провайдер + свободный ввод модели) доработан
в каталог: провайдер и модель берутся из серверного реестра, недоступный провайдер помечается
как недоступный. Второго селектора не появилось.

| Требование | Где сделано |
|---|---|
| 1. Провайдер | `GET /api/producer/options` → `frontend/src/producerModel.ts:parseCatalog` |
| 2. Модель из проверенного каталога | тот же эндпоинт, модели из `backend/model_catalog.py::LLM_MODELS` |
| 3. Оценка стоимости | `POST /api/producer/estimate` → `estimated_usd` |
| 4. Подтверждение платного запуска | `POST /api/producer/run` требует `approved`, `quote_token`, `max_cost_usd`, `request_id` |
| 5. Статус и фактически использованная модель | ответ `run` содержит `model` (`id`, `label`, `provider`, `paid`), `cost_usd`, `external_calls` |
| 6. Недоступный провайдер | `available: false` + сообщение бэкенда; кнопки блокируются, обещаний нет |
| 7. Выбор в состоянии проекта | `state.producer` (`frontend/src/App.tsx`), сохранение через `persistProject` с `base_revision` |
| 8. MOCK по умолчанию | `DEFAULT_CHOICE = {provider: 'mock', model: 'mock-producer'}`; платный вызов только после явного подтверждения |

## Как устроен выбор

```
GET /api/producer/options
  providers: [
    {id: 'mock',  available: true,  models: ['mock-producer']},
    {id: 'piapi', available: false, status: 'not_configured',
     message: 'Ключ не настроен: PIAPI_API_KEY.txt', models: [...]}
  ]
  models: [{id, label, provider, price_in, price_out, scopes}]
  default: {provider: 'mock', model: 'mock-producer'}
```

- **Источник правды — бэкенд.** Копии реестра во фронтенде нет, поэтому цена и состав моделей
  не могут разойтись с сервером. Доступность провайдера берётся из `backend/connections.py`
  (тот же механизм, что у панели подключений): нет ключа → `available: false` и честное
  сообщение, а не обещание платного запуска.
- **MOCK — первый и по умолчанию.** Локальная детерминированная структура: сети нет, расходов нет,
  ключ не нужен. В списке моделей MOCK стоит с нулевой ценой.
- **Цена видна до запуска.** У каждой модели в выпадающем списке показана цена за 1M токенов;
  кнопка запуска подтверждения показывает сумму оценки.
- **Автозапуска платных моделей нет.** Сначала «Оценить стоимость», потом отдельное
  «Подтвердить и запустить». Смена модели сбрасывает оценку — запустить по старой цене нельзя.

## Состояние проекта и конфликт

Выбор лежит в `state.producer` и сохраняется вместе с проектом обычным путём:
`persistProject` отправляет `base_revision`, сервер отвечает `409 PROJECT_CONFLICT`, если проект
изменили в другом окне, а фронтенд пытается разобрать правки через `mergeProject`.
Выбор модели — обычное поле состояния, поэтому при конфликте:

- если в другом окне сменили провайдера — конфликт по `producer.provider` и `producer.model`;
- если провайдер тот же, а модель разная — конфликт только по `producer.model`;
- если выбор не трогали — правка сохраняется молча.

## Обработка ошибок

| Ситуация | Поведение |
|---|---|
| Каталог не пришёл или битый | панель показывает «Каталог моделей недоступен: …», выбор блокируется |
| Провайдер без ключа | «Провайдер недоступен: Ключ не настроен: …», кнопки заблокированы |
| Модель чужого провайдера | сервер: «Модель … не найдена в реестре или её не обслуживает провайдер …» |
| Оценка без подтверждения | сервер: «Нужно подтверждение платного LLM-запроса» |
| Ответ модели вне контракта | сервер: 502 «Ответ модели не соответствует контракту этапа… Платный повтор автоматически не выполняется» |
| Проект изменён в другом окне | 409 `PROJECT_CONFLICT`, локальный выбор остаётся в форме |

  доступность, отсутствие ключевого материала в ответе, сохранение и загрузка выбора, конфликт ревизии.

- `cd frontend && npm test` — фронтовые тесты, включая новый `frontend/producerModel.test.mjs`
  и два кейса слияния в `frontend/projectMerge.test.mjs`.
- `cd frontend && npx tsc --noEmit` — типы.

**red→green.** Тест `test_provider_without_key_is_unavailable_without_promises` падает, если
эндпоинт отдаёт `available: true` провайдеру без ключа: это ровно то «ложное обещание»,
которое требовалось исключить.

**Окружение фронтовых тестов.** `frontend/directorState.test.mjs` поднимает Python-подпроцесс
и требует интерпретатор с `fastapi`; в клоне без `.venv` он берёт системный `python3` и падает.
Запуск: `STUDIO_PYTHON=C:\AI_Workflow_Studio\.venv\Scripts\python.exe npm test`.
Это известная особенность ветки, а не следствие правки (см. `docs/ENVIRONMENT_AUDIT_2026-10-20.md`
в ветке `codex/env-audit-20261020`).
