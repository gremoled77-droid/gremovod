# GremoVOD: полная спецификация n8n для обзора

Версия 1.0-review · 19.10.2026 · статус: проектирование, не развёрнутая система.

**Цель:** идея автора → A0 → варианты A1 → режиссёрская разработка → реальные картинки, звук и видео → монтаж → три независимых финальных критика → решение человека → Готовые.

## Порядок чтения

1. [SPECIFICATION.md](SPECIFICATION.md) — цель, роли, процесс, критика, навыки, модели, библиотеки, версии и ошибки.
2. [NODES.md](NODES.md) — отдельное задание для каждого из 43 основных узлов и 9 общих сервисов: вход, действие, выход, приёмка и переходы.
3. [nodes.json](nodes.json) — тот же каталог в машиночитаемом виде; это спецификация, не импортируемый n8n workflow.
4. [IMPLEMENTATION_AND_ACCEPTANCE.md](IMPLEMENTATION_AND_ACCEPTANCE.md) — последовательность реализации и проверки готовности.
5. [REVIEW_GPT_ASTRA.md](REVIEW_GPT_ASTRA.md) — готовое задание на архитектурный обзор GPT Astra.
6. [HANDOFF.md](HANDOFF.md) — границы сделанного и точка продолжения.

## Главные ограничения

- Текстовый пилот — часть общего процесса, не конечная цель.
- Новые workflow, генераторы и хранилища этим пакетом не созданы.
- Критики исследуют материал своего этапа; сценарий не доказывает качество картинки/звука/видео.
- Финальные три PASS не заменяют решение человека и не публикуют файл.
- A0–A8 и физическое число n8n nodes — техническое решение, допускающее пересмотр.
- Все платные вызовы, включая критиков, требуют отдельно разрешённого бюджета; пакет не разрешает расходы.
- Полная Studio проектируется после испытания n8n на реальных файлах.
- В пакете нет рабочих сценариев, медиа, баз, ключей или сырых конфигураций credentials.

Возможности конкретных моделей, цена и доступность API не установлены этой спецификацией. Расхождение официальной документации Message an Agent и retired-метаданных экземпляра описано явно; для первого пути выбран Execute Sub-workflow с ролевыми исполнителями.


## Поправки после архитектурного обзора Astra (v1.1)

**[ASTRA_FIXES_V1_1.md](ASTRA_FIXES_V1_1.md)** — обязательная поправка к этой спецификации: P0/P1/P2, переходы, бюджет, состояние, аудиомаршруты и финальный QA. [nodes.json](nodes.json) содержит проверяемые `astra_v1_1` поля и уточнённые условные маршруты. При конфликте новых и прежних формулировок применяйте поправку v1.1, но не считайте её реализацию подтверждённой.

Опытная SQLite-модель `integrations/n8n/pilot_state_sqlite.py` и её временные офлайн-тесты `backend/test_n8n_astra_pilot.py` — **reference implementation**, ещё не связаны с production FastAPI. Текущий облачный workflow для отрицательных тестов — симуляция, не media inspection.

**Согласованная последовательность:** исправления Astra → бесплатный mock и офлайн-тесты → реальный короткий MP4, когда появится → полный пилот → дизайн Studio. До MP4 A8/FINAL_MEDIA/READY остаются BLOCKED.
