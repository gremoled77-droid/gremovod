## Причины и приоритеты

1. **Длительные сессии с большим контекстом.** В первом чате медиана входа в событиях usage — около 196 тыс. токенов, максимум 386 358; четыре события compaction. Во втором максимум 396 210, в третьем 317 671. Медианы событий не следует считать точным средним по уникальным запросам: события могут повторяться. Начальные события нескольких новых чатов уже показывают около 37 тыс. входных токенов. В них входят инструкции, инструменты, каталоги навыков и прочий контекст — это не размер пользовательской реплики.
2. **Много шагов с инструментами.** Первый чат содержит сотни вызовов; работа с браузером и последовательные проверки добавляют шаги, результаты и историю. На момент проверки чаты «Проверь задачу еще раз» и «Камера и свет — интерфейс в стиле Higgsfield» были active. Укороченный ответ пользователю сам по себе это не устраняет.
3. **Изображения и интерфейс.** В результатах инструментов первых трёх чатов обнаружено соответственно 27, 31 и 16 блоков input_image. Есть текстовые блоки результатов длиной до 39 тыс. символов. Крупные JSONL-блоки с base64 проверены: это штатные input_image, не доказанная утечка base64 в текст. Размер логов в мегабайтах не равен количеству токенов.
4. **Накладные расходы подключений.** В config.toml включены 14 плагинов и 6 MCP-серверов. В контексте текущего чата присутствует большой каталог навыков. Сами полные SKILL.md не обязательно загружаются заранее. Точную долю токенов каждого подключения локальный счётчик не показывает.
5. **Очередь студии использует Codex.** backend/native_chat.py передаёт задачи в закреплённый чат; scripts/native_chat_worker.py только обслуживает локальный транспорт. Встроенная генерация и распознавание изображений расходуют подписку. Вызовы ожидания также присутствуют, но их доля здесь существенно меньше, чем у главных рабочих чатов. Внутренний HTTP polling Python каждые две секунды сам по себе не вызывает модель. Расход возникает при возврате управления агенту и очередном шаге модели.

## Что делать

- Для небольших правок и простой подготовки текста выбирать Luna, если доступна в селекторе; сложные изменения и диагностику оставлять Sol. Текущий глобальный default — gpt-6.1-sol, reasoning medium; это не доказывает настройку каждого активного чата.
- Использовать Standard для повседневной работы; проверить, не включён ли Fast/Ultrafast в конкретном чате. В проверенных данных текущий режим скорости не установлен.
- Разделять завершённые этапы: сохранять краткий handoff (результат, нужные пути, следующая задача) и начинать следующий независимый этап в новом чате. Не создавать новый чат после каждого сообщения: он заново оплачивает начальный контекст и может потерять полезный кэш.
- Для кодовых задач оставлять только нужные плагины/MCP. Медиаплагины включать для медиазадач. Отключение — отдельное изменение пользовательских настроек, в этом аудите не выполнялось.
- Искать в backend/, frontend/src/ или конкретном файле; выводить найденные строки и небольшие фрагменты. Исключать runtime/reviews/, tmp/, вложенную копию AI_Workflow_Studio/, сборки и зависимости из общих поисков. Наличие файлов на диске само по себе не расходует токены.
- Проверять UI в конце связанного набора изменений. Снимки делать по необходимости; для текста и структуры использовать DOM. Не перечитывать неизменённые изображения.
- Не держать модель в цикле ожидания пустой очереди. Ожидание и наблюдение выполнять обычным локальным процессом, возвращать модели готовое задание или результат. Текущий транспорт не умеет самостоятельно будить чат; для полноценного фонового режима потребуется отдельное решение.
- Генерацию изображений учитывать как самостоятельную существенную статью. Избегать повторных генераций без конкретного изменения; использовать утверждённые исходники. Переход на API переносит расход на отдельный платный баланс, а не делает генерацию бесплатной.

Короткая инструкция для будущих кодовых задач: «Работай только над указанной задачей. Сначала узкий поиск. Читай нужные фрагменты. Проверяй изменённое поведение; браузер используй для UI. Не запускай постоянный мониторинг. После результата остановись и кратко сообщи проверку».

## Проверка лимита

Во время аудита инструмент аккаунта вернул Plus: использовано 3% пятичасового и 1% недельного окна. Это общие показатели аккаунта на тот момент, а не доля этого проекта. Локальные исторические токены не позволяют восстановить прежние проценты лимита.

Официальная документация: https://learn.chatgpt.com/docs/pricing . На дату проверки она указывает влияние модели, контекста, reasoning, инструментов и кэширования; рекомендует сокращать контекст и число MCP. Для включённого лимита Fast указан как 2,5× Standard, Ultrafast — 8×; генерация изображений расходует общий лимит и в среднем использует его в 3–5 раз быстрее сопоставимых ходов без генерации. Это общие ориентиры, не измеренная доля нашего проекта. Точные обещания экономии в процентах без сравнения одинаковых задач необоснованны.
