## Критерии приёмки

### 1. Числа прогонов в документах — фактические

Находка слепого проверяющего дословно: «`docs/HANDOFF_MINIMAX_LLM_GATEWAY.md:68` и `docs/LLM_GATEWAY_TEST_REPORT.md` §6 пишут `Ran 359 tests`, на HEAD фактически **371** (круг F3 добавил 12 тестов после правки доков). npm-цифры совпали точно: 119 pass, 1876 модулей, 4.74 с».

Требование: приведи числа в обоих документах к **фактическим после твоих правок** — перепрогони обе брифовые команды и фронтенд сам и впиши свои числа. Плюс: в `docs/LLM_GATEWAY_ARCHITECTURE.md` проверь, не осталось ли там числа прогонов или числа коммитов в старом виде.

### 2. Маршруты реестра должны быть достижимы из интерфейса — без поломки сегодняшнего поведения

Находка слепого проверяющего дословно: «**цепочка Free→Paid недостижима из UI студии.** `frontend/src/llmAsk.ts:59-60` жёстко шлёт `provider: 'piapi'` и не передаёт `route_mode`/`allow_free`; то же в `WorkflowPanel.tsx:787`. Grep по `frontend/src` не нашёл ни одного `allow_free`/`route_mode` — окна IdeaBrief/OutlineDialog/WorldFromBrief всегда идут по manual-маршруту (legacy PiAPI). Цепочка включается только из API с `route_mode=auto` + `allow_free=true` … По API критерий брифа выполнен, но заказчик из интерфейса её не запустит».

Требование:

1. **Интерфейс перестаёт жёстко зашивать провайдера.** Окна LLM (Идея, Мир, Узлы, диалог сценария) передают серверу задачу и режим маршрутизации вместо `provider: 'piapi'`. Что именно означает «задача» в каждом окне — реши сам из ролей реестра (`simple` / `editorial` / `coding` / `backup`), и запиши решение в отчёт.
2. **Сервер не должен сломать студию, пока маршруты не включены.** Если реестр не даёт пригодной цепочки для задачи — вызов идёт по **совместимому маршруту** (как сегодня, проверенные цены PiAPI), а не падает с 400. Иначе включение шлюза выключит LLM-вызовы в студии.
3. **Как только владелец включит маршрут в реестре, интерфейс идёт по нему** — без правок во фронтенде. Это и есть смысл: маршрут выбирает сервер, а не клиент.
4. **Ничего не ломается в обратную сторону:** старый клиент с `provider='piapi'` работает как раньше; `POST /api/llm/chat` без новых полей работает как раньше; подпись и бюджетные проверки не меняются.
5. Автоматический режим и цепочка запасных маршрутов остаются **opt-in** для владельца: без явного разрешения (`allow_free`) бесплатный маршрут в цепочку не попадает, и **ни одна цепочка не делает две платные попытки**.

Обязательные тесты:
- реестр без пригодной цепочки → вызов идёт по совместимому маршруту (не 400), поведение как до правки;
- реестр с включённым маршрутом под задачу → вызов идёт по **нему**, а не по совместимому;
- режим по умолчанию — без параллельных вызовов и без двух платных попыток;
- обе брифовые команды проходят; фронтенд — `npm test` и `npm run build`.
