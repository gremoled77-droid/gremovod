## Критерии приёмки

### Деньги: две платные попытки на один запрос

- `backend/llm_guard.py:303` — `if entry.free or entry.opt_in` считает **платный** opt_in-маршрут «бесплатным» и кладёт его в цепочку; следом добавляется обычный платный → в цепочке **два платных маршрута**, т.е. две платные попытки на один запрос (двойное списание). Проверка: `plan_chain(reg,'coding',allow_free=True)` → `[kie/paid-optin (PAID), minimax/paid-normal (PAID)]`, платных 2; при `allow_free=false` → 1. Нарушено R21 и доктринг `llm_guard.py:296`. Фикс ограничен (1–2 строки: в цепочку идут только `free`/тариф 0/0; opt_in-платный не встаёт перед единственной платной попыткой) + тест рядом с `test_llm_guard.py:488`, который сейчас закрепляет «не больше одной платной» только для формы free+paid.

### Деньги: подтверждённый ноль у платного маршрута

- `backend/llm_gateway.py:419` (actual_quote) — тариф 0/0 при `free=false` считается как `confirmed` + $0.00, тогда как гейт `llm_adapters.py:80` считает тот же маршрут свободным. Проверка: `actual_quote` → `(0.0, 'confirmed')`, `_gate` → проходит как free. Противоречит `interfaces.md:287` («маршрут с тарифом 0/0 … даёт `actual_status='free'»») и докрингу `llm_gateway.py:410-412`; карточка показывает «Платный» + «Реальный платёж: $0.000000» (`llmDisplay.ts:180-197`) — ровно тот подтверждённый $0.00 у платного маршрута, который запрещён. Фикс — одна строка (зеркало `llm_adapters.py:80`) + тест.

### Деньги: потерянный usage в адаптерном пути

- `backend/llm_adapters.py:249-251` + `backend/llm_guard.py:425-430` — адаптерный путь выбрасывает разобранный `usage`, когда текст непригоден: тело провайдера с `usage {1000,200}` даёт строку `actual_status='unknown'`, `actual_cost_usd=NULL`, `input_tokens=NULL`, в лимите держится оценка 0.000303, а факт 0.00027 не считается. Легаси-ветка PiAPI на том же теле: `answered=True`, usage 1000/200 → `confirmed`. Через адаптер идут все четыре новых провайдера. Нарушены spec #30/R23 и `interfaces.md:254`. Фикс ограничен (2 файла); заодно `backend/test_llm_adapters.py:276-292` — тест закрепляет выбрасывание usage, его надо переписать на новое поведение.

### Операционная безопасность: зависшая очередь агента

- `backend/native_chat.py:306-365` (транзакция) и `:358` — отклонённый/упавший отчёт оставляет задание в `preparing`: очередь агента по всей студии заблокирована, задание не отменяется, расход агента не в журнале. Прогон: обычный отчёт с пустым промптом → 409 «Недопустимый переход этапа» → задание `preparing`, чужой проект не получает задание, `cancel` → 409. То же при сбое вставки в `llm_calls` (0 строк журнала). Нарушен `interfaces.md:293`. Фикс ограничен.
