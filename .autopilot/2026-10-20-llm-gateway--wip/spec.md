# Спецификация: LLM Gateway с двойным показом стоимости

Ветка `minimax/llm-gateway`. Решение владельца от 20.10.2026: **на карточке каждого LLM-вызова первым показывается тарифная стоимость Kie.ai / PiAPI (даже для бесплатного API), а в «Бюджет / Экономика» суммируется только фактическое списание.** Правило обязательное: `docs/LLM_GATEWAY_COST_DISPLAY_POLICY_2026-10-20.md`.

## Задача

Владелец ведёт AI Workflow Studio (GremoVOD) и хочет один общий LLM Gateway для дешёвых и бесплатных текстовых моделей — без второй платформы и без ослабления действующих защит от расходов.

Сегодня студия об LLM-вызове знает одну цифру. В таблице `llm_calls` колонка `usd` означает оценку, пока вызов зарезервирован, и факт после завершения; при сбое провайдера она обнуляется — даже если провайдер уже списал деньги. Провайдер зашит как `piapi`, авто-маршрута и фоллбэка нет, кода шлюза в ветке нет вовсе.

Из-за этого владелец не может увидеть две разные вещи, которые ему нужны раздельно:

- **сколько вызов стоил бы по тарифу Kie.ai / PiAPI** — сравнительная оценка, чтобы понимать, во что обошёлся бы текст, даже если он выполнен бесплатным маршрутом;
- **сколько реально списано денег** — единственная цифра, которая имеет право стоять в «Бюджете».

Сейчас эти две величины смешаны в одну, поэтому бюджет студии нельзя объяснить владельцу одним предложением.

## Решение

Становится один серверный шлюз с двумя независимыми числами на каждый вызов.

**Тарифный ориентир** считается по тарифу Kie.ai или PiAPI и показывается первым в карточке вызова — для платного и для бесплатного маршрута одинаково. На карточке видно, чей тариф взят, какая это модель-ориентир и дата цены. Если тариф взят у другой модели, это прямо написано: «другая модель, сравнение по объёму токенов». Если тариф не подтверждён — написано «Не подтверждён», а не `$0`.

**Фактическое списание** считается по тарифу того провайдера, который выполнил запрос. Только оно попадает в «Фактически потрачено». Ориентир живёт рядом отдельной строкой «Эквивалент по Kie/PiAPI» и никогда не прибавляется к деньгам.

Бесплатный успешный вызов даёт `$0.00` в бюджете и ненулевой ориентир на карточке. Сбой, после которого списание возможно (таймаут, 429, 5xx, неразобранный ответ), не приравнивается к нулю — он попадает в отдельный итог «Неизвестные списания / нужна сверка», резерв при этом не теряется. Платный фоллбэк после бесплатного маршрута — это реальный платёж, и платится только он.

Маршруты, провайдеры, тарифы и режимы приходят из одного серверного реестра, собранного из файла конфигурации. Произвольные адреса и модели от пользователя не принимаются. По умолчанию все маршруты выключены — включает их владелец сам, после живой проверки тарифа.

## Решения по реализации

| Решение | Почему |
|---|---|
| Отдельный модуль `backend/llm_gateway.py` (реестр, ориентир, факт, маршрут) рядом с существующим `llm_guard.py` | `llm_guard` — это защита денег и подпись; реестр и тарифы — другая ответственность. Разделение не ломает существующие тесты |
| Реестр читается из `config/llm_gateway.prices.json`; при отсутствии — из `config/llm_gateway.prices.example.json` (все маршруты выключены) | схема уже задана владельцем в примере; реальный файл игнорируется Git, чтобы не закоммитить тарифы владельца |
| Ориентир и факт считаются **на сервере**; клиентский `llmPricing.ts` остаётся только превью | клиентская формула токенизации уже расходится с серверной; деньги нельзя считать в браузере |
| Адаптеры выделены в `backend/llm_adapters.py` с одним швом — внедряемый `httpx.AsyncClient` | один и тот же шов позволяет закрыть все провайдеры `httpx.MockTransport` без единого живого запроса |
| Стоимость вызова пишется в `llm_calls` новыми колонками; `usd` сохраняет прежний смысл | обратная совместимость: старый код и старые тесты продолжают считать то же самое |
| Позиционный `INSERT INTO llm_calls VALUES(...)` переводится на именованные колонки | иначе любая новая колонка ломает вставку |
| Подпись расширяется необязательным полем `extra`; токены без `extra` принимаются как прежние | старые подписи переживают изменение, новые связывают больше |
| Резерв при неопределённом списании **не обнуляется**, а помечается `actual_status='unknown'` | «неизвестное списание не равно нулю» — прямое требование политики |
| В реестре хранятся цены за 1 млн токенов, как в существующем `PRICES` | единицы не меняются, миграция цен не нужна |
| Клиентская доля дробных сумм — 6 знаков (`smallUsd` уже так умеет) | «$0.000300» не должен превращаться в `$0.00» |
| Схема файла конфигурации закрепляется как есть: `schema_version`, `as_of`, `currency`, `unit` = «USD за 1 000 000 входных или выходных токенов», `status`, `rates[]` (`provider`, `model`, `model_id`, `input`, `output`, `source`, `as_of`, `protocol`, `enabled`, `verified_at`, `capabilities`, `role`, `free`, `opt_in`, `promotion`, `quota_limited`, `requires_dynamic_tier_check`), `comparison_display` (`card_primary` = «kie_piapi_reference_cost», `budget_primary` = «confirmed_actual_provider_cost», `reference_provider_allowlist` = `["kie","piapi"]`, `match_priority` = «exact_model_then_named_other_model_baseline», `default_baseline`, `alternative_baseline`, `explicit_different_model_label_required` = true, `show_reference_snapshot_date` = true, `free_api_actual_cost_usd` = 0, `paid_approval_must_show_actual_estimate` = true, `unknown_charge_is_not_zero` = true, `pending_and_unknown_reported_separately` = true, `small_amount_precision` = 6), `sample_limits_only` (`per_call_usd` 0.1, `per_day_usd` 1, `per_month_usd` 10, `do_not_override_existing_owner_limits` = true) | пример конфигурации уже дан владельцем — это контракт, а не свободная форма |
| **Префиксы путей Kie закрепляются по семейству модели, а не по протоколу:** семейство GPT-6 (Responses) → `openai`, семейство Claude (сообщения Anthropic) → `claude` | это не догадка: рабочий конфиг агента владельца (`~/.minimax/config.yaml`) обращается к `https://api.kie.ai/openai/v1` для `gpt-6.1-sol` и к `https://api.kie.ai/claude` для `claude-haiku-5-5`. Значит итоговые адреса — `https://api.kie.ai/openai/v1/responses` и `https://api.kie.ai/claude/v1/messages`. Раньше в примере стояли `codex` и `anthropic` — это пути других семейств Kie; в примере и в реальном конфиге заменены на `openai` и `claude` |
| Поля `sample_limits_only` — пример, а не лимит: значения не применяются как ограничения, они показывают порядок величин | `do_not_override_existing_owner_limits` = true; реальные лимиты владельца живут в `spending_limits` и `production_series_limits` |
| Ключи провайдеров остаются в принятой в проекте схеме «из UI или файла в корне репозитория», без записи в SQLite | README проекта: «ключи вводятся в приложении и передаются локальному бэкенду по запросу; в SQLite не записываются» |
| Платно-закрытое поведение сохраняется: маршрут без подтверждённого тарифа не используется для сетевого вызова | уже действует в проекте («платные LLM-маршруты закрыты до сетевых вызовов при отсутствии проверенных тарифов») — шлюз это не ломает, а формализует флагом `enabled`/`verified_at` |
| UI: новая карточка `LlmCostCard.tsx` + чистые функции подписей в `llmDisplay.ts` | чистые функции тестируются `node --test` без DOM |

## Открытые места

| Что | Где заглушка | Что нужно от владельца |
|---|---|---|
| Реальный файл конфигурации с тарифами и флагами | `config/llm_gateway.prices.example.json` — все маршруты `enabled: false`, `verified_at: null` | создать `config/llm_gateway.prices.json` с проверенными тарифами, датами и флагами `enabled`/`verified_at` |
| Тариф DeepSeek Flash | в примере `input: null`, `output: null`, `requires_dynamic_tier_check: true` → маршрут показывается как «Не подтверждён» и не может быть платным | проверить официальную страницу и вписать тариф или оставить маршрут выключенным |
| Ключи `MINIMAX_API_KEY`, `DEEPSEEK_API_KEY`, `OPENROUTER_API_KEY` | `connections.PROVIDERS` их не знает; добавляются в этом же прогоне по образцу `PIAPI_API_KEY` | владелец вписывает значения в `.env` сам; в Git они не попадают |
| Подтверждение тарифов Kie и PiAPI вживую | `verified_at: null` → карточка помечает тариф как неподтверждённый, но сумму показывает с датой и источником | после живой проверки проставить `verified_at` и дату |
| Как именно выводить непроверенный тариф | в брифе есть два прочтения: «выводить как “Не подтверждён”» (буквально) и «показывать ориентир с датой и источником» (пример в документе). Сборка делает безопасное объединение: **сумма показывается с датой, источником и пометкой «тариф не подтверждён вживую»; тариф, которого нет совсем, показывается как «Тариф не подтверждён» без числа; `$0` не выводится никогда** | владельцу подтвердить приемлемость этой формулировки; после живой проверки тарифа пометка снимается автоматически по `verified_at` |
