# AGENT_BUILD_MANUAL.md — правила совместной сборки GremoVOD

Версия: 2026-10-19 / v1.0. Исполнители: Codex, Claude Code, Argon. **Этот файл — координация, а не право менять рабочий проект без контроля.**

## Читай перед стартом (в таком порядке)

`AGENTS.md` → `CLAUDE.md` (при работе в локальной студии) → `docs/HANDOFF_CLAUDE_CODE.md` → этот файл → `STATUS.md` → `docs/CODEX_DECISIONS.md` → `docs/CODEX_NEXT_ACTIONS.md` → актуальные `docs/specs/n8n-production-2026-10-19/`.

Существующие правила `AGENTS.md` / `CLAUDE.md` о Windows worktree, портах и рабочих данных остаются в силе. При противоречии **не выбирай удобное**, записывай проблему в `docs/CODEX_DECISIONS.md` и оставляй спорный/платный шаг в BLOCKED до ревью.

## 1. Единственный хозяин каждой части проекта

| Исполнитель | Основная работа | Основные пути | Ограничения |
|---|---|---|---|
| **Codex** — архитектор и ревизор | Проверка P0/P1/P2, денежных состояний, архитектуры, API-контрактов и ревью всех PR | `docs/specs/**`, `docs/CODEX_DECISIONS.md`, схемы JSON/правила `VALIDATION.json`, ревью `.github/**` | Не запускает рабочую студию на 8000/5173, не вмешивается в чужие worktree |
| **Claude Code** — локальный строитель | FastAPI/SQLite и миграции, ffprobe/FFmpeg/Whisper, навыки и системные промпты, локальные проверки | `backend/**`, `db/**`, `scripts/**`, `tools/**`, `prompts/**` | Не переписывает `docs/specs/**` / `canon/**` без отдельного назначения |
| **Argon** — интегратор среды | Подключение семи n8n-модулей, поля API-адаптеров, MOCK тесты, транспорт Windows↔n8n | `workflows/**`, `integrations/n8n/**`, dev-конфигурация только в отдельном стенде | Не меняет базу, бюджет, защищённые API и архитектуру без Codex review |
| **Владелец** — шоураннер | Утверждение героев, канона, прав на голоса, бюджетных лимитов и финального выпуска | `canon/**` + подтверждения через защищённую Studio | Ни один агент не выдаёт свои гипотезы за утверждённый канон |

Папки `frontend/**`, `tests/**`, `.github/**`, `AGENTS.md`, `CLAUDE.md` и `STATUS.md` — **shared/controlled**: на каждую правку назначить одного владельца в `STATUS.md` до начала. `STATUS.md` обновляет только координатор текущей эстафеты, а исполнители оставляют результаты в отдельных `docs/agent_handoffs/...` или PR. Так мы не получим конфликты от одновременных записей.

Это распределение **по задачам, не по «качеству модели»**: Claude, Codex или Argon не объявляются незаменимыми для русского текста или SQL; результат оценивается по исходникам и тестам.

## 2. Ветки, worktree и безопасный Git

- `main` — только проверенная работа. **Нельзя** push/merge/force-push напрямую из агента; нужно пройти PR+CI+архитектурное ревью, затем merge по действующим правилам репозитория. Наличие технической branch protection **не подтверждено**.
- Codex: `codex/<задача>`, локальный `C:/AI_Workflow_Studio/.worktrees/codex` (существующая `codex/work` остаётся неприкосновенной).
- Claude Code: `build/claude/<этап>-<задача>`, `C:/AI_Workflow_Studio/.worktrees/claude` (существующая `claude/work` остаётся). Только Claude Code по действующему `CLAUDE.md` управляет рабочими 8000/5173.
- Argon: `build/argon/<этап>-<задача>`, отдельный **ещё не созданный локально** `C:/AI_Workflow_Studio/.worktrees/argon`. Argon не занимает чужие порты или data dir.
- `coordination/<задача>` — только инструкции, статусы и handoff, без функционального кода.
- До новых веток: `git status --short`, `git branch --show-current`, `git worktree list`, `git fetch origin`. **Не делать checkout/switch/reset в чужом worktree.**
- Два исполнителя **никогда** не правят один файл параллельно. Если нужна общая правка — сначала handoff и перенос ответственности в `STATUS.md`.
- Историю веток PR #17 (`feature/n8n-astra-contract-hardening-20261019`) и PR #18 (`feature/p0-studio-foundation-20261019`) не переписывать. PR #18 зависит от PR #17; сначала Codex разберёт их базу и конфликты.
- `git add` только с точными путями. Никаких `git add .`, force-push, автоматического разрешения конфликтов заменой файла целиком, коммита `.env`, sqlite, media, access tokens.

## 3. Физическая архитектура n8n

Ровно **семь** конечных физических workflow `WF_00..WF_06`; номера `N01..N43`, `S01..S09` являются логическими IDs. Машинная карта и существующие draft workflow ID: `integrations/n8n/WF_00_WF_06_MANIFEST.json`.

- `WF_00_Core_Infra` — диспетчер, бюджет, статус, владельческие решения.
- `WF_01_Writers_Room` — идеи, сценарий, режиссура, версионированные навыки.
- `WF_02_Canon_And_Images` — библиотека и тестовые изображения.
- `WF_03_Audio_Factory` — отдельные voice/sfx/music, external TTS.
- `WF_04_Video_And_LipSync` — отдельные операции video и lip-sync.
- `WF_05_Assembly_And_Critics` — монтаж, техконтроль, A6/A7/A8, владелец.
- `WF_06_Repair_Router` — точечный ремонт по slot ID.

Поддерживать в `workflows/` **версионированные экспорты JSON без credentials**. Не считать публикацию файла JSON доказательством, что он активирован в Cloud. Все новые workflow по умолчанию `active=false`, `MOCK_MODE=true`, `final_release_approved=false`. Зелёный MOCK не равен мультимодальной приёмке.

## 4. Денежные и содержательные запреты

- Перед любым платным request: подлинная сессия владельца, бюджетный пакет, *отдельное разрешение конкретного запроса*, зафиксированный hash, provider/model, цена и срок. Результат ИИ или n8n JSON **не заменяет** авторизацию Studio.
- Ошибка после отправки запроса, когда неизвестна судьба списания: `UNKNOWN`, резерв остаётся, **не повторять submit** автоматически.
- FFmpeg/ffprobe, хэши, длительность, наличие обязательных файлов, бюджет и версионность проверяет **обычный код**, не LLM.
- `N34` — только технический анализ. Без реального доступа к видео/звуку `N36–N38` возвращают BLOCKED; A8 не включать ради формальной галочки.
- Отдельный Windows media-worker: n8n Cloud не запускает локальные shell-команды. Не открывать локальный FastAPI публично.
- Исходный проект, `canon/**`, реальная SQLite, оригинальные медиа и API credentials не изменяются и не отправляются без авторизованного рабочего механизма. Право продолжать *разработку* не означает права незаметно списывать деньги или публиковать выпуск.
- Названия `grem`, `get-more-perspectives`, `generate-fresh-ideas`, `match-my-writing-style` — **не подтверждены как установленные** в репозитории. Не выдавать имитирующий prompt за реальный навык.

## 5. Эстафета: 3 действия после каждой задачи

1. **Исполнитель:** код/тесты в *своей* ветке; PR с `Scope`, `Changed files`, `Tests`, `Risks`, `Owner/Codex decision`. Никаких общих файлов вне назначенного диапазона.
2. **Handoff:** три строки в `docs/agent_handoffs/<роль>-<задача>.md`: **«Сделано»**, **«Файлы»**, **«Следующий шаг»**. Координатор переносит актуальное состояние в `STATUS.md` одним коммитом.
3. **Codex:** проводит архитектурное ревью PR и определяет PASS/CHANGES_REQUESTED/BLOCKED, заносит наблюдения в ревью/журнал и обновляет `VALIDATION.json` в своей ветке; только затем задача может быть принята по процедуре.

## 6. Что делать прямо сейчас

Сначала прочитать `STATUS.md` и `docs/CODEX_REVIEW_PACKET.md`; проверить зависимые PR #17 → #18. Далее Codex выбирает безопасный P0 merge/migration plan, отдаёт один подзадачный контракт Claude и один Argon, и они работают в **разных ветках**. Codex не должен автоматически править или сливать чужой PR «потому что тесты зелёные».

Любую неоднозначность с риском потери данных/денег — дописать в `docs/CODEX_DECISIONS.md` и остановить только опасную подоперацию, не все бесплатные тесты.
