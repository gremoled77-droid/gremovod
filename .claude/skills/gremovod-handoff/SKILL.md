# Передача задачи

## 1. Проверить состояние ветки

```powershell
git status --short
git branch --show-current
git worktree list
```

Ветка не должна быть `main`, `master` или `mavis/work`. Чужие незакоммиченные
изменения в том же worktree — СТОП, сначала сообщить владельцу.

## 2. Закоммитить

- `git add` только точными путями. Никаких `git add .` и `git add -A`.
- В коммит не попадают: ключи, `.env`, SQLite, `runtime/`, `backend/media/`,
  `backend/library/`, `backend/character_library/`, `projects/`.
- Сообщение коммита — коротко и по делу, на русском.
- Хук `guard_git.py` не даст сделать push в защищённую ветку, force-push или
  `git clean -f`. Это осознанное ограничение, а не сбой.

## 3. Handoff

Файл `docs/agent_handoffs/<роль>-<задача>.md`, три строки в начале:

```
- **Сделано:** …
- **Файлы:** …
- **Следующий шаг:** …
```

`STATUS.md` **не** править: его обновляет только координатор текущей эстафеты.
Результат агента живёт в handoff или в PR — так не возникает конфликтов.

## 4. Отправить ветку и открыть Draft PR

```powershell
git push -u origin <имя-ветки>
gh pr create --draft --base mavis/work --title "…" --body "…"
```

Тело PR:

```
## Scope
<что делает>

## Changed files
<пути>

## Tests
<точная команда> — <результат>

## Risks
<что может сломаться, что не проверено>

## Owner / Codex decision
<что нужно решить ревьюеру>
```

Правила оформления:

- PR остаётся **Draft**. Объединение в `main` — не автоматическое.
- Цепочка PR: если PR зависит от другого, это указать в теле.
- Не менять видимость репозитория, не добавлять другие remote, не делать force-push.
