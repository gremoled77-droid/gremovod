# Поиск контекста

## Шаг 1. Сузить область

Не читать `docs/` подряд: там больше 70 файлов, среди них исторические отчёты.
Карта «задача → файл» уже собрана в `.claude/rules/knowledge-map.md` — открыть её
и взять нужную строку.

## Шаг 2. Выбрать источник

| Нужен | Источник |
|---|---|
| Правила агентов, безопасность, деньги | `AGENTS.md` |
| Правила по коду бэкенда / фронтенда | `.claude/rules/backend.md`, `.claude/rules/frontend.md` |
| Ограничения хуков | `.claude/rules/guards.md` |
| Спецификация n8n | `docs/specs/n8n-production-2026-10-19/` |
| Решения владельца | `AGENTS.md`, раздел «Решения владельца» |
| Киноязык, промпты, сценарий | `skills/` — путь указан в `knowledge-map.md` |
| Моушн и монтаж кодом | `docs/MOTION_TOOLS_2026-10-18.md` |

## Шаг 3. Проверить, что файл актуален

Документы в `docs/` датированы в имени файла. Перед опорой на документ:

- сверить дату с `STATUS.md` и датой последнего коммита по файлу:
  `git log -1 --format=%ad -- <путь>`;
- если файл старше текущего состояния проекта — взять факт из кода и сказать об
  этом в отчёте, а не молча опираться на устаревший документ.

## Шаг 4. Не плодить копии

Если ответ нужен в двух местах — сослаться на источник, а не переписать его текст.
Правило проекта: содержимое документа не дублируется в нескольких файлах.
