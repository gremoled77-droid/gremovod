# Backend и база

- Модуль подключается к FastAPI через `register(app, studio)` в `backend/main.py`.
  Новый модуль не подключается вручную в `main.py`, если он уже экспортирует
  `register`.
- Схема SQLite лежит в `db/schema.sql`. Миграция — отдельным скриптом
  (`scripts/p0_migrate.py` и т. п.), с откатом и на **копии** настоящей базы.
  `backend/studio.sqlite3` — реальные данные владельца, туда не пишем и не читаем
  из тестов.
- Тесты используют временную базу. Свою `STUDIO_DATA_DIR` стенду задавать явно,
  чтобы две копии студии не смотрели в одну SQLite.
- Реальная студия на 8000/5173 — в корне владельца. Свой стенд поднимать на
  8001/5174 и не останавливать чужой процесс. `ORIGINS` в `backend/security.py`
  пропускает только 5173/8000, для стенда нужен прокси без заголовка `Origin`.
- Проверки после правки backend: `python -m pytest backend` (pytest в venv проекта)
  либо `python -X utf8 -m unittest discover -s backend -p "test_*.py"` — обе команды
  валидны, выбирать одну и не расходиться в отчёте.

## Деньги и внешние вызовы

- Оценка цены и подтверждение — обязательный путь любого платного запуска
  (`GenerationReview`, токен подтверждения, лимиты проекта/дня). Не обходить.
- Провайдер выбирается реестром (`backend/model_catalog.py`: `MODEL_SPECS`,
  `LLM_MODELS`, `llm_spec`), а не условием по имени вендора в коде. Деньги и
  журнал расходов общие для всех провайдеров.
- Ошибка после отправки запроса, когда судьба списания неизвестна, — это `UNKNOWN`:
  резерв остаётся, повторный submit автоматически **не** повторяется.
- Ключи, `.env`, базы и медиа в `.gitignore` — не снимать и не переносить.
